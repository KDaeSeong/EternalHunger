# 공유 필드 자원 구현·검증

기준일: 2026-09-05. G1.2의 고갈 재계획과 G3.1의 자원 경쟁을 구현한 기록이다. 경기 흐름·밸런스·재미 전체의 합격을 뜻하지 않는다.

## 실제 동작

- 기본 필드 아이템은 경기 공통 `spawnState.fieldResources`에 지역/품목별 초기 수량, 잔량, 획득 수량을 저장한다. 일반 상자 탐색, 목표 루트 파밍, 시설의 물 채집이 같은 재고를 사용한다.
- 실제 지역 자료, 허용된 맵 상자 목록, 아이템 공급 지역에 있는 미조합 기본 아이템만 초기 공급에 포함한다. 조합품과 특수 재료를 일반 필드의 무한 대체 지급으로 만들지 않는다. 특수 재료/보급 상자의 별도 월드 오브젝트는 유지한다.
- 기본값은 공급 지역마다 품목별 12개이며, 이는 시뮬레이터 공급량의 첫 기준값이지 원작의 현재 상자 수량을 재현했다는 뜻이 아니다. 맵의 `fieldResourceStock[zoneId][itemId]`로 0을 포함한 명시 수량을 설정할 수 있다.
- 탐색 제안은 재고를 소비하지 않는다. 실제 인벤토리 수용과 재고 차감을 동기적으로 처리한다. 마지막 하나를 두 팀이 노려도 한 팀만 받고, 가방에 못 넣은 수량은 남는다. 같은 획득 제안의 중복 처리도 방지한다.
- 목표 파밍은 부족 수량 이상을 가져가지 않는다. 소진된 지역은 성장 계획에서 제외하고 남은 공급 지역으로 이동한다. 필수 재료를 구할 수 없는 제작 목표는 다른 장비 목표로 전환한다. 기존 후반 재료 탐색도 소진된 정적 공급 위치를 제외한다.
- 밤낮 전환, 상태 복제, JSON 저장/복원은 잔량을 보존한다. 새로운 경기 상태에서는 새 재고를 만든다. 경기 도중 자동 재입고는 없다.
- 실제 획득, 지역별 품목 소진, 고갈 후 경로 변경 이벤트와 로그를 기록하고 결과 상세에 `자원 경쟁` 행을 표시한다.

## 실제 경기 기준선

실제 게스트 경기 실행기를 사용하고 표시 대기만 생략했다. 24인, 8개 팀, 기존 장비/교전/부활/금지구역을 사용한다. `EH_MATCH_SEED`로 시작 난수를 고정한다.

| 난수 | 공유 재고 획득 | 지역별 품목 소진 | 고갈 경로 변경 | 초반 장비 완성 관측 | 실제 제작 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1101 | 564개 | 11건 | 2회 | 13/24 | 344회 |
| 2202 | 533개 | 11건 | 3회 | 12/24 | 336회 |
| 3303 | 544개 | 12건 | 5회 | 13/24 | 336회 |

- 초기 공급은 세 경기 모두 552개 지역/품목 조합, 총 6,624개다. 공급량을 편성이나 테스트 성공 여부에 맞춰 늘리지 않았다.
- 시간축 검사는 각 10/10 통과했다. 초기 수량 = 잔량 + 획득량, 모든 재고 차감과 획득 이벤트의 일치, 단계 전환 중 수량 부활 없음, 음수 잔량 없음, 사망자 재행동/중복 공격 없음, 서버 요청 0회를 확인했다.
- 세 경기 모두 여전히 6일 밤에 종료했다. 공유 재고 기능은 작동하지만, 이를 자연스러운 중후반 흐름이 완성됐다는 증거로 쓰지 않는다.
- 경기 전체 공급은 많이 남지만 특정 지역의 특정 품목은 먼저 소진된다. 총량만으로 지역별 공급과 성장 난이도를 평가하지 않는다.

## 전체 검사와 브라우저 확인

- `npm run check:eternal-hunger` 전체 회귀 검사와 프로덕션 빌드가 종료 코드 0으로 통과했다. 이후 사용자 정의 맵의 명시적 물 공급 지역도 초기 재고에 반영하도록 보강하고 자원 검사 14/14, 실제 경기 시간축 10/10(1101, 위 표와 동일 결과), `npm run check:runtime:full`의 정적 검사/프로덕션 빌드를 다시 통과했다.
- 컴퓨터 사용 스킬의 브라우저 조작으로 로컬 프로덕션 빌드에서 로그인 없는 24인/8팀 스쿼드를 x32 자동 관전했다. 개발자 장비 지급/조작은 사용하지 않았다.
- 실제 종료: 6일 밤 20:30, 백로 / 6팀 생존 1/3. 공유 재고 487개 획득, 지역별 품목 소진 10건, 고갈 경로 재계획 5회가 결과 상세에 표시됐다.
- 레시피 제작 291회, 팀 교전 22회, 팀원 공격 56회, 집중 공격 17회, 엄호 1명·회, 어시스트 17명·회가 함께 표시됐다.
- 명예의 전당/유저 전적 로컬 완료와 로컬 완주 기록 완료를 확인했다. 브라우저 경고·오류 로그는 0건이었다.
- 자원 경쟁 행을 스크린샷으로 확인했다. 텍스트가 결과 창 안에서 읽을 수 있게 표시된다. 스크린샷 파일이나 원본 경기 JSON을 저장했다는 뜻은 아니다.
- 브라우저 확인은 사용자 정의 맵의 물 공급 지역 보강 직전 빌드이며, 기본 게스트 경기에서 결과 표시를 확인한 증거다. 해당 사용자 정의 맵 조건은 별도 자동 검사로 검증했다.

## 다음 작업과 한계

- 기본 공급량 12개의 적절성, 지역별 혼잡, 이동/합류 지연, 성장 복귀, 강제 결판 의존도는 후속 밸런스 작업이다.
- 브라우저 경기에서도 같은 초기 지역으로의 집중과 후반 강제 집결을 확인했다. 재고 도입만으로 이 현상이 해소됐다고 주장하지 않는다.
- 후속 소스 확인: `suddenDeathRuntime.js`는 최종 안전 지역으로 생존자의 위치를 직접 바꾸는 집결 처리와, 실제 타격 없이 팀 점수 비교로 패배 팀의 HP를 0으로 만드는 별도 결판 처리를 갖고 있다. G3.2에서는 이 보정에 기대지 않고 이동·교전·구역 압력이 종료를 만드는 흐름을 검증해야 한다.
- 금지구역/위험 인원/지도 표시가 서로 일치하지 않는 기존 관전 화면 문제도 확인했다. G4의 단일 실제 상태 연결에서 처리해야 한다.
- 현재 상태는 중립적인 필드 재고를 AI 계획에 공유한다. 정찰/미확인 재고 추정 모델까지 구현한 것은 아니다.
- 현재 재고의 JSON 복제 검사는 경기 재현 기능(G5.1)의 완성을 뜻하지 않는다. 설정/난수 저장 및 재경기 UI는 별도 작업이다.
