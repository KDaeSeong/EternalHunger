# HF6 커스텀 아이템 지원 감사와 구현 기준

2026-09-20. 사용자 평가의 빈 장비 슬롯·커스텀 제작·소모품·파열 같은 아이템 효과 지원을 끝까지 연결하는 후속 작업이다. **미완료**이며 이번 기록은 결함 재현과 다음 구현 범위를 고정한다. HF1–HF5와 전체 목표를 대신하지 않는다.

## 현재 제품 경로

- `ItemEditorModal.jsx`는 이름·분류·슬롯·기본 능력치·조합식 비용/결과 수량을 저장한다. 소모품/발동 효과의 명시적 편집 필드는 없다.
- `server/models/Item.js`는 기본 정보와 ObjectId 재료 참조를 저장하지만 `consumeEffect`/장비 발동 효과 스키마는 없다. 임의로 보낸 효과 필드는 보존되지 않는다. 실제 계정 DB 변경이나 정리는 실행하지 않았다.
- 게스트의 `loadGuestSimulationItemCatalog()`는 내장 카탈로그를 복사한다. 계정 편집과 별도로 게스트 커스텀 카탈로그 저장/선택도 연결해야 한다. 캐릭터/지도 편집이 있다는 사실로 아이템 편집까지 있다고 판정하지 않는다.
- `applyItemEffect()`는 이름·태그 기반 기존 음식/영구 소모품/캡슐을 해석한다. 일부 명시적 회복량을 읽더라도 실제 획득 경로 `addItemToInventory()`에서 효과 필드가 빠진다.
- `tryAutoCraftFromInventory()`와 `tryAutoCraftFromLoot()`는 재료/수용량 방어가 있지만 결과 1개를 고정하고 조합식 크레딧 비용을 읽지 않는다.

## 실제 함수 재현

기준 엔진: `afb0c26fd5aeb9e032b5d90f9c6ff9fadbae9e58d0aaa7649a54b3a3845cacde`.
실행: `client`에서 `node ./scripts/audit-custom-item-support.mjs`.
실제 스키마·분류·획득·사용·제작 함수를 일회용 메모리 입력으로 호출한다. DB 연결·계정 저장·설정 변경은 없다. 종료 코드 0은 감사 실행 성공일 뿐 지원 완료가 아니다.

| 식별자 | 입력/기대 | 실제 관측 |
| --- | --- | --- |
| HF6-SCHEMA | 명시한 회복량 25 저장 | 문서 변환 후 효과 없음; 비용 7·결과 3개는 보존 |
| HF6-CATEGORY | 편집기 분류 `소모품`, 이름 `맞춤 회복약` | 런타임은 재료로 분류, 자동 회복 후보 아님 |
| HF6-RECEIPT | 회복 25를 명시한 음식 획득 | 획득 전 25 → 가방 저장 후 기본 회복 18, 효과 유실 |
| HF6-USE | 지원하지 않는 효과 사용 거부·아이템 보존 | 강제 사용 성공, 회복 0·아이템 1개 소실. 자동 사용은 안 됨 |
| HF6-CRAFT | 약초 2개+7Cr → 결과 3개 | 재료 소비·결과 1개·20Cr 그대로. 0Cr도 성공, 획득 직후 제작도 결과 1개 |

다섯 항목 모두 미지원/결함을 재현했으며 아직 수정하지 않았다. 실제 원 평가의 캐릭터·카탈로그·경기 기록은 미확보다. 단검 T1이 없는 표본 카탈로그에서 시작 무기를 생성하지 않는 경계는 확인했지만 이를 원 경기 빈 슬롯의 원인으로 단정하지 않는다. 가상 장비를 지급하여 빈 슬롯을 감추지 않는다.

## 구현 순서와 완료 기준

1. **편집→저장→카탈로그의 단일 계약:** 계정/게스트의 식별자·분류·슬롯·조합식·명시적 효과를 같은 의미로 보존한다. ObjectId와 게스트 안정 키를 구분하고 내장 원본을 유지한다. 저장 실패·미지원 필드·잘못된 참조/순환 레시피를 명확히 알린다.
2. **실제 획득/제작 정산:** 지원 효과 보존, 재료 합계·결과 수량·크레딧·수용량의 원자적 처리. 실패/중복 실행/저장 복원 재시도에서 재료·크레딧·기존 장비를 보존한다. 실제 레시피만으로 제작한다.
3. **소모품 자동 판단과 적용:** 이름의 우연이 아닌 명시적 회복/보호/강화 계약으로 판단한다. 이유·실제 적용량·지속·소비 수량을 기록한다. 무효/미지원/사망/상태 제한이면 가짜 성공·아이템 소실이 없어야 한다. 기존 음식 효과를 묵시적으로 바꾸지 않는다.
4. **장비 효과의 실제 전투 연결:** 파열 등은 설명문만 저장하지 않는다. 발동 조건·수치·시간·중첩·면역·쿨다운·장착/해제·사망/부활 계약을 먼저 확정한다. 원작 의미/수치를 지어내지 않으며 커스텀 규칙과 원작 재현을 구별한다. 미지원 효과는 명확히 안내한다.
5. **빈 슬롯과 후반 성장:** 미설정, 카탈로그/슬롯/무기 불일치, 공급처 없음, 제작 대기, 장착 실패를 구분한다. 후반 선택→자원 경쟁→획득→제작/장착도 실제 상태로 추적한다. 원 평가의 빈 슬롯은 실제 입력 확보 시 재현한다.
6. **제품 왕복:** 실제 편집 저장→새로고침→편성/획득→재료·비용 소비→장착/효과→보관→동일 재경기. 배속/관전 변경 뒤 사건·프레임·최종 상태·난수·종료 일치, 원본 보존, 보상 중복 없음이 기준이다. 함수 검사·모의 저장만으로 완료 처리하지 않는다.

## 검증 경계

원 경기의 빈 슬롯/마커스 고립 동일 재현과 사람의 재평가는 미완료다. 전체 자동 검사가 통과해도 위 미지원 기능이 구현된 것은 아니다. HF2의 공개/재경기 증거는 `movement-objectives-verification.md`에서 별도 관리한다. HF6 구현 뒤에는 변경 엔진으로 관련 회귀·성능·제품 화면을 다시 확인한다.
