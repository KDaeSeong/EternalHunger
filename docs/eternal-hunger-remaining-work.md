## G5.1 물리 저장 한계 증거

- Edge 153의 새 격리 프로필에서 제품 UI로 빈 보관함 schema를 먼저 생성하고 첫 x32 경기를 정상 저장했다. 초기 사용량 1,115B, 첫 저장 뒤 933,741B였다.
- 첫 기록 물리 증가분 932,626B의 75%를 여유로 더해 quota를 1,633,210B로 고정했다. 보관된 조건에서 `캐릭터 스킬`을 켬→끔으로 바꾼 두 번째 x32 경기는 `QuotaExceededError` 안내와 `보관 다시 시도`를 실제로 표시했다.
- 실패 직후 기존 첫 기록의 ID·바이트·SHA-256은 변하지 않았다. 별도 같은-origin 게임 탭에서 `기록 삭제`→`삭제 확인`을 수행하자 IndexedDB 사용량은 6,154B로 내려갔다.
- quota override가 여전히 활성이고 한도도 1,633,210B인 상태에서 원래 탭의 실패 기록을 다시 저장했다. 최종 기록은 정확히 1건이며 실패 ID와 같았다. 실패/재저장 payload는 모두 4,423,928B, SHA-256 `76d7fbd369b41b321a1c851b2ec371c78c9ff716ab27d740a3f6041a6d0f10d4`였다. 재저장 뒤 사용량은 937,288B였고 종료 뒤 override 해제까지 확인했다.
- 이 판정은 Edge 153·단일 격리 프로필·두 same-origin 탭의 제품 흐름에 한정한다. Chrome 152에서는 브라우저 확인 중 GPU fatal이 발생해 quota 결과를 얻지 못했다. 다른 브라우저의 quota 정책, 브라우저 강제 종료, 여러 사용 탭의 동시 경쟁까지 일반화하지 않는다.

- 직후 팀 관전·x8·동일 입력을 DOM polling 없이 세 번 연속 실행했다. 시작 heap은 30.17→31.06→30.99MB로 세 번째에 낮아져 단조 상승하지 않았고, Long Task 최대는 162/165/199ms였다. 확인 조건에서는 지속 증가가 재현되지 않았지만 강제 GC 뒤 안정화나 보편적인 누수 부재를 증명하지 않는다.

현재 영향 범위 회귀는 난수 complete matches 12/12(3경기·seed 1101·frames 6,505·events 7,076·ticks 1,273.75·draws 9,584·API 0, event digest `2a67a4...`, frame digest `2f89f6...`)과 action timeline 10/10(seed 1101·1,280.75초 종료·frames 6,609·farming pickups 549·crafts 350·battles 101·API 0)을 포함한다. 이는 결정론·시간축 회귀와 production build의 증거이지 브라우저 FPS/heap 또는 사용자 재미의 증거가 아니다.

## G5.3 인간 평가 — 5분 실행 체크리스트

자동 검사·빌드·분포 수치는 이 평가를 대신하지 않는다. 평가자는 헝거게임 시뮬레이터 경험자 1명 이상이며, 한 세션을 5분으로 제한한다. UI는 1–5점 10개, 예/아니오 1개, 자유 메모 1개인 총 12필드다. 결과 화면까지 5분 안에 도달하지 못하면 추측하지 말고 `미관측`으로 기록한다.

준비 경로는 2026-09-12 로그인 없는 프로덕션 브라우저에서 실제 확인했다. 24명·시드 `1789192220412`의 x32 경기가 21:42.58에 교전으로 종료하여 보관됐고, 행 상태 `미시작`→`진행 중`, 대상 경기 메타, `입력된 관찰 0/12`, 미관측 안내, 패널 자동 스크롤·닫기·재열기를 확인했다. 평가 값은 입력하지 않았고 상태만 초안으로 남겼다. 이는 제품 경로 준비 증거이지 아래 인간 판정을 대신하지 않는다.

### 시작 전 준비 — 0:00–0:30

- 로그인하지 않은 상태에서 이미 완료된 기준 경기가 `경기 보관함`에 있는지 확인하고, 해당 행의 `5분 평가 기록`을 누른다. 개발자 패널과 테스트용 설정은 사용하지 않는다.
- 표시된 기준 경기의 시드·편성·전술을 적고, 평가자에게 목표나 내부 구현 설명을 미리 주지 않는다.
- 화면이 멈추거나 진행 버튼이 잠기면 원인과 시각을 적고, 우회하여 합격 처리하지 않는다.

### 경기 이해 — 0:30–2:30

- 보관한 기준 경기의 동일 재경기를 가능한 범위에서 x32 배속으로 진행한다. 지도, 경기 현황/팀 관전, 로그 중 최소 두 영역을 실제로 본다.
- 평가자에게 다음 세 질문을 말로 답하게 한다: `지금 선택한 팀은 무엇을 하려는가?`, `왜 이동·합류·후퇴했는가?`, `사망 또는 위험의 직접 원인은 무엇인가?`
- 답변이 기록된 문구가 아니라 추측에 의존하면 `이해 실패`로 표시하고, 어느 화면·문장이 부족했는지 적는다.
- 10시드 기준선의 영웅 장비 준비율 54.2%는 체감 관찰의 참고값일 뿐, 장비 미완성을 자동 실패/성공으로 판정하지 않는다.

### 결과와 재실행 의향 — 2:30–5:00

- 결과 화면 또는 이미 완주한 기준 기록을 열어 우승·생존·탈락 원인·주요 차이를 평가자 자신의 말로 요약하게 한다. 관측하지 못한 항목은 `미관측`으로 둔다.
- 보관 경기에서 `조건 복사·변경`을 열고 한 항목만 바꾼다. 기본 시드는 유지하며, 평가자가 새 시드를 명시적으로 선택한 경우에만 그 사실을 기록한다.
- 변경 경기의 시작 조건이 화면에 보이는지, 원본과 새 경기가 별도 기록으로 남는지 확인한다. 실제 시작·완주가 5분을 넘으면 조작 경로와 중단 지점을 적고 결과 차이를 상상하지 않는다.
- 마지막 30초에 1–5점으로 `이해 가능성`, `판단 이유의 설득력`, `파밍`, `합류`, `교전`, `후퇴`, `탈락 원인` 이해, `재미`, `다시 해보고 싶은 마음`, `화면 읽기 쉬움`을 각각 평가하게 한다. `10분 안에 한 번 더 경기하겠는가 (예/아니오)`와 가장 큰 걸림돌도 적는다. 말로 답한 세 질문·한 문장 결론·문제 재현과 심각도는 별도 UI 필드가 없으므로 자유 메모에 함께 남긴다.
