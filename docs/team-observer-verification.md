# 팀 추적과 판단 설명 검증

기준일: 2026-09-05. G4.2 팀 관전 작업. 자동 검사와 실제 사용자 이해/재플레이 평가는 구분한다.

## 구현 범위

- 생존자와 사망자에 남아 있는 팀을 선택해 추적한다. 부활한 참가자는 현재 생존 상태를 우선하며, 동명이인이라도 참가자 ID로 사건을 연결한다.
- 현재 위치, HP, 실제 가방 기준 목표 장비 확보 수, 장착 장비, 미확보 목표, 처치/어시스트를 보여준다. 화면을 그리기 위해 이동·성장 계획을 재실행하지 않는다.
- 가장 최근의 실제 판단에는 게임 시각을 붙인다. 행동을 선택한 기록을 제작·이동 성공으로 표현하지 않으며, 마지막 부활보다 앞선 판단은 현재 생의 판단으로 사용하지 않는다.
- 이동 사유, 당시 현장 인원, 제작, 재료 고갈 후 재계획, 실제 교전 참여자, 집중 공격, 행동 시간을 소비한 엄호, 추격, 사망/처치자, 부활을 기존 사건에서 설명한다. 모르는 사유는 추측해 채우지 않는다.
- 최근 사건 10개, 경기 종료 후 마지막 주요 사건 8개를 보여준다. 이는 원인 분석 전체나 전체 경기 리플레이가 아니다. 기존 사건 보관 한도 5,000개가 유지되므로 화면에도 `현재 보존된 경기 기록 기준`을 명시한다.
- 지도에서 관전 대상 생존자와 시신을 금색으로 표시한다. 지역별 표시 개수 제한 안에서는 관전 대상을 우선하고, 실제 경기 명단이나 순서는 바꾸지 않는다.
- 팀 관전·경기 현황·전체 로그를 별도 탭으로 제공한다. 관전 팀, 펼친 상세, 로그 보기 상태는 탭을 바꾸어도 유지한다. 상단의 기존 지도·캐릭터·로그 관전창도 유지한다.
- 장비 설명 함수가 읽기 과정에서 참가자의 장비 객체를 생성하던 부작용을 제거했다. 경기 규칙을 바꾸기 위한 수정이 아니다.

## 통제 및 실제 실행기 검사

`client`에서 `cmd /c npm run check:team-observer`: 13/13 통과.

1. 사망 팀 선택, 정확한 ID 연결, 부활 중복 방지
2. 상대 공격·피해자·지원자까지 연결되는 팀 사건
3. 미래/무시각 사건 제외 및 같은 초 안의 기록 순서
4. 판단 시각과 성공 여부의 구분
5. 같은 판단의 반복 축약과 변경된 목적지 보존
6. 기록된 현장 인원·후퇴 사유·성장 차단 사유 설명
7. 오래된 성장 계획 대신 현재 가방으로 진행도 계산
8. 입력 동결 및 난수 호출을 금지한 상태에서 관전/장비 설명
9. 혼잡한 지도에서 관전 대상 우선 표시 및 원본 명단 보존
10. 사망 원인·실제 처치/어시스트·종료 전 우승 추정 금지
11. 부활 비용, 집중 공격, 실제 엄호 설명
12. 부활 전 판단 제외 및 같은 초의 부활 후 새 판단 허용
13. 합류/공동 목표와 실제 이동/대기 구분, 도착을 추정하지 않음

`check-action-timeline.mjs`는 실제 실행기의 프레임 중 게임 시각이 40초 간격인 상태에서 관전 팀을 바꾸어 모델을 읽는다. 매 표본에서 난수 상태 불변, 24명 명단 보존, 팀 생존 인원/HP 일치, 미래 사건 제외를 검사한다. 경기 자체의 매 프레임 검사는 기존 G4.1 검사를 유지한다.

이번 최종 소스의 기본 스쿼드 1101은 1,278개 프레임, 34개 관전 표본, 15회 부활을 거쳐 20:52에 2팀 승리로 종료했다. API 요청은 0이었다. 전체 사건 해시는 기존 G4.1 기록과 동일하다.

`bac03f684c718171e0ca05c1de584dc22d9d32c8fe90b87a62cbc72c54cf7063`

이는 해당 고정 입력에서 관전 읽기가 경기 결과를 바꾸지 않았다는 증거다. 브라우저 저장/재현, 모든 편성의 균형, 재미를 증명하지 않는다.

## 브라우저에서 발견한 문제

중간 빌드의 비로그인 기본 24인/8팀 경기를 x4→x32로 실행했다.

- 8팀 선택 후 청람·은하·솔빛의 목표 장비 진행, 미확보 목표 및 시각이 있는 판단이 표시됐다.
- 02:20에 솔빛의 후퇴가 `당시 현장 아군 1명 / 적군 2명` 기록과 연결됐다.
- 12분대에는 8팀 생존 1/3, 청람·은하 사망 원인과 처치자, 솔빛 HP 및 성장 완료가 함께 표시됐다.
- 20:24에 5팀이 실제 교전으로 우승했고, 8팀의 전원 사망 및 마지막 주요 사건을 계속 볼 수 있었다.
- 1280×720 화면에서 지도와 관전/로그가 과도하게 압축되어 잘렸다. 읽을 수 있는 최소 경기 영역을 확보하고 게임 화면을 스크롤하도록 수정했다. 관전과 전체 로그가 높이를 나누어 경쟁하던 배치는 탭으로 분리했다.
- 성장 판단이 `low_hp`, `forbidden`, `power_gap`을 접두사 없이 기록할 때 설명되지 않던 문제를 수정했다. 성장 차단 사유가 실제 후퇴 사유를 덮지 않게 하고 통제 검사에 포함했다.

## 배치 수정 후 브라우저 검증

같은 1280×720 로컬 브라우저에서 새 빌드로 다시 진입했다. 새 경기는 무작위 편성이며 중간 빌드와 같은 입력의 재현 시험이 아니다.

- 지도는 읽을 수 있는 크기를 유지하며, 게임 화면 스크롤로 아래 관전 내용과 진행 제어에 접근했다. 팀 관전·경기 현황·전체 로그 탭 각각의 실제 렌더링을 확인했다.
- 8팀(별하·여울·은하)을 고르고 첫 장비 설명을 펼친 뒤 다른 탭을 거쳐 돌아왔다. 선택한 8팀과 펼친 장비 설명이 유지됐다.
- x8로 첫 페이즈를 진행하던 01분대에 6팀(가람·백로·라온)으로 변경했다. 진행 버튼은 잠겨 있었지만 관전 선택은 가능했고, 해당 팀의 지도 금색 표시와 위치/HP가 변경됐다.
- 02:00의 가람은 골목길→주유소 후퇴와 당시 아군 1명/적군 2명이 연결됐고, 백로의 토르의 망치 제작은 실제 완료 사건으로 표시됐다.
- x32 자동 진행 중 상단 로그창을 열었다. 앞서 선택한 전투 상세 모드가 유지됐고, 실제 팀 교전·피해·처치 로그가 표시됐다. 닫은 뒤 6팀 관전으로 돌아왔다.
- 11:50에 6팀 세 명이 개울에 모였고, 백로/라온의 합류 대기와 실제 제작 완료가 함께 기록됐다. 이 과정에서 판단의 합류 목표를 이동 성공처럼 읽지 않도록 표현을 추가로 수정했다.
- 21:08에 가람이 이슬을 추격하여 처치하고 6팀이 최후 생존 팀이 됐다. 결과·관전 시각, 생존 2/사망 22가 일치했다. 관전 요약은 14처치/10어시스트였고 구성원별 합계와 일치했다.
- 백로의 시신도 금색 관전 표식과 `사망 / 병원` 설명을 유지했다. 경기 종료 후 8팀으로 바꾸면 전원 사망, 8처치/6어시스트, 세 명의 처치자와 마지막 사건이 표시됐다. 사망 팀을 선택 목록에서 지우지 않았다.
- 브라우저 경고/오류 기록은 비어 있었다.

이 완주 후 마지막 수정은 합류 문구를 목표/이동/대기로 구분하는 읽기 전용 설명과, 독립 로그창의 기존 폭을 보존하는 CSS 선택자다.

## 최종 통합 검사와 재진입

- 마지막 수정까지 포함한 `cmd /c npm run check:eternal-hunger`: 종료 코드 0. 관전 13/13, 상태 10/10, 실제 시간축 10/10, 종료 13/13, 기존 기능 회귀 및 런타임 검사와 프로덕션 빌드가 통과했다.
- 최종 빌드에서 `다시 하기`로 재진입해 24명/8팀, 장비 목표 0/5의 초기 상태를 확인했다. 이 별도 경기도 x32로 21:11에 실제 교전으로 종료했다.
- 최종 경기의 우승은 6팀 전원 생존 3/3, 총 9처치/5어시스트였다. 가람 3/2, 백로 3/1, 라온 3/2가 관전 요약과 일치했다. 마지막 21:11에 백로가 별하를 처치하고 가람/라온이 지원한 기록이 표시됐다.
- 탈락한 1팀의 세 명과 사망 원인, 처치자 및 마지막 사건이 남았다. 종료 전 관전하던 팀이 탈락했다고 자동으로 우승 팀으로 바뀌지 않았다.
- 최종 독립 로그창의 기존 폭, 닫기 버튼, 실제 최종 교전 로그를 스크린샷으로 확인했다. 브라우저 경고/오류는 없었다.
- 마지막 합류 문구의 목표/이동/대기 구분은 통제 검사로 검증했다. 최종 브라우저 완주에서 그 문구가 나오는 중간 시점을 별도로 캡처한 것은 아니다.
- 검증용으로 실행한 로컬 서버들은 실행 명령과 PID를 확인하여 종료했다. 배포나 계정 변경은 하지 않았다.

## 남은 범위

- 실제 사용자가 이유를 이해하고 다시 편성하고 싶어지는지는 G5.3 사용자 평가가 필요하다.
- 모든 화면 크기, 사용자 지도/규칙, 여러 편성의 관전 성능은 이번 기본 조건과 별개다.
- 전체 경기 입력/규칙/난수 보존, 기록에서 재현/재편성, 전략 비교는 G5 작업이다.
- 초기 파밍 혼잡, 합류/후퇴 실효성, 전체 아이템 지급 경로 감사와 여러 조건의 균형 검증도 남아 있다. 전체 목표는 미완료다.
