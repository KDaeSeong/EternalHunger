## 협력적 준비·저장 경계 후속

경로 탐색은 같은 generator를 동기 엔진과 비동기 준비에서 함께 소비한다. 후보 생성 뒤·장비 슬롯 탐색 뒤·캐릭터 완료마다 체크포인트가 있고, 준비 실행기는 약 8ms의 계산 묶음마다 화면 처리 기회를 요청한다. 시간은 양보 시점만 결정하고 경로 선택·난수·탐색 폭에는 영향을 주지 않는다. 최종 준비 엔진은 `48b796752593c20b953c1703d1ca63ed7b434ff55eace966a59923e0c04b7f10`이다.

- 지도 준비 시작과 동시에 ref 잠금을 잡고 화면에 `지도 준비 중`을 표시한다. 참가자/규칙/지도 설정과 경기 시작을 잠그며, 경기 시작·편성/설정 변경의 실행 경로도 별도로 잠금을 확인한다.
- 선택·저장·삭제·새로고침은 기존 저장/검증 함수를 임시 메모리 저장소에 적용한다. 참가자와 후보 목록 모두 계산이 끝날 때까지 실제 저장과 화면/지도 ref는 바뀌지 않는다.
- 저장 직전 원본 저장 문자열을 다시 비교한다. 준비 도중 다른 탭에서 변경한 값이 있으면 덮어쓰지 않고 재선택을 안내한다. 비교와 쓰기 사이에 await는 없지만 브라우저 간 분산 잠금/모든 동시 쓰기의 원자성을 증명하지는 않는다.
- 실제 저장 성공 뒤 같은 동기 구간에서 두 목록·지도·선택 ref/state를 반영한다. 경로 계산을 React 상태 갱신 함수 안에서 실행하지 않는다. 실패·입력 변경·페이지 이탈 시 미완료 결과를 폐기한다.
- 경기 시작 시 로컬 저장 지도를 몰래 다시 읽지 않는다. 화면에서 준비한 조건을 캡처하며, 다른 탭의 지도/규칙을 가져오려면 시작 전에 명시적 새로고침을 사용한다.
- 기존 저장 형식, 사냥 R 금지, 금지구역 시간, 기록의 엔진 호환성 경계는 유지한다.
