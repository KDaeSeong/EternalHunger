# 지도 설정과 경로 추천·실제 이동 일치

2026-09-24. HF1의 지도 연결 감사에서 발견한 구현 불일치를 다룬다. 원작 루미아 섬의 모든 실제 길을 확정하거나 원 마커스 경기의 원인을 복원한 작업은 아니다.

## 실패 재현과 수정

루미아와 같은 지역 ID를 쓰되 단방향 연결만 지정하고 하이퍼루프를 끈 사용자 지도를 만들었다. 수정 전 새 검사 17개 중 **3개 통과/14개 실패**였다.

- 이동 그래프는 명시한 단방향 도로를 따르지만, 초기 장비 루트 추천은 기본 루미아 연결을 다시 합쳐 없는 직통 도로와 역방향 이동을 무벌점으로 취급했다. 존재하지 않는 구역을 가리키는 연결/장치도 추천의 단축 경로로 인정했다.
- `getHyperloopZoneIds`가 기본 장치 목록을 무조건 합쳤다. 별도로 지역 정보를 덧붙이는 `applyRegionDataToZones`도 명시한 `false`를 `true`로 바꾸므로, 한쪽만 수정하면 표시/페이즈/저장 입력 준비에서 다시 살아나는 결함이었다.
- 기본 연결이 없는 레거시 사용자 지도의 순환 fallback과, 장치 플래그가 없는 레거시 루미아의 이동 가능성도 실제 이동과 루트 벌점이 달랐다.

수정 후 루트 추천은 `buildBaseZoneGraph`와 `getHyperloopZoneIds`를 함께 사용한다. 지도 해석을 따로 복제하지 않는다. 장치 판정은 명시한 `hasHyperloop` boolean → 옛 `hyperloop` boolean → 필드가 없는 레거시 기본값 순서다. 명시한 `false`는 유지한다. 별도 지도 수준의 `hyperloopDeviceZoneId`는 기존 의미대로 지정한 실제 구역에 장치를 추가하며, 없는 구역에는 추가하지 않는다. 기본 장치 순서도 보존했다.

전투·난수·시간·보상·금지구역 규칙과 보스 포함 사냥 궁극기 금지는 변경하지 않았다. 레거시 지도/저장 기록의 엔진 호환성 검사를 완화하지 않는다. 내장 지도의 현재 21개 지역 및 유효 장치 12개와 모든 구역 쌍의 통행/하이퍼루프 판정은 그대로다.
