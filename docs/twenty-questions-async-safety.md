# 스무고개 방 응답과 쿠키 갱신 경계

## 서버의 동시 저장

질문·정답 도전·답변·힌트·종료는 읽은 방의 버전과 현재 활성 상태를 저장 시점에 함께 검사한다. 같은 상태를 읽은 두 요청은 하나만 반영되며, 뒤늦은 요청에는 기존 입력을 보존한 채 최신 방을 다시 확인하도록 409 응답을 보낸다. 완료된 답변을 덮거나 수동 종료와 정답 처리의 최종 상태를 역전시키지 않는다. 알림은 실제 저장에 성공한 요청만 만든다.

게임 변경은 바뀐 게임 필드만 저장하고, 접속 목록은 데이터베이스의 현재 값에서 병합한다. 기존 접속 갱신도 실제 집계 변수와 저장 라이브러리의 파이프라인 옵션에 맞춰 처리한다. 옛 버전 필드 누락은 최초 한 건의 저장만 허용하며, 과거 기록을 읽을 때 새 기여나 답변을 만들지 않는다.

현재 모델에서 허용하는 옛 `null` 답변과 누락된 답변 필드는 화면과 같이 대기로 처리한다. 공유 횟수를 다 썼어도 이런 대기 질문이 있으면 마지막 답변까지 기다린다. 이미 답한 질문·빈 문자열·불리언·숫자를 새 대기로 취급하지 않는다. 소스 회귀 20건, 실제 격리 MongoDB·Mongoose·HTTP·독립 JWT 계정의 18그룹과 변경 네 파일 집중 린트를 통과했다. 실행 중인 프로세스·경로·복제 집합도 대조했으며, 시험 데이터베이스 제거·연결 해제·HTTP 종료를 확인했다. 실제 운영 계정이나 운영 데이터는 이 검사에 사용하지 않았다.

`server`에서 `npm run test:twenty-questions`로 실제 라우트·Mongoose 모델과 제어된 입출력 경합을 검사한다. `npm run test:integration:twenty-questions`는 현재 실행 중인 격리 로컬 MongoDB의 소유 기록을 `TQ_TEST_MONGO_MANIFEST`로 명시해야 한다. 옛 검증 결과를 입력으로 사용하지 않고 새 시험 방·계정·데이터베이스만 만든다. 루프백·프로세스·경로·복제 집합을 확인한 뒤 실제 HTTP·JWT·저장·조회·경합을 실행하고, 자신이 만든 무작위 시험 데이터베이스만 제거한다. 실제 브라우저 두 로그인이나 자연 로그인 만료 인수의 대체 증거는 아니다.

## 수정된 동작

방 A를 읽는 도중 방 B로 이동하거나 계정을 바꾸면, A의 늦은 성공·오류·완료 처리가 B의 방 정보, 비밀 정답, 작성 중인 문구, 처리 중 표시와 알림을 바꾸지 않는다. 방과 계정이 바뀌는 첫 렌더부터 이전 방을 숨기며, 같은 계정의 프로필 갱신은 작성 중인 문구를 보존한다.

백그라운드 조회와 접속 알림은 한 번에 하나만 진행한다. 명시적 새로고침은 이전 조회를 대체할 수 있다. 질문·답변·정답 도전·힌트·종료 요청이 시작되면 그보다 오래된 조회를 무효화하고, 같은 프레임의 중복 변경도 차단한다. 조용한 쿠키 갱신을 발견하면 기존 방 세션을 한 번 폐기한 뒤 새 조회로 복귀한다.

공통 API는 요청 시작 시의 계정·세션 리비전뿐 아니라 CSRF 쿠키도 비교한다. 갱신 전 요청의 늦은 401 응답은 갱신된 현재 로그인을 지우거나 서버 로그아웃을 요청하지 않는다. 갱신되지 않은 현재 세션의 인증 실패는 기존처럼 처리한다.

## 자동 검증

- `npm run check:auth-session`: 기존 계정 격리 15그룹, 기록·프로필 갱신 경합 10그룹, 프록시 계약과 새 쿠키 갱신 경합 8그룹을 통과했다.
- `npm run check:twenty-questions`: 기존 규칙·31개 피드백 사례와 새 방 비동기 경합 14그룹을 통과했다.
- 쿠키 검사는 실제 API 모듈과 Axios를 실행하고, 응답 지연과 로그아웃 통신만 메모리 안에서 제어한다. 새 네트워크 요청이나 실제 계정 쓰기는 없다.
- 방 검사는 현재 소스의 실제 선언·효과·조회·변경 콜백을 제어된 훅과 API 일정으로 실행한다. 실제 React 마운트나 독립 인증 두 환경의 인수 검사를 대신하지 않는다.
- 변경된 제품·검사기 4개의 린트와 배포용 빌드를 통과했다. 빌드 전후 소스 1,221개가 같으며, 제품 워커의 첫 단계 실행 검사도 통과했다. 워커 검사는 브라우저가 아닌 Node VM에서 실행한다.

## 엔진 지문과 남은 검증

공통 API가 시뮬레이션 지문 입력에 포함되므로 생성 엔진 버전은 `39a0d282…`에서 `592a3e57…`로 바뀐다. 전투·파밍 런타임 자체의 변경은 없다. 앞선 16개 고유 입력·17회 실행 결과는 변경 전 버전의 기준 자료로 보존하며 새 버전의 재실행으로 표시하지 않는다. 새 제품 빌드의 워커 검사는 별도로 수행한다.

실제 출제자·참가자의 독립 로그인 환경, 자연 로그인 만료 후 복귀, 사람의 화면 이해도, 전경 관전 성능은 여전히 별도 인수 항목이다. 일반 탭 두 개는 로그인 상태를 공유하므로 두 계정 검증으로 계산하지 않는다.
