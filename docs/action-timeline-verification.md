# Eternal Hunger — 반복 성장 행동과 경기 시계

검증일: 2026-09-04

후속 변경(2026-09-05): 교전 개인 공격 간격 및 소수점 경과 시간을 추가했다. 아래는 원래 단계의 기록이다. 현재 시간 정밀도·상태 경계·표시 대기 검사와 실제 경기 증거는 `combat-timing-verification.md`를 참조한다.

## 이번 단계의 목표

팀과 참가자가 낮/밤 시작에 한 번만 파밍한 뒤 남은 시간에는 교전만 반복하던 구조를 수정한다. 사이트 기능 추가나 새 게임 제작은 범위에 포함하지 않는다.

## 구현

- 기본 20초마다 살아 있고 행동 가능한 참가자가 이동, 루트 탐색, 사냥, 제작, 구매를 다시 판단한다. `ruleset.ai.growthActionIntervalSec`로 간격을 조정할 수 있다.
- 첫날 낮 140초에는 0, 20, 40, 60, 80, 100, 120초의 7번 기회가 있다. 종료 경계 140초에서 이전 낮의 행동을 추가 지급하지 않는다.
- 모든 팀원의 성장 판단은 같은 경기 시점을 사용한다. 24명의 이동 시간을 순서대로 합산해 경기 시간을 소모하지 않는다. 이동 시간은 해당 참가자의 다음 행동을 지연시킨다.
- 스킬 행동 잠금도 관련 참가자만 지연시킨다. 다른 팀의 성장 시점을 건너뛰거나 이미 기록된 교전 뒤에 과거 시각의 행동을 끼워 넣지 않는다.
- 상태 이상, 지속 회복/피해, 폭발 타이머와 쿨다운은 경과한 초만큼 처리한다. 금지구역이 없어도 쿨다운은 흐른다.
- 세계 스폰, 부활, 자연 크레딧 정산, 장비 저장은 기존 낮/밤 단위 경계에 유지한다. 가젯 에너지도 낮/밤당 한 번만 지급한다. 구형 비폭발 규칙의 금지구역 HP 피해는 기존 낮/밤당 한 번 동작을 유지한다.
- 인벤토리 제작의 중복 방지를 낮/밤 키와 별개인 행동 키로 구분한다. 같은 행동의 중복 제작은 막고, 다음 행동에서는 같은 낮/밤에도 새 재료로 제작할 수 있다. 레시피 재료 소비와 장비 적합성 검사는 유지한다.
- 반복 성장 및 상태 갱신은 HP뿐 아니라 해당 낮/밤의 확정 사망 명단도 확인한다. 전투에서 남은 이전 객체가 사망자를 다시 행동시키지 못한다.
- 결과 화면에 `성장 행동` 통계를 추가한다. 제작 선택 횟수와 실제 레시피 제작 성공 횟수를 구분한다.

## 자동 검증

`client`에서 실행:

```text
npm run check:action-timeline
npm run check:team-tactics
npm run check:eternal-hunger
```

`check:action-timeline`은 전체 검사 묶음에도 포함했다. 실제 모듈을 불러오는 10개 검사를 수행한다. 테스트에서는 화면 대기만 생략하며, 실제 내장 카탈로그 774개 / 레시피 639개, 24인 편성, 지도, 파밍·제작·교전·스폰·부활·종료 모듈을 사용한다. React 상태와 이벤트 연결은 테스트 어댑터로 제공하므로 브라우저 검증과 구분한다.

최종 소스의 고정 난수 조건(1101) 한 판:

| 항목 | 결과 |
| --- | ---: |
| 낮/밤 처리 | 12회 |
| 종료 | 6일차 밤 |
| 시계 진행 | 1,230틱 |
| 성장 행동 기회 | 866회 |
| 실제 레시피 제작 | 53회 |
| 교전 이벤트 | 96회 |
| 스폰 처리 / 장비 저장 | 각각 12회 |
| 네트워크 호출 | 0회 |

교전 시작 이후에도 실제 제작이 존재함, 첫날 낮 7개 성장 시점, 사망 이후 동일 낮/밤의 재행동 금지, 행동·제작·교전·사망 기록의 시간 역전 방지를 확인했다. 53회 제작과 96회 교전은 이 조건 한 판의 결과이지 평균이나 목표 밸런스가 아니다.

검사 상태:

- 전체 `check:eternal-hunger`: 중간 구현에서 통과(팀 판단 20개, 시간 구조 9개, 기존 검사 및 빌드 포함).
- 스킬 잠금의 참가자별 시간 처리 보완 후 `check:action-timeline`: 10/10 통과, 위 표와 같은 결과.
- 최종 `check:team-tactics`: 20/20 통과.
- 최종 `check:runtime:full`: 런타임 정적 검사 및 프로덕션 빌드 통과.

## 실제 브라우저 관찰

스킬 잠금 보완 이전의 중간 빌드에서도 게스트 24인/8팀 경기가 6일차 낮에 종료됐다. 구름 / 6팀 / 생존 1/3, 실제 레시피 제작 53회, 성장 행동 826회, 로컬 완주 기록 완료가 표시됐다. 브라우저 경고·오류는 없었다. 이 판은 최종 소스 검증으로 대신하지 않는다.

최종 빌드를 별도로 시작한 뒤 새 브라우저 탭에서 같은 게스트 초기 편성, 32배속으로 다시 완주했다. 최종 화면 역시 **6일차 낮 19:40 / 구름 / 6팀 생존 1/3 / 레시피 제작 53회 / 성장 행동 826회**를 표시했다. 로컬 완주 기록 완료, 브라우저 경고·오류 0건을 확인했다. 동일 조건 반복 확인이며 독립적인 여러 난수 판의 밸런스 표본으로 세지 않는다.

결과 창에서 `성장 행동` 항목까지 스크롤하여, 긴 설명이 창 내부에서 줄바꿈되고 팀 판단 행과 겹치지 않는 모습을 실제 화면으로 확인했다. 관찰 텍스트는 `artifacts/action-timeline-verification/final-ui-observation.txt`, 자동 검사 결과는 같은 폴더의 `headless-result.json`에 기록했다. 스크린샷은 도구 화면으로 확인했으며 이미지 파일이나 원시 경기 JSON을 저장했다고 주장하지 않는다.

게스트 판의 전투 기여는 전술 스킬 80회, 무기/캐릭터 스킬 0회였다. 새 스킬 시간 잠금 함수와 실제 전투 연결은 단위 검사·코드·빌드로 확인했지만, 이 브라우저 판이 사용자 커스텀 캐릭터의 시전 잠금 재현까지 증명하지는 않는다.

## 남은 범위와 다음 후보

1. 행동 기회를 늘렸지만, **목표를 끝내는 판단**은 아직 별도 문제다. 최종 브라우저 판은 826개 성장 행동 중 이동·도주가 616회였다. 루트 탐색 선택은 2회였고 이동 중 필드 획득과 자동 조합도 발생했다. 이동 선택을 전부 헛이동으로 볼 수는 없지만, 목표 재료를 구할 수 있는 곳에 머물며 장비를 완성하는지 추가 검증해야 한다.
2. 화면의 참가자 상태/미니맵 기본 갱신은 여전히 낮/밤 결과 반영에 의존한다. 반복 행동의 위치·체력 변화를 관전 화면과 더 촘촘히 동기화하려면 진행 중 자동 종료/부활 보호 처리도 함께 검토해야 한다.
3. 이동은 구역 단위 결과와 다음 행동 가능 시각으로 모델링한다. 연속 좌표 이동이나 도착 순간 별도 판정까지 구현한 것은 아니다.
4. 특수 재료의 즉시 상위 장비 변환 경로(`gearImmediateSpecialCraftRuntime.js`)는 이번 단계에서 제거하지 않았다. 모든 장비가 정규 레시피만으로 만들어진다고 주장하지 않는다.
5. 교전은 기존 개인 판정에 팀 지원과 범위 효과를 더한 구조다. 완전한 3대3 전투 엔진, 서든데스 의존도, 반복 이동에 따른 숙련도 성장, 후퇴 빈도, 소모품/상점 공급량은 다음 밸런스 검증 대상이다.

이번 결과는 반복 성장과 시계의 기능 검증이다. 원작 최신 규칙 재현, 재미, 재방문 가치, 로그인 가치가 검증되었다는 뜻은 아니다.
