2026-11-15 기준 기록이다. 후계가 준비되어도 공동체 조건 때문에 인계되지 않는 상황의 안내를 구분하고, 같은 행동의 후반 학술 단계에서 새 목표가 열렸을 때 반환 상태의 선택값을 기존 저장 복원 정책과 일치시켰다. 아래 결과는 보존된 실행 결과와 원장을 읽어 확인한 범위이다. 문서의 독립 감사는 읽기 전용으로 수행했으며, 제품 검사·빌드·화면 검증은 각각 별도 실행 증거로 구분한다.

## 제품 변경

### 준비된 후계의 조건부 인계 안내

`primitiveArchiveLineage.js`는 기존 공동체 준비 조건의 계산 결과를 `lineageSummary.communityReady`로 노출한다. 새 인계 조건이나 저장 필드를 만든 변경이 아니다. `primitiveArchiveSuccessionGuidance.js`와 실제 화면 선언은 다음 상황을 나눈다.

- 활동 중인 생존 인물에게 후계가 없으면 준비 안내와 기존 창건자 탭 이동을 제공한다.
- 후계가 이미 준비되었지만 공동체 조건이 충족되지 않으면 인계 대기와 공동 배식·사기·정착 기반 확인 안내를 제공한다. 연결 버튼은 공동체 탭으로 이동한다.
- AP 0만으로 준비된 후계의 인계가 공동체 조건 때문에 막혔다고 판정하지 않는다. 종료·옛 생애 정책·은퇴·사망 인물을 잘못된 행동 안내에 포함하지 않는다.

안내와 탭 이동 자체는 후계 준비 비용을 지불하거나 인계를 실행하지 않는다. 기존 활동 20년 경고, 준비된 후계의 25년 이상 생전 자동 인계 조건, 관찰 생애 60년, 실제 일손 전환, 배식·사기 조건은 유지한다.

### 학술 단계가 끝난 행동 반환 경계의 선택 정규화

실제 179년 상태에서 후장식 소총(`BREECH_LOADING_RIFLE`)은 이미 116/116 완료였지만, 바로 진행할 다음 기술이 없어 기존 선택으로 남아 있었다. 180년의 후반 제도 단계가 공장제(`FACTORY_SYSTEM`)를 108/114에서 114/114로 완료하면서 철도 공학(`RAILWAY_ENGINEERING`)을 열었다. 원래 반환 상태는 완료된 후장식 소총 선택을 유지했지만 `normalizeState` 저장 복원은 철도 공학을 선택하여 전체 상태가 달라졌다.

`primitiveArchiveEngine.js`는 기존 `normalizeState`의 선택 정책을 공통 함수로 옮겼다. 개인 행동·연간 정산·일일 정산·휴식의 기존 학술 단계가 모두 끝난 반환 경계에서만 적용한다. 완료 처리 도중에 선택을 앞당겨 바꾸지 않으므로 같은 행동 후반의 RP·CP 대상과 기여량을 바꾸지 않는다. 유효한 미완료 목표는 유지하며, 전 노드 완료처럼 새 목표가 없으면 이전 선택을 유지한다. 선행조건·정산 순서·난수·AP·재고·인물·수명·보상 규칙을 완화하지 않는다.
