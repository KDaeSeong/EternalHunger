# 문명 아카이브 좁은 화면 상단 지표 검증

2026-11-15 기준 기록이다. 기존 공개본 `171fb890`의 좁은 화면에서 상단 지표 이름이 한두 음절 폭으로 눌리는 현상을 대상으로 한다. CSS 변경과 검사·빌드는 제한 범위에서 통과했고, 실제 일일·연간 화면의 모바일 압축 개선도 확인했다. 다만 `fixed-local`의 원래 전체 화면 판정은 **`failed-layout-acceptance`로 보존**한다. 이후 같은 15조건에서 네이티브 수평 휠 접근성을 추가로 실측한 별도 검사는 `passed-fixed-layout`로 통과했다. 수정본 공개 전달은 커밋 후 같은 검사로 별도 판정한다.

이 문서는 아래 실제 결과 파일을 읽어 작성했다. 문서 작성 과정에서 검사·브라우저·캠페인·빌드·계정 작업·전경 조작을 추가 실행하지 않았다. 제품 CSS는 동결 상태다.

## 변경 범위와 소스 보존

제품 변경은 `client/src/styles/PrimitiveArchiveEras.css` 한 파일의 기존 `max-width: 760px` 블록에 추가한 6개 규칙, 1,133바이트다. 모든 선택자는 `.primitive-era.primitive-archive-page-shell` 범위에 속한다.

- 상단 기본 지표와 보조 지표 서랍을 한 열의 별도 행으로 배치한다. 기본 지표 4개는 두 열을 유지한다.
- 각 작은 지표 칩은 이름과 값을 각각 한 행에 놓는다. 보조 지표 칩에도 같은 배치를 적용하고 최대 폭을 제한한다.
- 이름은 단어 단위 줄바꿈을 유지하고, 값은 자연스럽게 줄바꿈하며 긴 연속 문자열에는 추가 줄바꿈을 허용한다.

지표·라벨·값·보조 서랍을 숨기거나 생략하지 않고, 글꼴 크기 축소나 말줄임으로 우회하지 않았다. 기존 서랍 내부 배치와 네이티브 `details`/`summary`, 시대 토큰·색·테두리, 다른 게임과 761px 이상 규칙은 변경하지 않았다. 공유 화면 마크업과 지표 데이터·게임 상태 처리도 변경하지 않았다.

설치된 PostCSS로 원형·수정 CSS를 모두 파싱했다. 추가 구간만 제거하면 원형 CSS의 나머지 바이트가 전부 일치한다.

## 실제 비교 입력과 첫 환경 실패

실제 연간 60년 저장 상태, 한 번 생성한 원형 일일 상태, 실제 연간 307년 저장 상태를 사용했다. 각 입력을 320·390·760·761·1280px에서 비교하여 원본·수정본 각각 15조건을 완성했다. 같은 드라이버·입력 해시를 사용하고 실제 애플리케이션의 공유·시대 CSS 전체를 로드했다. 시험용 CSS를 별도 우선순위로 주입한 결과가 아니다. 실제 CSSOM·미디어 조건과 시대 글꼴 진단도 보존했다.

첫 `baseline-public` 시도는 샌드박스 임시 프로필에서 Edge가 시작 중 닫히는 환경 오류였으며 **실행된 화면 조건은 0개**다. 원본 드라이버와 계획·입력·측정·결과의 해시를 보존했다. 이를 제품이나 레이아웃 실패로 계산하지 않는다.

이후 승인된 소유자 실행 환경에서 별도 `baseline-owned`를 완성했다. 첫 시도에서 이미 생성된 일일 상태의 같은 바이트를 재사용했고, 브라우저 샌드박스 옵션·글꼴·기하 측정·키보드·판정 조건을 바꾸지 않았다. 기존 실패 폴더를 덮어쓰거나 실패한 제품 조건을 더 쉬운 입력으로 바꾼 것이 아니다. 환경 기록의 `driver-prepared-not-executed`는 해당 기록 작성 시점의 상태이며, 이후 실제 원본 15조건 완료는 별도 결과에 남아 있다.

## 남은 데스크톱 내부 스크롤 판정

`fixed-local/result.json`은 15조건 완료·실행기 오류 0건이지만, 다음 **한 건** 때문에 `failed-layout-acceptance`다. 해당 실패는 삭제하거나 합격으로 바꾸지 않는다.

| 조건 | 원본·수정에 동일하게 남은 측정 |
| --- | --- |
| 입력·폭 | 연간 307년, 1280px |
| 대상 | 기본 지표 네 번째 칩, 관리 행동력 `3/4` |
| 기본 지표 행 | `clientWidth: 506`, `scrollWidth: 529`, `overflow-x: auto` |
| 절대 포함 판정 | 칩 오른쪽이 행 오른쪽보다 약 22.828px 바깥에 있음 |

원본과 수정본 모두 같은 내부 스크롤 구조와 좌표이며, 전체 상단·작업 영역·서랍·지표의 열린/닫힌 데스크톱 기하도 동일하다. 따라서 이 기록은 새 모바일 CSS가 만든 데스크톱 회귀의 증거가 아니다. 그러나 **기하가 같다는 사실만으로 가려진 지표에 실제 사용자가 접근할 수 있다고 증명할 수도 없다.** 기존 절대 포함 판정의 실패와 실제 수평 스크롤 접근성은 구분해야 한다.

원래 실행기·실패·관측값을 그대로 보존하고 `verify-mobile-header-scroll.cjs`로 실제 접근 동작을 추가 검증했다. 모든 입력에 동일하게 실제 `overflow-x: auto/scroll`과 양의 스크롤 범위를 확인한 뒤, `mouse.wheel`로 칩·모든 글자 Range를 완전히 드러내고 반대 휠로 원래 좌표·전체 저장 상태를 복원해야만 별도 접근 가능 영수증으로 분리한다. 특정 입력 예외, CSS 주입, `scrollLeft` 대입이나 잘림 무시는 허용하지 않았다. 다른 글자 압축·자체 칩 넘침·본문 넘침·데스크톱 차이 판정은 유지했다.

같은 세 입력·다섯 폭의 새 원본 `baseline-scroll-reviewed`는 실제 글자 압축 10건을 여전히 재현했고, 별도 접근 가능 내부 스크롤 5건을 기록했다. 수정본 `fixed-local-scroll-reviewed`는 15/15 조건·레이아웃 실패 0건·글자 압축 0건으로 통과했다. 남은 원관측 1건은 실제 양의 가로 휠 40으로 `scrollLeft`가 0→23이 되어 마지막 칩 전체가 보였고, 반대 휠 -529로 23→0이 됐다. 부모 너비는 506px·내용 너비는 529px이며, 복원한 전체 기하·저장 상태와 본문 안전 조건이 정확히 일치했다. 제품 수정·재빌드·새 경기 없이 같은 빌드에서 확인했다.

두 좁은 화면 PNG는 앞서 시각 확인한 결과와 SHA256이 같아 반복 출력하지 않았다. 모든 원장·키보드·재로드·쓰기 차단 검사는 같은 기준이며, v2도 완전한 15조건 원본과 실행기 전체 해시 일치를 필수로 확인한다. 공개판은 커밋 뒤 별도 배포 및 같은 15조건 결과로 판정한다.
