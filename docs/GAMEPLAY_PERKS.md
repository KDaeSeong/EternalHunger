# LP 플레이 특전

## 상품과 적용 범위

| 상품 | 가격 | 대상 | 효과 |
| --- | ---: | --- | --- |
| 꼼꼼한 채집 | 250 LP | 문명 아카이브 | 일반 채집에 성공하여 기본 자원을 실제로 얻었을 때 한 종류 +1. 런당 최대 3회. |
| 연구 기록법 | 400 LP | 문명 아카이브 | 직접 연구 행동에서 유효한 연구 포인트 +1. 런당 최대 10회. |
| 출발 후원금 | 250 LP | 이터널 헝거 | 경기 전에 지정한 후원 팀 대원마다 경기 크레딧 +30, 경기당 한 번. |
| 조달 제휴 | 400 LP | 이터널 헝거 | 경기 전에 지정한 후원 팀의 경기 내 키오스크·드론 구매 비용 5% 할인. |

구매는 영구 보유이고 자동 장착하지 않는다. `/perks`에서 게임별로 최대 3개를 장착한다. 장착·해제는 새 런 또는 새 경기부터 적용된다. 이미 시작한 경기의 효과와 사용 횟수는 변경하지 않는다. 경기 크레딧은 사이트 계정 크레딧과 다른 재화다.

## 게임 규칙

- **문명 아카이브:** 새 런의 `shopPerks`에 코드와 사용 횟수를 고정한다. 저장·불러오기·직전 런 복구는 그 스냅샷을 보존한다. 처음 여는 새 기기 런도 첫 행동 전에 장착 정보를 확인한다. 채집 실패, 안전 채집, 전문 생업에는 꼼꼼한 채집을 소모하지 않는다. 추가 난수를 뽑지 않고 기존 획득 순서의 첫 기본 자원에 보너스를 더한다. 연구 완료·잠김·행동 불가 또는 기본 연구만으로 완료하는 경우에는 연구 기록법을 소모하지 않는다. 일일 자동 연구와 사회 제도에는 적용하지 않는다. 행동 화면과 런 관리에서 남은 횟수를 확인할 수 있다.
- **이터널 헝거:** `경기 설정 → 이번 경기 후원 팀`에서 후원 대상을 정한다. 관전 팀과 별개이며, 최종 편성의 `matchTeamId`와 대원 ID를 경기 시작 입력에 고정한다. 솔로는 선택 대원 1명이다. 후원금은 중복 지급하지 않고, 할인은 실제 견적·구매 가능 판단·결제에 같은 규칙으로 적용한다. 리플레이는 원래 후원 정보와 지급 상태를 사용하며 계정 특전을 다시 조회하지 않는다. 기준 평가 경기는 계정 후원을 적용하지 않는다.
- 두 게임 모두 인증된 특전 확인이 실패하면 새 경기를 임의로 시작하지 않는다. 재시도하거나 명시적으로 **LP 특전 없이 시작**을 선택할 수 있다. 계정이나 경기 조건이 확인 도중 바뀌면 시작을 중단한다.
- LP 플레이 특전은 기존 전역 자동 특전 합산에서 제외한다. 기존 치장 상품 및 관리자가 만든 별도 전역 특전 규칙은 유지한다.

## 계정 API와 유지보수

- 기본 상품: `server/utils/defaultPerks.js`; 클라이언트 효과 계약: `client/src/utils/gameplayPerks.js`.
- `GET /perks/available`: 활성 상품과 본인의 `user.perkLoadouts`를 반환한다.
- `POST /perks/loadout`: `{ gameSlug, codes }`. 게임별 최대 3개, 보유·활성·게임 범위·중복을 확인하고 해당 게임 장착만 변경한다. 빈 배열은 전체 해제다. LP와 소유 목록은 변경하지 않는다.
- `perkLoadouts`는 로그인·세션·내 정보 응답에도 포함한다. 구매는 기존 조건부 단일 갱신으로 중복 과금을 막는다.
- 새 경기 캡처는 캐시를 사용하지 않으며, 현재 계정·활성 상품·보유 코드·장착 코드의 교집합만 사용한다. 다른 계정의 지연 응답은 무시한다.

## 검증

- `npm --prefix server test`: 구매·장착·인증·기존 서버 회귀 검사.
- `npm --prefix client run check:gameplay-perks`: 네 상품 계약, 계정 전환과 지연 응답, 상점 구매·장착, 문명 아카이브 효과·횟수·새 런, 이터널 헝거 후원·견적·결제·리플레이 검사.
- `npm --prefix client run check:primitive-archive`: 기존 문명 아카이브 전체 유지 검사에 신규 특전 검사를 포함한다.
- 영향받는 인증·조달·경기 재현 검사, 변경 파일 ESLint, 배포용 빌드를 함께 확인한다.
- 브라우저 검증은 공개 계정 재화를 사용하지 않는 로컬 메모리 API와 실제 배포용 클라이언트를 이용한다. 이 결과는 실제 사용자의 재미·이해도 평가를 대신하지 않는다.
