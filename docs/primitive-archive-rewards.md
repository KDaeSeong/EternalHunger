# 문명 아카이브 완료 보상 정책

완료 보상은 첫 저장된 런 스냅샷에서만 판정한다. 서버는 결과·점수·클라이언트가 보낸 금액을 보상 근거로 사용하지 않고, 생성된 정책 계약의 완료 조건을 확인해 고정 금액을 결정한다.

- 기본 완료: 500 LP와 계정 크레딧 1,000
- 기술·사회 제도 전체 완료: 총 1,500 LP와 계정 크레딧 3,000
- 계정별 KST 날짜 한도: LP 5,000, 계정 크레딧 10,000

완료 상태, 승리 상태, 계약상 최소 일수, 필수 핵심 기술·사회 제도, 정착 시설과 책, 생존자 수, 런 정산 식별자를 모두 확인한다. 개발자 도구는 `used`가 참이면 제외한다. 패널만 켰고 실제 조정값이 없는 스냅샷은 허용하지만, 활성화된 상태에서 확정 성공·전문화 행동 해제·0이 아닌 행동 보정이 있으면 제외한다. 잘못된 형식은 보상 대상이 아니다. 부적격 런도 기존 전적 저장 동작은 유지한다.

런 보상 원장, 사용자 잔액, KST 날짜별 사용액은 한 MongoDB 트랜잭션에서 변경한다. 보상 원장은 사용자·게임·런 식별자로 영구 중복 방지하며, 전적 행을 삭제해도 지급 이력은 남는다. 일일 한도를 넘은 보상은 지급액 0으로 응답하고 한도를 소진하지 않는다. 해당 런의 첫 저장 스냅샷을 다음 KST 날짜에 재시도하면 정해진 금액을 받을 수 있다. 매일 지급액을 새로 산정하지 않으며 런별 첫 지급 후에는 재지급하지 않는다.

## 신뢰 한계

게임 결과는 현재 `client_reported` 스냅샷이다. 서버는 제출된 상태 필드 사이의 필수 조건을 검사하고 지급액과 중복 방지를 서버에서 결정하지만, 플레이 과정 자체가 진짜였는지 또는 스냅샷이 변조되지 않았는지를 증명하지 않는다. 스냅샷만 조작해도 보상을 노릴 수 있으므로 이 검사는 서버 권위 게임 판정이나 부정행위 방지로 설명해서는 안 된다. 고정 지급액과 계정별 일일 한도는 악용 규모를 제한할 뿐, 악용을 차단하지 않는다.

정책 원본은 `client/scripts/generate-primitive-archive-reward-contract.mjs`와 게임 데이터다. `node client/scripts/generate-primitive-archive-reward-contract.mjs --check`로 클라이언트 표시 규칙과 서버 계약 파일이 같은지 확인한다.

## 게임 내부 특전 점검

완주 포인트는 `max(3, floor(finalScore / 700))`, 미완성 정산은 `max(1, floor(score / 850))`이며 같은 런의 재정산과 개발자 보정 런 지급은 막는다. 이 포인트는 계정 LP·크레딧과 별개이며 다음 런의 소유 특전에 사용한다. 현재 여섯 특전을 최대 레벨까지 구입하는 총비용은 15포인트다. 장기 런에서는 지급액보다 선택지와 사용처가 먼저 부족해진다. 이번 변경은 포인트 점수식을 올리지 않는다.

전용 실제 엔진 검사 10개로 지급·중복·개발자 제외, 여섯 종류의 구매 비용과 상한, 새 런에서의 효과, 체크포인트 직렬화와 복원, 회복 물품 사용을 확인했다. 발견한 과상한 소유 레벨 및 무한대 포인트를 정규화하고, 설명과 달리 빠져 있던 육포·약초 달임을 기존 지급품에 추가했다. 정상 저장의 기존 지급품과 AP 효과는 줄이지 않는다.

## 추가 특전 제안 — 아직 구현하지 않음

아래 비용과 효과는 검토용이며 현재 상점이나 엔진에 적용되지 않는다. 자동 생존 기능을 다시 유료 특전 뒤에 잠그지 않고, 유상 행동과 자원 소비를 남기는 방향이다.

| 후보 | 제안 효과 | 레벨당 비용 / 최대 레벨 |
| --- | --- | --- |
| 연구 노트 | 새 런에서 연구를 개방할 때 연구 포인트 +5/레벨을 한 번 지급 | 8 / 3 |
| 겨울 준비 | 밤의 추위 피해를 레벨당 5%, 최대 15% 줄임. 추위 면역은 주지 않음 | 6 / 3 |
| 공동 취사 | 공동 식사의 허기 회복량을 레벨당 5% 높임. 식량과 AP 비용 유지 | 10 / 2 |
| 개척 지도 | 시작 인접 지역 하나를 추가 공개. 탐사 보상·사건은 지급하지 않음 | 6 / 1 |
| 채집 요령 | 매일 첫 유상 안전 채집에서 선택 자원 +1. 나머지 채집 비용 유지 | 5 / 1 |
| 응급 비축 | 새 런 시작 시 약초 달임 +1/레벨. 기존 약초 주머니와 합산 | 6 / 2 |

## 사이트 LP 상점 점검

문명 아카이브 내부의 여섯 특전과 사이트 LP 상점의 여덟 치장 상품은 별개다. 사이트 상품은 구매와 계정 소유 저장까지 구현되어 있으나, 현재 사용자 화면에서 `cosmeticKind`·`portraitFrame`·`logStyle`·`victoryEffect`를 소비하는 적용 경로는 발견되지 않았다. 칭호도 프로필·결과 화면 적용 경로가 없다. 프레임·로그·승리 연출의 일부 설명은 원래부터 콘셉트 또는 향후 기능으로 되어 있다. 이 소스 감사는 실제 연출 작동을 검증한 결과가 아니며, 추가 상품보다 기존 여덟 종류의 사용·적용 연결이 우선이다. 이번 변경에서 새 연출을 구현하지 않는다.

구매 경로의 읽기-차감-전체 저장은 보상 지급이나 다른 상품의 동시 구매와 충돌해 잔액·소유 목록을 잃을 수 있었다. 서버 가격 검증 뒤 잔액·미소유 조건을 포함한 단일 사용자 문서 갱신(`$inc`·`$addToSet`)으로 바꿨다. 실제 라우트 단위 fixture 여섯 사례는 같은/다른 상품의 동시 구매, 지급과 차감의 합산, 재구매, 부족 잔액, 잘못된 가격과 요청 가격 위조를 확인한다. 이는 모의 모델 단위 증거이며 앞선 실제 Mongo 보상 정산 검사 네 가지와 구분한다.
