# 회사 리포트 수량 입력 검증

2026-11-15 백그라운드 브라우저 검사에서 수량을 `0`으로 입력하고 생산하면
1개를 생산하면서 9,000원과 하루를 사용하는 문제를 재현했다. 주문 생성에도
같은 최소 수량 보정이 있어 잘못된 입력으로 주문 번호가 발급될 수 있었다.

`createOrderAction`과 `inboundInventoryAction`은 입력을 숫자로 해석한 뒤
1 이상의 안전한 정수인지 검사한다. 0, 음수, 빈칸, 소수, 유효하지 않은 숫자를
1개로 바꾸지 않고 안내만 남긴다. 이 경우 현금, 날짜, 재고, 주문과 일련번호는
변하지 않는다. 숫자로 된 문자열은 정상 수량으로 사용할 수 있다.

검증 결과:

- 기존 소스에서 추가 회귀 검사 2개가 실패해 생산·주문의 같은 문제를 확인했다.
- 수정 후 업무 시간 검사 25개와 회사 리포트 전체 검사 10종이 통과했다.
- 변경 파일 정적 검사와 배포용 빌드, 실제 생성된 실행기의 첫 구간 검사가 통과했다.
- 수정한 배포용 빌드의 손님 화면에서 수량 0 생산·주문을 직접 실행해 현금·날짜·재고·주문이 유지됨을 확인했다.
- 같은 화면에서 3개 생산의 27,000원·하루 소비, 신규 주문 선택·출고의 재고 3개 소비를 확인했다.
- 실제 결제일까지 날짜를 진행한 뒤 해당 채권 92,400원을 회수하고 재회수 버튼이 잠기는 것을 확인했다.

화면 검사는 계정과 게임 상태를 주입하지 않은 별도 백그라운드 브라우저에서
수행했다. 실제 계정 저장과 자연스러운 로그인 만료, 장기 경제 균형은 별도 검증 대상이다.
