## 범위와 보존 조건

- 대상: `client`, `server`, `shared`의 웹 서비스 코드와 검사 도구.
- 시작 당시 추적 중인 웹 코드 1,280개와 기존 미추적 웹 도구 8개를 분류했다. 수정 후 새 검사·실행 파일 5개를 포함한 JS/TS 구조 분석은 1,271개 모듈, 구문 분석 실패 0개다.
- 웹 밖의 미추적 `native`, `myanime`, `tools` 등은 파일 목록만 조사했다. 해당 코드의 전체 수동 검토나 삭제는 수행하지 않았다.

## 조사 기록과 남은 관문

작은 로컬 조사 도구·수치·원시 실패 기록은 `.local/code-audit/`에 보존했다. 주요 기록은 `baseline-structure.json`, `after-structure.json`, `replay-comparison-after.json`, `build-asset-inventory.json`, `client-build.log`, `mongo-market/*/receipt.json`, `cleanup-receipt.json`, `cleanup-native-result.json`이다. 대용량 원본·프로젝트 사본은 추가하지 않았다.

실제 DB 도구를 준비할 때의 옵션 검사 필드 오류와, 기존 인벤토리 손실을 드러낸 실패 기록도 남겼다. 최종 성공만 남기기 위해 실패 증거를 삭제하지 않았다. 종료된 DB 데이터·내려받은 임시 바이너리·검증이 끝난 이전 빌드·재생성 캐시는 경로와 해시를 잠근 뒤 정리하고, 현재 빌드·직전 성공본·고유 오류 재현 빌드는 보존했다.

자연 생명의 나무 목표의 실제 화면 표시, 편성 변경의 충분한 협동 노출, 엄격한 전경 배속·메모리 기준, 사람의 후속 관전 평가, 문명 아카이브의 수정 후 첫 3일 이해도와 자연 로그인 만료 후 복귀 검증은 여전히 별도 관문이다. 이번 코드 최적화나 통제 검사가 해당 관문을 대신하지 않는다.

## 후속 조사: 공간 조회와 관전 진단

위 표는 첫 배포 `53b84f3b`의 당시 결과다. 후속 변경은 다음과 같다.

- 전투 대상 조회 한 번 안에서만 공간 능력치를 재사용한다. 후보가 0~1명이면 기존 경로를 유지한다. 전역 캐시·객체 정규화 캐시를 추가하지 않았으며, 다음 조회에서 장비·상태 변경을 새로 읽는다.
