# 사용자 지정 키오스크의 목표 재료·제작비 보호

2026-11-15. 정확한 목표 주문에는 레시피 검증이 있었지만, 그 뒤 고르는 일반
구매·교환·환급에는 없었다. 실제 견적과 원자 거래에서 목표 수수료 20Cr를
남긴 대원이 무관한 물품을 7Cr에 구매하여 13Cr만 남기거나, 예약 재료를
교환·매각하는 경우를 재현했다. 가방 자동 정리와 장비 교체도 목표 부품을
잃게 할 수 있었다.

세 일반 거래 경로에 실제 거래 미리보기와 남은 레시피 검사를 연결했다.
이미 확보한 예약 재료를 줄이거나 제작비 부족액을 늘리는 일반 거래는
선택하지 않는다. 기존의 정확한 목표 주문은 여전히 남은 전체 제작비를
감당해야 한다. 판매 미리보기는 실제 `kioskSell` 정산 경로를 사용한다.

다음 정상 거래는 유지한다.

- 정확히 남는 7Cr를 지불하는 27→20Cr 구매.
- 자금이 부족해도 진짜 여분만 팔아 5→12Cr로 늘리는 환급과 무료 거래.
- 실제 목표를 구매하여 남은 제작비를 없애거나, 중간품 획득으로 줄이는 거래.
- 여분 한 묶음을 팔아 가방 한 칸을 비우고 실제 목표 제작을 가능하게 하는 거래.
- 목표나 규칙 입력이 없는 기존 호출의 동작, 판매처 제한과 기존 확률 게이트.

구성품을 받는다는 이유만으로 예약 보호를 해제하지 않는다. 실제 남은 제작품을
대체하며 수수료·새 제작 단계·필요 수량을 늘리지 않는 획득만 예외로 둔다.
이미 만든 부품을 원재료로 되돌리거나, 영비용 부품 2개를 1개로 교환하여
같은 단계의 실제 제작 횟수를 늘리는 경우도 차단한다. 기존 목표 거래의
검증과 전역 거래 API·난수·가격·재고 공급은 바꾸지 않았다.

## 검증

`npm run check:kiosk-growth-reservation`은 실제 견적·정산과 성장 계획 갱신,
JSON 복원, 수량·지출, 미리보기의 원본 불변, 가방 회복, 다단계·갈래·영비용
레시피, 목표 직접 구매와 여분 환급을 27그룹으로 확인한다. 기존 팀 구매
검사 묶음에도 연결했으며, 이를 실행하는 검증 모드의 소스 지문에 포함했다.

같은 최종 검사에 이전 `887e3abb`의 두 제품 모듈만 메모리에서 불러온 독립
실행은 12/27, 수정 소스는 27/27이었다. 실제 제품 파일을 이전 소스로
되돌리지 않았다. 첫 독립 실행은 Windows의 절대 `--import` 경로 오류로
검사에 진입하지 못했으며, 파일 URL로 고친 동일 입력 실행과 구분해 보존했다.

조달·기존 키오스크·팀 구매·목표 재료·이동 견적·성장 획득·예약·검증 지문과
린트 14명령은 동일한 1,618개 소스 입력에서 통과했다. 이동 견적은
`--fixtures-only`만 실행했으며, 실패한 고정 편성 8회와 5501/5502 표본을
재실행하거나 시드를 탐색하지 않았다. 새 엔진은 `5e4118c2…`다.

이는 동기 행동에서 실제 사용자 지정 상점의 목표 보호를 확인한 범위다.
모든 커스텀 조합의 자율 선택·전략 균형·전경 배속·사람 평가 합격으로
확대하지 않는다. 전체 프로덕션 빌드 `JbEJHG9D_bjR9_ON-iy0a`는 같은 1,618개
입력과 엔진 지문을 유지했고, 빌드된 Worker 첫 단계까지 통과했다. 공개판의
실제 경기·재경기는 푸시 후 별도 확인한다.
