# 관전 성능 진단과 연속 측정의 계약

팀 판단 스케줄러의 회귀검사는 팀 순서, 취소 시 generator 종료, 양보 중 난수 범위 해제와 일반/협력 실행의 난수·결과 보존을 검사한다. 주입 시계와 합성 wait로 검증한 계약을 실제 브라우저 실행 시간이나 화면 렌더링 성능의 합격 근거로 쓰지 않는다. 협력 실행의 시간 예산은 팀/행동 경계에서 양보하는 기준이며 단일 팀·행동을 중간에 끊는 강제 상한이 아니다.

## 발생 시각과 귀속 보존

자동 중지의 측정 시각은 중지 요청 때 고정하지만 늦게 전달되는 observer 표본은 다음 RAF와 task 뒤까지 배출한다. 그 동안 JSON의 경계는 `draining`이며 `settled`나 최종 `incomplete`와 구분한다. RAF만 실행된 시점도 아직 `draining`이다. 최종 종료·시간 초과·즉시 dispose/restart의 결과를 회수한 뒤 다음 측정을 시작한다. 이전 배포의 v3 JSON은 배출 중에도 임시 `incomplete`로 나타날 수 있으므로 수집 도구는 화면의 '측정 완료'도 확인해야 한다. 종료 시각이 있다는 이유만으로 최종 결과라고 인정하지 않는다.

`longTasks.slowest`는 관측한 전체 긴 작업 중 duration 상위 8개의 `startOffsetMs`와 `durationMs`만 보관한다. 전체 count/total/max 집계는 표본 제한과 무관하게 유지한다. 측정 경계와 교차하는 작업의 전체 시간을 사용하므로 시작 offset은 음수일 수 있다. PerformanceEntry, container 식별자, Window 참조나 무제한 task 로그를 보관하지 않는다. 이 발생 시각을 기존 계산 단계의 `maxStartOffsetMs` 및 LoAF와 같은 측정 시계에서 대조할 수 있다. 단계별 전체 호출 기록이나 전체 스택은 아니므로 시각이 겹친다는 이유만으로 CPU 시간이나 특정 script의 원인 귀속을 확정하지 않는다.

실시간 observer 전달을 과거 타임라인의 제한된 버퍼 조회로 대체하지 않는다. [Performance Timeline 작업 초안](https://w3c.github.io/performance-timeline/#queue-a-performanceentry)의 2026-03-24 정의는 관심 observer의 buffer에 새 entry를 추가한 뒤 별도의 타임라인 buffer 한도를 판단한다. `droppedEntriesCount`도 그 과거 타임라인 buffer의 누적 누락 수이므로 곧바로 이번 측정 창의 observer 누락 수라고 해석하지 않는다. 이는 작업 중인 명세의 설명이며 모든 브라우저의 무손실 전달을 실측으로 증명한 것은 아니다. 기존 대량 합성 검사는 전달받은 전체 표본을 probe가 자체 제한으로 버리지 않는지 확인한다. 자세한 진단 목록 8개 제한과 전체 집계의 보존은 구분한다.

LoAF의 `slowest`는 duration 상위 8개를 유지하고, `mostBlocking`은 blocking duration 상위 8개를 별도로 유지한다. 긴 프레임이 다른 짧고 많이 막힌 프레임을 가리는 것을 방지한다. 각 프레임의 script는 최대 8개이며 기존 텍스트 길이 제한과 URL의 인증정보·query·fragment 제거를 유지한다. 미지원·누락·잘못된 blocking duration은 null로 보존하고 실제 0은 0으로 기록한다. 반환하는 두 배열과 script 배열은 소유한 복사본이며 반환값 수정·재시작·이전 observer 콜백이 새 결과를 바꾸지 않는다.

[Chrome의 LoAF 설명](https://developer.chrome.com/docs/web-platform/long-animation-frames)에 따라 프레임 duration, blocking duration, render/style-layout 시간을 구분한다. 비동기 진입점 정보는 전체 호출 스택이나 GC 원인 분석이 아니며 실제 화면 제시·paint 완료·INP를 증명하지 않는다. 중첩 계산 단계의 total/max는 같은 시각의 값이 아닐 수 있으므로 합산하지 않는다.

## 파일 순서와 회차 간격

분석기는 x1·x8·x32에서 각각 정확히 세 회차를 같은 문서·엔진·환경·원본 입력으로 받는다. 파일 목록에서 같은 배속 세 회차가 이웃해 있는 것만으로는 연속 측정을 인정하지 않는다. 같은 배속의 이전 `endedAtMs`부터 다음 `startedAtMs`까지의 간격을 계산하여 사전에 선언한 `maxInterRunGapMs` 이하인지 검사한다. 누락·비유한·음수·초과 간격은 미검증이며, 해당 묶음의 메모리 관문도 합격 처리하지 않는다. 간격 정책의 기본값은 없으며 0은 명시적으로 선언한 인접 측정의 상한으로 허용한다.

CLI에서는 `--max-inter-run-gap-ms=<사전 선언 값>`을 넘긴다. 빈 숫자 인자는 0으로 바꾸지 않는다. 기존 strict 최대 Long Task <200ms 외의 RAF p95·최대 간격·시작 heap 증가 예산도 실측 전에 정하고 명시한다. 결과를 본 뒤 예산을 정해서 합격으로 만들지 않는다. 반복 중 누락/공백이 발생하면 해당 표본을 보존하고 새 측정 계획을 선언한다. 성능 실패 자체는 표본 제외나 재측정 이유가 아니다.

새 JSON은 `numericPrecision.roundedMillisecondsResolutionMs`에 밀리초 출력의 반올림 간격을 명시한다. 현재 값은 0.001ms이며 포맷 함수와 같은 상수에서 만든다. 분석기는 최대 Long Task·RAF 간격에 출력 반올림의 상한을 반영하고, 회차 간격은 두 시각의 오차 범위를 반영한다. 실제로 기준을 넘은 값이 출력에서 내려가 합격처럼 보이는 것을 막는다. 기존 v3의 메타데이터 없는 기록은 그 포맷의 세 자리 소수 출력을 적용하며 잘못된 명시 정밀도는 미검증이다. 정밀도 0은 반올림하지 않은 정확한 입력을 뜻하며 합성 fixture에서 사용한다. 이는 JSON 출력의 정밀도이며 브라우저 API 자체의 시계 정밀도나 CPU 시간 보장이 아니다. 예산의 물리적 의미나 값을 사후 변경하지 않는다.

전체 `pass`에는 완주·자동 비교·배출 경계·측정 시작 전 문맥·전체 가시성·회차 간격·모든 선언한 품질 관문의 증거가 필요하다. 시작 문맥의 비교 결과와 비교 사건 수는 모두 null이어야 하며, 이전 재경기의 비교 결과를 새 회차의 근거로 인정하지 않는다. 누락된 증거는 전체 `unverified`지만 이미 관측한 개별 Long Task 실패를 숨기지 않는다. 전체 입력이 유효하고 어느 품질 관문이 실패하면 다른 예산이 미선언이어도 전체 `fail`이다. RAF percentile의 overflow/null을 0이나 상한의 건강한 값으로 바꾸지 않는다. 시작/마지막 RAF 경계 지연을 최대 간격에 포함한다.

`performance.memory`는 GC·캐시·결과 기록에 영향을 받는 관측값이며 세 기준선이 낮아져도 누수 부재를 확정하지 않는다. 가시성은 각 측정 창 및 종료 배출 중 알림의 기록이다. 회차 사이 공백 전체의 가시성을 기록했다고 주장하지 않으며, 측정 창 내내 visible이어도 초점·화면 제시·환경의 스로틀링 유무는 별도 확인이 필요하다. 배속 설정을 확인한 것과 실제 진행 속도 달성을 구분한다. GAME READY 이전 보관 자료 복원 시간은 현재 측정 창 밖이므로 측정했다고 주장하지 않는다.

## 검증과 실측의 경계

RAF p95 관문은 히스토그램 반올림과 밀리초 출력 반올림의 상한을 함께 반영한다. 출력 정밀도가 없거나 잘못된 경우도 이 관문의 합격 근거로 쓰지 않는다.

`check-observer-performance-probe.mjs`는 합성 PerformanceEntry/시계/observer로 집계·경계·소유권·표본 제한을 검사한다. `check-observer-performance-report.mjs`는 합성 9회 입력으로 잘못된 합격 거부와 CLI 종료 코드를 검사한다. 두 검사 모두 실제 브라우저 속도의 증거가 아니다. 새 계측 필드는 새 엔진 버전에 포함되며, 이전 엔진에서 수집한 표본을 새 배포의 실측으로 승계하지 않는다. 실제 Long Tasks·RAF·heap·가시성과 화면 제시/사용자 조작은 접근 가능한 해당 배포의 브라우저에서 별도로 측정한다. 인증이 필요한 미리보기를 우회하지 않는다.
