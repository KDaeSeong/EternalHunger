# 게스트 이름·스킬 편집 연결 및 검증

기준일: 2026-09-05. G2.3의 캐릭터 정의를 로그인 없는 실제 편성/경기 경로에 연결하는 단계다. 전체 목표 완료, 원작 전 실험체 구현, 밸런스/재미 합격을 뜻하지 않는다.

후속 기록: 지역 내부 거리·시야 및 접근은 이후 `combat-spatial-verification.md` 단계에서 연결 중이다. 아래 추상 사거리 설명과 경기/브라우저 증거는 게스트 편집 단계의 엔진 기록이며, 새 공간 규칙 버전의 검증 증거로 사용하지 않는다.

## 사용자 경로와 범위

경기 시작 전 `24인 직접 편성` → 후보의 `이름·스킬 편집` → 이름, 전술, Q/W/E/R/패시브 설정 → `기기에 저장하고 반영` → 편성 적용 → 경기 시작.

- 기존 게스트 기본 24개 슬롯을 편집한다. 식별자와 팀 배정은 유지하고 표시 이름/스킬만 바꾼다. 새 캐릭터 라이브러리의 임의 추가·삭제나 초상화/기본 능력치/무기 편집까지 구현한 단계는 아니다.
- 기본 게스트에는 원작 Q/W/E/R을 자동으로 창작해 넣지 않는다. 후보에 현재 정의된 슬롯 또는 `캐릭터 스킬 없음`을 표시한다.
- 사용자가 명시한 이름/스킬/전술을 별도 로컬 저장 키 `eh_guest_character_profiles_v1`에 저장한다. 계정 캐릭터 저장이나 계정 API를 호출하지 않는다. 다음 새로고침/새 경기의 게스트 초기화에서도 읽는다.
- 저장 성공 뒤 후보 목록과 현재 선택 참가자를 함께 갱신한다. 편성 프리셋은 기존의 안정적인 캐릭터 ID/팀 순서를 유지한다. 별도 캐릭터 정의 저장과 동일 경기의 전체 시작 입력 보관은 다른 용도다.
- 경기 시작 뒤, 진행 예약 잠금 직후, 종료 상태, 동일 재경기에서는 편집 쓰기를 거절한다. 재경기는 그때 저장한 전체 입력만 사용하여 이후 이름/스킬 변경을 읽지 않는다.
- 캐릭터의 실제 HP 잔량, 장비·재료 가방, 팀, 쿨다운, 예약 시전, 보상 등 경기 상태를 프로필에 저장하지 않는다.
- 이름을 원작 실험체와 같게 바꿔도 숨은 이름 매칭으로 원작 스킬/능력치/무기를 추가하지 않는다. 명시적으로 끈 슬롯도 기존 카탈로그 스킬로 되살아나지 않는다.

## 스킬 편집의 실제 의미

- 기존 공용 스킬 입력 필드를 재사용한다. 레벨별 피해/회복/보호막, 피해 종류, 공격력/스킬 증폭 계수, 시전/후딜, 재사용 창, 지원 대상과 AI 조건을 저장한다.
- Q/W/E/R 레벨은 성장에 따른 자동 선택 또는 슬롯별 1~5레벨 고정이다. 이전 편집기의 `최대 레벨` 문구와 실제 고정 레벨 처리를 그대로 가져오지 않았다.
- 설명에서 수치 채우기는 기존 로컬 설명 해석기의 입력 보조다. 임의 CC/이동 동작을 생성하는 기능으로 설명하지 않는다. 변환 후 필드를 확인하도록 안내한다.
- 공용 작성 정규화에서 빠지던 `includesMovement`, `damageType`, 공격력 계수를 보존하도록 고쳤다. 이동 포함은 현 단계의 속박 사용/취소 구분이며 실제 돌진 경로 생성이 아니다.
- 사거리와 광역은 아직 같은 지역 안의 추상 판단이다. 화면에서도 실제 미터 판정이라고 주장하지 않는다.
- 사용 중인 스킬의 이름/실제 효과가 비어 있거나 현재 지원 시간/범위 상한을 넘으면 저장을 거절한다. 이름 변경만 하는 경우 모든 캐릭터 스킬을 끈 상태로 저장할 수 있다.
- 저장 공간 없음/초과/쓰기 실패는 현재 편성에 적용하지 않고 실패 사유를 표시한다. 손상되거나 지원하지 않는 저장 형식은 자동 덮어쓰기하지 않는다.

## 패시브 체력 연결 수정

기존 `getEffectiveStats`에는 패시브 체력이 포함됐지만, 초기 참가자의 실제 `maxHp`/`hp`에는 연결되지 않았다. 편집창에서 선택한 효과가 표시용 능력치에만 머무르지 않도록 초기화와 경기 전 편집에 연결했다.

- 실제 적용한 체력 차이를 경기 상태에 기록하여 반복 저장 때 중복되지 않게 한다. 이 표식은 프로필의 저장 항목이 아니다.
- 패시브를 끄거나 값을 바꾸면 이전에 실제 적용했던 차이만 교체한다. 최소 HP 1에 걸리는 큰 음수 값도 제거 후 원래 상한으로 돌아온다.
- 양수 증가가 사망자를 부활시키지 않게 하고, 기존 특전 기본 HP 재계산이 패시브를 지우지 않도록 함께 갱신한다.
- 새 경기 초기화는 이전 생명의 적용 표식을 재사용하지 않는다. 기본 능력치에 패시브 수치를 중복 합산하지 않는다.

### 실제 브라우저 편집

검증 전용 로컬 주소 `http://127.0.0.1:3120/eternalhunger`의 게스트 화면을 사용했다. 실제 계정이나 원격 서버의 캐릭터를 수정하지 않았다.

- 백로를 `시전 검사 백로`로 바꾸고 전술을 `치유의 바람`으로 변경했다.
- Q `검증 지연 타격`: 공격 스킬, 피해 20/25/30/35/40, 3레벨 고정, 고정 피해, 쿨타임 3초, 선딜 1.25초, 후딜 0.25초를 실제 입력란에서 설정했다.
- 패시브 `검증 체력`에 체력 +30을 입력했다. 저장 직후와 새로고침 후 실제 참가자 HP가 118/118에서 148/148로 변경됐다. 같은 값을 반복 저장해도 148/148을 유지했다.
- 새로고침 후 편집창에서 Q 이름·레벨·피해 배열·시간·종류와 전술이 복원됐고, 직접 편성 적용 후 다시 새로고침한 화면에서도 사용자 지정 모드와 5팀 배정이 유지됐다.
- 저장하지 않은 이름 변경을 취소하면 기존 이름으로 돌아왔다. 사용 중인 Q 이름을 공백으로 바꾸면 `Q 스킬 이름을 입력해 주세요.`를 표시하고 편집창을 유지했다. 취소 후 저장된 정상 스킬을 사용했다.
- 경기 시작 후 편성 편집 진입이 사라지고, 저장 입력 재경기의 준비 화면에도 편집 진입이 없음을 확인했다.

### 화면에서 발견해 수정한 문제

- 전역 오디오·튜토리얼 실행 버튼의 표시 순서가 편성/편집창보다 높아 저장 버튼 일부를 가렸다. 편성창을 실행 버튼보다 위, 해당 안내 대화상자보다 아래에 놓아 저장 버튼이 온전히 보이도록 수정했다.
- 공용 캐릭터 편집 스타일의 어두운 글자색이 어두운 게스트 편집창에 적용됐다. 게스트 편집창 안의 패시브/레벨 항목 글자색을 밝게 지정했다.
- 후보 목록이 Q/W/E/R만 나열하던 부분에 실제 정의된 패시브도 포함했다. 패시브가 있는데 스킬이 없는 것으로 보이지 않게 했고, 브라우저에서 `Q · 패시브` 표시를 확인했다.
- 실제 1280×720 화면에서 Q/패시브 입력란, 내부 스크롤, 저장·취소 버튼과 수정된 대비를 확인했다. 다른 화면 크기·브라우저의 전수 검증으로 확대 해석하지 않는다.

### 실제 브라우저 경기

사용자 작성 Q/패시브를 가진 1명과 기본 게스트 23명의 직접 편성 경기에서 전술 회복, 사용자 작성 스킬 시전 취소(시전자 사망), 실제 교전 종료와 로컬 기록 저장을 확인했다. 원본은 20:52에 3팀 마루·윤슬 2명 생존으로 종료했다. 이 경기의 브라우저 오류 로그는 비어 있었다.

원본 입력 재경기도 20:52에 같은 팀·생존자로 끝났고, 실제 결과 화면에서 **사건 5,704개와 최종 상태가 모두 일치**함을 확인했다. 재경기에서는 첫날 낮·밤과 둘째 날을 페이즈별로 진행한 뒤 자동 진행을 켰다. 둘째 날 낮 308.25초 발동 예정인 Q는 시전자 사망으로, 둘째 날 밤의 시전은 대상 지역 이탈·시전자 지역 이탈로 취소된 상세 기록을 확인했다.

정상 발동은 별도 새 경기에서 Q 이름을 `검증 신속 타격`, 선딜을 0.1초로 편집하고 같은 3레벨 고정 피해 30을 사용해 확인했다. 실제 UI의 둘째 날 낮 전투 상세 기록은 다음 순서였다.

1. `검증 신속 타격: 시전 시작 → 307.1초 발동 예정`.
2. 상대 라온의 기본 공격으로 시전자 HP 101 감소.
3. 라온의 보호막이 피해 7, 전술 초월이 피해 18을 처리.
4. 시전 검사 백로 → 라온의 고정 피해: 원피해 30, 실제 HP 5 감소.
5. 후속 기본 공격으로 시전자 사망.

짧은 시전은 사망 전에 발동했고, 긴 시전의 취소 표본을 성공으로 바꾸어 기록하지 않았다. 별도 정상 발동 표본은 둘째 날 낮 페이즈 완료까지만 확인했으며 전체 경기 완주나 동일 재경기 표본으로 세지 않는다. 이 설정은 검증용 사용자 입력이고 기본 명단의 스킬·밸런스로 채택한 것이 아니다. 정상 발동 표본의 브라우저 오류 로그도 비어 있었다.

검증 전용 탭과 로컬 개발 서버는 확인 후 닫았다. 저장한 검증용 프로필·원본 기록은 해당 로컬 주소의 브라우저 저장소에 남겼으며 기존 사용자 기록을 삭제하지 않았다. 이 표본들은 UI 연결 검사이지 기본 명단의 밸런스·재미 합격 판정이 아니다.
