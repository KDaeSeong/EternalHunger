# 성장 계산 분할과 경기 결과 보존

## 요구와 수정

2026-09-25. 이전 실제 연속 x8 세 번째 경기의 Long Task 234ms 중 `growth.allActors`가 233.2ms였다. 이 실패는 `observer-memory-lifetime-verification.md`에 보존한다. 전원 성장 처리를 대원/계획 단계 사이에서 나누고, 화면이 응답할 기회를 주되 경기 결과는 바꾸지 않는 것이 이번 범위다.

- `runPhaseActorActionPipelineSteps`는 기존 명단·계획 사본·공유 자원·난수 순서를 유지한다. 기존 동기 호출도 같은 구현을 끝까지 실행한다.
- 성장 준비, 개별 계획 갱신, 팀 판단, 개별 행동 뒤에 중단 가능 지점을 둔다. 기본 8ms 예산으로 묶고 브라우저의 다음 화면 처리 기회 뒤 재개한다. 한 대원의 판단 자체를 중단하지 않으므로 **모든 묶음이 8ms 이내라는 보장은 아니다**.
- `advanceToSteps`는 성장 처리가 끝날 때까지 같은 경기 시각을 유지한다. 교전·효과 만료·금지구역 시간·다음 화면 반영이 미완성 성장 처리를 추월하지 않는다. 기존 동기 시간축 사용은 유지한다.
- 동시 시간축 진행과 협력형 시간축의 동기 호출을 거부한다. 실패/취소된 부분 성장 처리는 같은 시간축에서 재시도하지 못하게 하여 공유 자원 이중 소비를 막는다. 실패한 세계 갱신을 완성 프레임으로 표시하지 않는다. 모든 상태를 되돌리는 범용 트랜잭션을 구현한 것은 아니다.
- `growth.slice` 계측은 실제 계산 묶음만 재며 브라우저 대기 시간을 CPU 작업 시간으로 더하지 않는다. 난수는 `runSimulationSteps`의 각 동기 실행 구간에서만 설치한다.
- 규칙·저장 형식·보상·사냥 궁극기 정책·개인 금지구역 시간은 변경하지 않는다. 엔진 지문은 변경되므로 제품의 이전 엔진 재경기 차단을 그대로 유지한다.
