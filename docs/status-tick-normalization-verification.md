# 매초 상태 갱신의 중복 정규화 제거 — 2026-10-09

## 제품 변경과 소유권 경계

현재 cycle은 매초 살아 있는 대원을 `applyActorPhaseStatusTick`으로 갱신한다. 이 함수가 이미 `normalizeRuntimeSurvivor`를 실행한 새 결과를 반환하지만, 곧바로 호출한 금지구역 tick의 진입부가 전체 대원을 다시 정규화하고 결과에서도 한 번 더 정규화했다. 가방·효과·장비·능력치·경로를 반복 순회하는 실제 제품 경로다.

cycle이 만든 `statusActors`만 `normalizedSurvivors: true`로 전달한다. 이 내부 계약의 입력은 현재 호출에서 방금 정규화한 배열이며 호출 뒤 재사용하지 않는다. tick은 마지막 중복 ID 우선/첫 삽입 순서와 빈 ID 필터를 유지한다. 기존 대원 root·cooldowns·각 skillState entry 복사를 그대로 수행하고, 쿨다운·고유 자원·폭발 타이머·HP·구역·사망 메타데이터는 그 복사본에서 갱신한다. 결과 정규화도 유지한다.

일반 호출과 world resolution은 이 계약을 선택하지 않아 기존 진입 정규화를 계속한다. 원본 입력이나 저장 파일에 flag를 추가하지 않는다. 객체 identity를 저장하는 장기 캐시, 무료 재료/장비, 경기 시간·행동 횟수·난수 변경은 없다. 배열이 아닌 임의 입력을 빠른 경로에 전달하는 API는 제공하지 않는다.

## 새 입력 기반 검사

`npm run check:status-tick-normalization`은 실제 status producer와 hazard tick의 기본 경로/빠른 경로를 같은 새 입력·난수로 비교한다. 과거 경기 결과나 진단 artifact를 읽지 않는다. 15개 검사/336회 비교가 통과했다.

다룬 경계는 0초/분수/정수 경과, 정규화 멱등성, 구간 시작 효과의 쿨다운 가속/만료, 고유 자원, 30/45초 개인 상한, 폭발/최종 구역 사망·복귀 자격·순서·로그, CNOT/휴대용 안전지대 비용·난수, 경직의 실제 보호 구간, 틈 공간, 중복/빈 ID, 동결 입력·살아 있는 출력의 수정 가능한 필드 소유권, 동일 원본 수정 뒤 재호출, 일반/world 입력 정규화다. 실제 getter 관측에서 불필요한 진입부 능력치 읽기 3회가 1회로 줄었고 출력은 같았다. 이것은 호출 경계 증거이지 전체 UI 속도 측정이 아니다.

named `status-tick-unit`은 위 검사 외에 타이머 21개·프레임 19개·엔진 지문 4개와 runtime lint를 종료 0으로 마쳤다. 엔진 전후는 `4347d44ee766a2923169b80a5fd95b131fb75718efcbe3ba730b7bc8eb8cb103`으로 같다. 첫 실행은 검사에서 공격력 79.7을 80으로 반올림한다고 잘못 가정해 실패했다. 기존 소수점 규칙에 맞춰 검사 기대값만 고쳤으며 실패 기록도 보존한다.

## 전체 경기 차등 검사

`npm run check:status-tick-normalization:match`는 현재 cycle의 고유한 flag 설정 한 곳만 메모리에서 false로 바꾼 기준 경로와 수정 경로를 별도 Node 프로세스에서 실행한다. 변환 대상이 정확히 한 곳인지 검사하고, 파일은 수정하지 않는다. 두 입력은 현재 제작한 동일 24인 fixture다. 모든 사건/게시 프레임 digest, 최종 프레임, 종료, 로그, RNG 상태를 비교한다. 과거 엔진 또는 과거 저장 결과를 정답으로 사용하지 않는다.

새 경기 2판의 11개 phase, 11,632개 사건, 5,840개 프레임, 최종 상태·종료·로그·RNG가 같았다. 1,124.916666초/6일 아침에 team:1이 실제 교전으로 우승했다. named match 종료 0·디스크 엔진 전후 일치를 확인했다. 기준/수정 하네스 경과 시간은 95,857/89,525ms였으나 단일 Node 진단일 뿐 실제 x32 속도 개선의 합격으로 해석하지 않는다.

현재 엔진 빌드는 종료 0·62페이지, BUILD_ID `Y_-aWsXIQ9-pnGojfjnVN`이다. 실제 서버/클라이언트 청크의 normalizedSurvivors 계약도 확인했다. 검증 대상 소스 6개는 검사·빌드 전후 해시가 같았다. 이번 빌드의 webpack pack 6개·592,288,191바이트만 정리했고, 보호 파일 23개와 완성 빌드 1,429개 파일의 해시는 정리 전후 같다. 원시 진단, 실패/성공 검사 기록, 사용자 변경·다른 프로젝트를 보존했으며 물리 여유 공간 증가는 측정하지 않았다.

## 인정하지 않는 범위

Node 하네스는 프레임 동결·복사·해시 비용을 포함한다. 이 검사나 경과 시간은 실제 전경 x32 속도, 페인트/FPS 또는 연속 경기 메모리의 합격이 아니다. 저장 replay 입력 API, 계정 저장/로드, 유료 AI 품질, 실제 사람의 이해도/재미, 공개 배포도 이번 새 증거에 포함하지 않는다. 추가 허용 없이 전경 경기·유료 AI·계정 쓰기·푸시·배포를 실행하지 않는다.

원래 G1~G5의 요구와 완료 기준은 그대로이며 전체 목표는 활성/미완료다. 출력 전용 근거를 최종 정리한 뒤 `artifacts/status-tick-normalization-20261009.json`에 보관한다.
