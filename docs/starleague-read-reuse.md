# 스타리그 화면 조회 계산 재사용

같은 리그 상태에서 알림이나 탭만 바꾸면 거래 후보·거래 미리보기·경력·자유계약·계약·창고·장비·팀 행동·진행 경기 수·전체 경기 수·점수를 다시 계산하던 화면 경로 11곳을 재사용한다. 실제 팀/선수/대상/현금 변경과 새 리그 상태는 필요한 조회를 갱신한다. 창고·계약만 바뀌고 팀/선수 참조가 유지되는 경우에도 전체 상태 참조가 갱신 조건에 포함된다.

원래 엔진과 데이터·가격·수락 확률·선수 순서·난수·행동·저장 규칙은 바꾸지 않는다. 경제 요약은 구형 로그의 누락 시각을 현재 시각으로 채우는 관찰 가능한 동작이 있어 직접 조회를 유지하고, 실제 플레이 시간도 고정하지 않는다. 전역 객체 캐시는 추가하지 않았다.

## 확인한 범위

- 새 일반 검사 9그룹은 실제 화면 선언과 현재 엔진을 사용한다. 캐시 재사용과 선택 변경, 새 상태의 창고/장비/계약 갱신, 정렬·기본값·입력 불변·난수 보존·실제 거래 수락/거절·경제/플레이 시간의 직접 조회를 확인한다. 비공개 작업 자료 읽기 차단 상태에서도 통과했다.
- 별도 원본 화면 대조는 처음 같은 상태의 반복 조회에서 중복 계산을 재현하고 종료 1이었다. 첫 실패 이후의 그룹 합격으로 해석하지 않는다.
- 독립 원본/수정 화면 투영 8개에서 값과 입력 참조가 같았다. 기본 데이터 10팀·80선수 전체를 사용하며 고정 거래 두 경우의 실제 수락/거절과 결과 전체도 같다. 같은 상태의 알림/탭 변경에서 정규화 호출은 통제 계측상 32회에서 1회로 감소했다. 이 수치는 화면 속도·전체 게임 실행 시간·FPS의 실측치가 아니다.
- 전체 스타리그(기존 중계·피드백·음원과 신규 9그룹), 공통 피드백, 공통 화면, 변경 파일 린트의 네 명령이 종료 0이었다. 최종 빌드 `KHDA69eWzLSLgPKtmxYOc`도 종료 0이며 선언 입력 1,304개는 검사와 빌드 전후 동일하다. 이터널 헝거 엔진 지문 `3102c32c…`는 유지된다. 생산 Worker 검사는 격리된 Node VM이며 브라우저 관전 증거가 아니다.
- 배포 검사 도구는 전체 파일 비교 16건, 원본 함수 모양 15건, 실제 빌드/합성 의존성 그래프 18건을 통과했다. 컴파일러가 순수 조회를 함수 본문으로 합치므로 원본과 변환본의 함수 본문 모양이 같다고 주장하지 않는다. 실제 기본 내보내기 화면 함수에 연결된 전체 32개 메모의 순서·의존성·소유 상태 연결을 확인하고, 공개 파일은 별도 불변 소스/전체 바이트 증거로 판정한다.

## 남는 인수

실제 마운트된 화면·키보드/모바일·브라우저 반응 속도·장기 시즌/밸런스·사람 평가는 별도다. 현재 화면 조작은 Esc 중단 상태를 유지한다. 이 변경이나 공개 파일 일치만으로 EH G1~G5 → 문명 아카이브 → 스무고개 → 스타리그 → 회사의 전체 목표를 완료 처리하지 않는다.
