# 기기에 작성한 재료의 분류와 실제 제작 검증

2026-11-15. 실제 손님 아이템 작성 화면에서 재료로 지정한 `연결 검사 묶음
중간재`가 이름의 `검` 때문에 무기로 추정됐다. 고철 3개와 1Cr로 중간재
2개를 만드는 유효한 조합이 장비 묶음 상한 1개에 막혀 `inventory_full`을
반복했고, 이를 사용하는 직접 지정 장비도 만들지 못했다.

## 수정 범위

기기 프로필(`localItemProfile: true`)의 분류가 `재료` 또는 `material`이고
명시한 장착 부위가 비어 있으면, 이름으로 장비·음식을 추정하기 전에 재료로
취급한다. 명시한 장착 부위는 기존 우선순위를 유지한다. 새 재고 수령과
기존 스택 합치기에서 기기 프로필 표시를 보존하여 정규화·JSON 복원 뒤에도
이름 때문에 분류가 바뀌지 않도록 한다.

프로필을 적용하지 않은 내장 774개 아이템의 기존 분류는 유지한다.
특히 기존 데이터에서 `재료`로 표기된 고기의 음식 추정과 탄창의 장비 추정을
전역 변경하지 않는다. 레시피·비용·재료·묶음 상한·시작 자원과 무작위 규칙을
변경하지 않는다.

## 실제 UI 원본과 원인 확인

별도 headless Edge 손님 화면에서 중간재, 영웅 장비 다섯 부위, 다른 무기군의
영웅 무기, 상위 투구, 복합 소모품 등 9개를 직접 작성했다. 저장·새로고침 뒤
실제 Worker 입력과 보관 원본의 프로필·목표가 같았으며 24명의 15Cr·빈 가방을
유지했다. Worker 입력과 저장소를 검사 코드로 주입하거나 무료 재료·강제 피해·
강제 사용을 추가하지 않았다.

수정 전 원본은 16,035개 사건으로 실제 종료했으며 실제 보관함의 동일
재경기가 사건·최종 상태·난수·종료 판정까지 일치했다. 중간재와 지정 장비는
제작·장착이 모두 0이었다. 목표 대원들은 실제 고철을 확보했지만 조합이
가방 부족으로 막혔다. 중간재 이름만 바꾼 작은 통제 복사본은 같은 재료·
효과·가격·외부 키로 2개 수령에 성공해 이름 추정을 직접 원인으로 구분했다.

소모품은 별도로 93회 유료 제작(물 1개·3Cr 소비, 결과 2개)과 자연 사용
49회를 기록했다. 모든 사용은 독립적으로 관찰한 재고 1개 차감·남은 수량과
일치했고, 양수 회복 사건은 28개였다. 실제 HP 프레임 차액에는 다른 피해와
재생이 섞여 있으므로 이를 회복량과 같다고 해석하지 않는다. 보호막·재생·
능력치의 등록도 실제 흡수·각 지속 효과의 인과 기여와 구분한다.

첫 메뉴 이동 누락, UI의 생략 가능한 0 기본값에 대한 과도한 단언, 효과
사건을 재고 변경으로 센 검사 오류는 제품 오류와 구분했다. 최초 실패
결과·드라이버·입력과 원자료를 보존했으며, 재고 판정은 같은 원자료의 독립
사후 분석으로 바로잡았다. 유리한 시드나 레시피로 다시 선택하지 않았다.

## 회귀와 같은 입력 재검토

`npm run check:authored-material-classification`은 14그룹으로 실제 UI 형태의
프로필, 재료 이름 네 종류와 표기 두 종류, 수령·스택 합치기·정규화·JSON
경계, 실제 유료 중간재→투구/무기→상위 투구 제작·정확 장착, 원자 롤백을
검사한다. 같은 검사는 보존한 원형 두 모듈에서 2/14, 수정본에서 14/14였다.
기존 커스텀 제작 체인과 검증 입력 지문에도 연결했다.

ESLint를 포함한 관련 20명령이 같은 1,623개 입력에서 통과했고, 같은 엔진
`d76d3e99…`의 프로덕션 빌드 `vzPr1i4rEVfatjhAFT-yo` 및 격리된 Node VM
프로덕션 Worker 첫 단계가 통과했다. 이 Worker 검사는 브라우저 실행과
구분한다.

실패했던 실제 UI 입력의 엔진 버전만 현재 버전으로 옮겨 나머지 입력 전체가
동일함을 단언한 통제 전체 경기에서는 일곱 목표 모두 실제 유료 제작·정확
장착됐다. 영웅 목표 여섯 개는 원래 첫밤 기한 250초 안에 완료했고 상위 투구도
실제로 장착했다. 전체 경기는 13,940개 사건과 실제 `last_team`으로 종료했다.
이는 입력을 보존한 현재 런타임 재검토이며 새 공개판의 실제 UI·보관 재경기를
대신하지 않는다. 공개 전달은 커밋·배포 뒤 별도로 판정한다.

원래 고정 편성 비교 실패, 광범위 커스텀·자연 생존/후기 경쟁·전경 배속·
메모리·사람 평가와 다른 게임 인수는 미완료 상태를 유지한다. 스타리그 웹
플레이는 사용자 요청에 따른 종료 상태를 유지한다.
