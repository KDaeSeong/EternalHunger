# 사이트 업적 개편

사이트 전체 업적을 14종에서 47종으로 확장한다. 기존 14종의 ID·조건·업적 점수를 유지하며, 화면을 열거나 새로고침할 때 현재 저장된 기록으로 달성을 확정한다. 이미 확정한 업적은 재화 사용·캐릭터 삭제·전적 삭제로 취소하지 않는다. 이전에 삭제되어 남지 않은 기록이나 저장되지 않은 과거 잔액까지 추정해서 복구하지는 않는다.

| 분야 | 업적 수 | 기준 |
| --- | ---: | --- |
| 헝거게임·이터널 헝거 | 8 | 계정 누적 경기·승리·처치 |
| 문명 아카이브 | 3 | 개발자 보정 없는 기초 완주·전체 발전·3회 완주 정산 |
| 여러 게임 도전 | 19 | 플레이 기록·승리/클리어·서로 다른 게임·게임별 첫 기록 |
| 스무고개 | 5 | 방 생성·정답 기록 |
| 캐릭터와 기록 | 5 | 캐릭터·팀·저장 경기 기록 |
| 특전과 수집 | 5 | LP·크레딧·배지·특전 |
| 커뮤니티 | 2 | 게시글·댓글 |

## 보상

- 업적 점수 1점당 5 LP·10 크레딧을 계정에 지급한다. 점수 자체는 별도 기록용 수치다.
- 예: 10점은 50 LP·100 크레딧, 60점은 300 LP·600 크레딧, 100점은 500 LP·1,000 크레딧이다.
- 전체 1,600점이며 모든 업적의 최초 보상 합계는 8,000 LP·16,000 크레딧이다. 계정당 업적별 한 번만 지급하며 주기적으로 초기화하지 않는다.
- 기존 기록으로 충족한 업적도 받을 수 있다. 문명 아카이브의 기존 런 보상과 업적 보상은 별개다.
- 달성 시점의 점수·보상 금액을 기록한다. 이미 수령한 요청의 재시도에는 기존 지급액과 현재 잔액을 반환한다.

## 데이터와 지급 계약

공통 목록은 `shared/achievementCatalog.cjs`를 사용한다. `AchievementRecord`의 기본키는 계정 ID와 고정 업적 ID의 조합이다. 달성 기록은 최초 생성 값만 저장하고, 보상 수령은 계정 잔액과 같은 MongoDB 트랜잭션 안에서 확정한다. 트랜잭션을 지원하지 않는 연결에서는 별도 잔액 갱신으로 우회하지 않는다.

`GET /api/achievements`는 본인 기록을 계산하고 신규 달성만 보존한다. `POST /api/achievements/claim`은 `{ "achievementIds": ["first_sim"] }` 또는 `{ "all": true }`를 받는다. 계정은 인증 정보에서 결정하며, 요청 본문의 계정·금액·달성 여부를 지급 근거로 사용하지 않는다.

`GET /api/achievements/catalog`는 공개 목록·조건·보상만 제공하며 계정 진행도를 포함하지 않는다. 개인 진행도와 보상 수령은 기존 인증 보호를 유지한다.

마이애니메 기록은 실제 지원 게임의 `GamePlayRecord`를 집계한다. 같은 게임·런 ID를 가진 기존 중복 기록은 최초 기록 한 건으로 계산하고, 런 ID가 없는 기록은 각각의 저장 기록 ID를 사용한다. 문명 아카이브는 별도 정산 원장의 유효한 `basic`·`full` 판정만 사용한다. 일일 지급 한도로 보상이 대기 중이어도 유효한 완주는 포함하며, 개발자 보정·부적격 원장은 제외한다.

계정 전환·로그아웃·세션 변경으로 무효가 된 화면 응답은 진행도나 잔액에 반영하지 않는다. 수령 뒤 더 최신의 계정 정보가 반영되었다면 이전 잔액으로 덮어쓰지 않는다. 손님은 47종의 목록·조건·보상을 미리 보고 분야·상태·검색 필터를 사용할 수 있다.

## 검증

```text
cd server
npm run test:achievements
npm test

cd client
npm run check:site-achievements
npm run build
```

`server/tests/achievements-mongo.integration.js`는 별도로 준비한 빈 로컬 복제 집합 DB에서 실행한다. `ACHIEVEMENT_TEST_MONGO_URI`는 `127.0.0.1`과 `achievement-test-<12자리 16진수>` DB 이름만 허용하며, 기존 데이터가 있으면 시작하지 않는다. 동시 20회 지급, 개별/전체 중첩, 잔액 기록 실패 시 실제 롤백, 소비·삭제 후 달성 보존과 기록 집계를 검증한다. 공개 DB나 실사용 계정 검증을 대체하지 않는다.
