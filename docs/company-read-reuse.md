# 회사 리포트 화면 조회 분리

주문·채권·세금 선택과 납부액을 바꿀 때 회사 전체 요약까지 다시 만들던 화면을 세 계산으로 나눴다. 전체 회사 상태가 바뀌면 17개 상태 조회를 갱신하고, 복원 모드/테이블은 실제 복원 계획만 갱신한다. 선택한 행과 납부액은 현재 조회 행에서 다시 고른다. 알림/탭처럼 기존에도 동일 상태에서 캐시되던 경우를 새 성능 개선으로 집계하지 않는다.

원래 `buildCompanyReportPlayViewModel` 직접 호출은 매번 새 조회를 수행한다. 같은 객체의 장부를 직접 수정하는 기존 호출자도 현재 내용을 읽는다. 전역 객체 캐시, 경제 계수, 신용/이자/만기 정책, 영업 점수, 자산/세금/복원/저장 규칙을 바꾸지 않았다. 실제 플레이 시간도 고정하지 않는다.

## 확인한 범위

- 현재 코드만 읽는 신규 11그룹과 비공개 작업 자료 읽기 차단 실행이 통과했다. 실제 화면 선언과 현재 엔진으로 선택 변경, 복원 계획, 새 외곽 상태/같은 회사 참조, 새 런/불러오기, 빈 목록/잘못된 ID, 구형 자료 정규화, 직접 API의 같은 객체 수정, 시간·입력·난수 보존을 검사했다. 마운트된 React나 브라우저 검사는 아니다.
- 별도 원본 화면 실행은 두 그룹 통과 후 선택 변경의 같은 요약 참조 재사용 검사에서 실패했다. 원본 파일은 교체하지 않았다. 이 RED를 이후 그룹 합격으로 해석하지 않는다.
- 독립 원본/수정 화면·조회 함수와 별도 동일 엔진을 24회 비교해 전체 값·키/직렬화 순서·원본 입력·최근 객체 참조가 같았다. 실제 고정 자료에서 선택 변경의 정규화는 93→0회, 복원 설정은 93→1회였다. 첫 조회/새 상태는 93회로 같고 원래도 재사용하던 알림/탭은 양쪽 모두 0회다. 이는 실제 브라우저 FPS나 전체 경기 시간 측정이 아니다.
- 기존 회사 경제·지급·VAT·환거래·영업일·원금 상환·피드백·저장 경합과 신규 11그룹, 음원, 공통 피드백/화면, 변경 소스 린트의 다섯 명령이 종료 0이었다. 검사 입력 1,306개는 전후 동일하다. 엔진/데이터와 EH 지문 `3102c32c…`는 바꾸지 않았다. 최초 검사 로더 순서 오류는 제품 오류와 구분해 보존한다.

## 남은 인수

생산 빌드 `QG4tCoQLI_-if9JXG3OId`는 종료 0이며 최종 5명령과 선언 입력 1,306개가 같다. 최초 빌드는 생성 폴더 EPERM으로 종료 1이었고, 실패 자료·도구 원본을 보존한 뒤 정확한 해당 경로 생성 확인과 같은 작업 폴더의 명시 재개로 통과했다. 격리된 Node VM Worker 검사는 브라우저 관전 증거가 아니다. 공개 전달은 별도의 현재 소스/전체 파일 증거로 판정한다. 실제 마운트·전경 속도·키보드/모바일·장기 경영/밸런스·사람·자연 만료·독립 계정 검증은 별도다. 물리적 Esc 이후 화면 조작 중단을 유지한다. 개별 최적화나 소스 검사만으로 EH G1~G5 → 문명 아카이브 → 스무고개 → 스타리그 → 회사의 전체 목표를 완료 처리하지 않는다.

공개 확인 도구의 실제 빌드/합성 검사 18건은 전체 메모 순서와 실제 소유 상태·선택 속성·선행 메모 결과의 출처를 연결한다. 최초 입력 이름 교환을 구분하지 못한 검사 실패는 보존했고, 논리 속성 바인딩을 고정한 뒤 18/18을 확인했다. 변환된 함수 본문 모양이 원본과 같거나 실제 화면을 실행했다고 주장하지 않는다.
