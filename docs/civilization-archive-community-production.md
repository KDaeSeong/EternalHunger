# 문명 아카이브 공동체 가공

## 범위와 사용

기존 부족 화면의 직업 배치에 **가공대** 한 직업을 추가했다. 수동으로 배치한 실제 부족원과 지속 저장되는 생산 계획 한 개를 사용한다. 공동체 생산으로 넘어가는 첫 단계이며, 후기 시대의 모든 생산 체계·제도·시간 단위나 전체 개발 목표의 완료를 뜻하지 않는다.

가공대 카드에서 공정과 목표 비축을 선택한 뒤 **설정 적용**으로 함께 저장한다. 해금 전 공정도 미래 계획으로 저장할 수 있지만, 실행에는 정착 연구와 해당 공정 연구가 모두 필요하다. 재료·일손이 없거나 목표에 도달해 멈춘 상태에서도 계획을 수정할 수 있다. AP가 없거나 선택한 행동 대원이 사망했다는 이유로 계획 설정을 막지 않는다. 종료된 런과 기존 소유자·쓰기 권한·저장·불러오기·상점 작업 보호 조건은 적용한다.

가공대의 ± 버튼은 기존 직업 배치 기능을 사용한다. 미배치 인원으로 증원하며 다른 직업의 인원을 쓰려면 기존 배치를 먼저 줄여야 한다. 가공에 배치한 인원은 식량 확보·건설·연구 등에 동시에 투입할 수 없다. 자동 배치 인원은 0이며, 기존 자동 배치가 가공대로 인원을 끌어오지 않는다. **가동 안 함**으로 바꾸거나 생산이 중단되어도 수동 배치한 가공대 인원은 그대로 남는다.

계획은 `tribe.processingPlan = { actionId, targetStock }`로 저장한다. 중지는 빈 공정과 목표 0, 가동 계획은 아래 공정 식별자와 양의 안전한 정수 목표를 사용한다. 목표는 누적 생산량이 아니라 산출품의 실제 비축 개수이다. 입력 중인 초안은 재고·날짜 변경으로 지워지지 않으며, 런이나 저장된 계획이 바뀌면 초기화한다. 오래된 다른 런·변경 전 계획의 제출은 현재 계획을 덮어쓰지 않는다.

## 실제 공정

모든 공정은 `SETTLEMENT`(정착) 연구를 공통으로 요구하며, 기존 개인 운영 행동과 동일한 재료·산출 정의를 사용한다.

| 공정 | 추가 연구 | 1묶음 투입 | 1묶음 산출 |
| --- | --- | --- | --- |
| `kiln` 가마 굽기 | `POTTERY` 토기 | 점토 2, 나무 1 | 토기 2 |
| `weave` 방직 | `CORDAGE` 끈과 밧줄 | 섬유 3 | 직물 1 |
| `smelt` 제련 | `BRONZE_WORKING` 초기 청동 기술 | 금속광 2, 나무 2 | 금속 주괴 1 |
| `forge` 단조 | `EARLY_IRONWORKING` 초기 철제 기술 | 금속 주괴 1, 나무 1 | 금속 공구 1 |
| `mill` 제분 | `WATERMILL` 수차 | 곡물 3 | 제분 곡물 2 |
| `paper` 제지 | `PAPERMAKING` 제지 | 나무 1, 섬유 1 | 종이 2 |
| `preserve` 식량 보존 | `FOOD_STORAGE` 식량 저장 | 고기 2, 수지 1, 베리 1, 약초 1 | 보존식 1 |

가공대 1명당 하루 최대 1묶음을 처리한다. 실제 투입 재료가 있어야 산출하며, 개인 AP·기력(ST)을 소비하거나 개인 행동 횟수(`counters`)·창건자 업적 기록을 추가하지 않는다. 설정만으로 재료를 소비하거나 무료 아이템을 생성하지 않는다. 기존 개인 제작·운영 버튼은 유지한다.

## 전망과 실제 정산

카드의 전망은 **현재 저장된 계획과 현재 비축**을 기준으로 계산한다. 아직 적용하지 않은 입력 초안이나 다음 아침의 생산을 현재 재고처럼 표시하지 않는다.

실제 가공은 다음 아침의 기존 원재료 생산, 사업, 연구, 부족 및 가구 배식이 끝난 뒤 남은 실제 재료로 계산한다. 이번 밤에 다음 아침 산출을 빌려 쓰지 않으며, 앞선 처리에서 자재나 식량이 소비되면 실제 가공량이 현재 전망과 달라질 수 있다.

필요 묶음 수는 `(목표 비축 - 현재 비축) / 묶음 산출량`을 올림하여 계산한 뒤 실제 일손·재료·안전한 재고 한도로 제한한다. 예를 들어 토기 비축 0개, 목표 3개, 가공대 2명과 충분한 재료라면 2묶음으로 4개를 생산하고 멈춘다. 이후 비축이 목표 아래로 줄면 다음 정산 때 다시 생산할 수 있다.

현재 상태와 실제 정산 기록에는 연구 부족, 일손 없음, 목표 도달, 재료 부족, 하루 일손 한도, 재고 수량 확인 불가 또는 안전한 수량 한도 등 해당 이유를 표시한다. 재료·인원이 일부만 가능하면 가능한 묶음만 생산하고 제한 이유를 남긴다.

## 실제 기록과 저장 호환

실제 가공 기록은 기존 부족 장부의 **직전 정산 실제 가공**에 표시한다. 저장 위치는 `tribe.lastProduction.processing`이며 기본 필드는 다음 9개다. [제작 전승 예약](civilization-archive-processing-tradition.md)을 적용한 기록에는 기존 선택 필드 `bonusBatches`도 포함한다.

### 2026-11-11 공동 식량 비축

기존 개인 식량 보존 공정을 가공대 계획에서도 선택할 수 있도록 연결했다. 개인 행동과 공동체 생산은 같은 투입·산출 정의를 공유한다. 개인 보존 버튼의 비용·성공 처리·로그·행동 횟수·공로·난수 순서는 기존 전용 분기를 그대로 사용한다.

공동 보존은 정착·식량 저장 연구와 실제 가공대 일손을 요구하며, 배식 후 남은 재료로 목표 비축까지 생산한다. 가공대 인원이 식량 확보·건설·연구에도 동시에 기여하지 않는다. 설정만으로 식량이 지급되지 않으며, 이번 밤의 허기 피해를 다음 아침 보존식으로 먼저 막지 않는다. 기존 제작 전승을 예약한 경우에도 기본 생산이 있어야 하고 추가 한 묶음의 재료를 전액 지불한다.

기존 저장의 계획을 자동으로 보존식 생산으로 바꾸거나 과거 생산 이력을 만들지 않는다. 새 보존 기간·부패·영양·가격·생산율이나 자동 배치 정책을 추가한 작업은 아니다. 원래 후기 운영의 공동 비축 선택을 현재 가공 체계로 연결한 범위이며, 전체 생산망·상호부조 제도의 완성을 뜻하지 않는다.

새 집중 검사 `check-primitive-archive-processing-preserve.mjs`는 최초 옵션 부재의 RED 종료 1을 보존한 뒤 10그룹을 통과했다. 실제 개인 비용과 산출, 연구 해금, 일손·목표·재료 한도, 배식 우선, 선소비 전승의 실제 추가분·만료, JSON·체크포인트 복원과 기존 6공정의 중립성을 다룬다. 기존 가공·화면·전승·저장 관련 6명령과 검사 파일 린트도 종료 0이다. 로컬 집중 근거는 `.local/code-audit/processing-preserve-*.log`이며, 전체 검사·빌드·공개 전달과 실제 브라우저·사람 인수는 별도로 판정한다.

같은 최종 소스의 전체 `check:primitive-archive`, 공통 피드백·화면 검사와 변경 파일 린트도 실제 종료 0이다. 배포용 빌드 `j11B4RtvJfuw-XOhnjZZ_`도 종료 0이며 선언 소스 1,258개와 이터널 헝거 엔진 `e8e8b934…`가 유지됐다. 모듈 검사 23조건과 격리된 Node VM Worker의 새 경기 첫 단계 완료 1회도 통과했다. 근거는 `.local/code-audit/archive-preserve-checks-result.json`·`archive-preserve-build-result.json`이다. Worker 검사를 실제 브라우저·전경 성능·사람 인수로 표시하지 않는다.

정산 일자는 상위 `lastProduction.day`를 사용한다. 기록은 당시 계획·실제 배치·처리 묶음·투입·산출·중단 이유를 나타낸다. 이후 계획·인원·재고가 바뀌어도 직전 기록을 현재 전망으로 다시 만들지 않는다. 가동 계획을 다음에 실제 정산할 때 새 기록을 남기며, 중지 계획의 가공 영수증은 만들어 넣지 않는다.

기존 비축의 소수 수량은 관찰값으로 보존한다. 예를 들어 `0.3`은 그대로 `0.3개`로 표시한다. 목표·인원·묶음·실제 투입 및 산출은 정수이다. 산출품의 수량을 유효하게 관찰할 수 없으면 현재 전망은 `null`을 **확인 불가**로 표시하고 0묶음으로 중단한다. 이 경우 실제 기록의 `stockBefore`와 `stockAfter`도 모두 `null`이며 투입·산출은 비어 있다. 관찰 실패를 이유로 원래 재고를 0이나 다른 값으로 고쳐 쓰지 않는다.

이전 저장에 새 계획·가공대 필드가 없으면 중지 계획과 0명으로 취급한다. 이전 실제 생산 기록에 가공 기록이 없으면 **이전 가공 정산 미기록**으로 표시한다. 과거 기록에 새 가공 결과를 소급하여 채우지 않는다. 새 필드를 명시한 경우에는 정확한 필드 구성, 지원 공정, 정수 목표·인원·투입·산출, 관찰 가능한 비축 또는 허용된 양쪽 `null` 기록을 엄격하게 검증한다. 잘못된 새 구조를 조용히 초기값으로 바꾸지 않는다.
