2026-09-20. **진행 중이며 제품 지원은 아직 미완료다.** 커스텀 제작 수량/비용 수정과 별도로 효과 편집→저장→획득→사용→관전→보관/재경기를 연결한다. 파열 등 장비 발동 효과와 후반 성장 요구도 여전히 유지한다.

### 최종 배포용 빌드의 저장 복원·재경기

- 같은 엔진의 프로덕션 서버 `127.0.0.1:3106`에서 개발 서버 때 보관한 시드 `2026092007` 원본을 실제 보관함으로 불러왔다. 원본 x32와 달리 x16·4팀 관전으로 재경기했다. **21:12·7일차 낮·4팀/다온**으로 끝났고, 결과 화면에서 **원본과 사건 7,840개·최종 상태·종료 판정 모두 일치**를 확인했다. 이는 위 모델 7,547사건과 다른 제품 편성 표본이다.
- 재경기 뒤 새로고침하고 검증 탭을 닫은 뒤, 새 탭의 보관함에도 `2026092007` 원본(4팀·21:12·오후 9:45:55)은 정확히 1건이었다. 이전 엔진의 `2026092006`(2팀·21:11)도 보존됐으며 규칙 변경 안내와 함께 동일 재경기 버튼만 비활성화됐다. 기록 삭제나 입력 데이터 직접 주입은 하지 않았다.
- 새 탭에서 `내 아이템 편집` → `제작 검증 회복약 편집`으로 돌아가 물 1개·3Cr·결과 2개, 회복 25·보호막 20·재생 2·공격력 +5·3.5초의 복원을 확인했다. 편집창 스크린샷에서 효과·제작 필드가 읽히며 관리자 전용 필드는 숨겨져 있었다. 테스트 주소에만 저장한 2개 기기 아이템은 보존했다.
- 로컬 프로덕션 제품 경로의 증거이며 실제 계정/MongoDB 저장, 공개 새 버전, 장시간 성능 또는 사람의 평가를 대신하지 않는다.

### 실제 기기 편집 화면 확인 — 개발 서버, 최신 엔진

분리된 로컬 `127.0.0.1:3106`의 실제 제품 화면에서 `제작 검증 회복약`을 **새로 생성**했다. 기준 평가/계정/내장 원본은 수정하지 않았다.

- 결과 수량 `1.5`를 저장하면 정수 입력 안내가 나오며 창과 입력이 유지된다. 수량을 `2`로 고친 뒤 재료 없이 저장하는 경우도 실제 조합식을 요구하며 거부했다.
- 물 1개 + 3Cr → 2개, 회복 25·보호막 20·초당 재생 2·공격력 +5·지속 3.5초로 저장했다. 새로고침 뒤 다시 열어 실제 수치와 재료/비용/수량을 확인했다.
- 최종 화면은 관리자 잠금/DB 식별자/효과와 무관한 장착 능력치·등급 코드·계정 가격·미적용 개별 묶음 수량을 노출하지 않는다. 가방 묶음 한도는 선택 경기 규칙을 따른다는 안내가 있으며 기존 메타데이터는 보존한다.
- 이 화면에서 돌아가 시드 `2026092007`·24인·x32 경기를 실제 시작했다. 5일차 낮 로그에서 솔빛/이슬/다온의 `제작 검증 회복약` 사용, 실제 체력 +25와 남은 수량 1/0/0을 관측했다. 이후 **21:12·7일차 낮·4팀 2/3명 생존**으로 교전 종료했으며 결과의 `시작 조건과 전체 사건을 경기 보관함에 저장했습니다.` 안내를 확인했다. 이후 배포 빌드의 원본 로드·x16 재경기 증거는 위 별도 절을 따른다.
- 여기까지는 개발 서버에서의 제품 UI 증거다. 최종 프로덕션 빌드, 공개 배포와 인간 평가 결과로 확대하지 않는다.

### 전체 검사에서 발견한 성장 회귀와 수정

붕대의 원본 분류는 `소모품`이며 장비 조합 재료로도 쓰인다. 명시 분류를 우선하도록 고친 뒤, 성장 파밍 후보가 `material/equipment`만 허용해 붕대를 계속 찾지 못했다. 안전한 24인 훈련에서 **18/24 완료**로 실패했다. 이는 일반 소모품 사용 또는 전투 사망 탓이 아니었다.

필요한 조합 재료로 지정된 소모품도 집중 파밍 후보가 되도록 연결했다. 지역/재고/요청 ID/단계 제한을 유지하며, 아이템 분류를 재료로 속이거나 무료 장비를 지급하지 않는다. 새 직접 회귀는 수정 전 획득 실패를 재현했고 수정 후 실제 소모품 획득→재료 소비→장착, 재고 소진 후 획득 거부를 통과했다. 같은 훈련의 결과는 **24/24**, 제작 357건, 이동 195건, 완료 340–520초이며 성장 집중 검사는 **17/17**이다. 이 안전 훈련을 실제 경쟁 경기의 장비 완성률로 해석하지 않는다.

### 편집·획득·사용 연결의 범위

- `/eternalhunger/items`에서 로그인 없이 새 아이템/내장 아이템의 기기 전용 수정을 저장한다. 기본 평가 경기는 개인 수정물을 읽지 않으며, 보관된 재경기는 저장 당시 카탈로그를 사용한다. 기기 저장 한도/오류/잘못된 참조·순환 조합식은 기존 데이터를 보존한다.
- 사용 시 HP/수량/자발 행동 가능 여부를 검사하고 실제 효과가 생긴 경우에만 수량·같은 페이즈 제한·사건을 한 번 확정한다. 보호막은 교전 시 사용하며 더 강한 기존 효과를 약한 약으로 덮어쓰지 않는다. 효과 적용 뒤 콜백 실패/JSON 복원 재시도도 중복 소비를 막는다.
- 보호막/초당 재생/일시 능력치는 실제 초 단위 상태 효과이며, 3.5초 만료 검사에서 기본 능력치를 영구 변경하지 않았다. 획득/스택은 효과를 깊게 복사하며 같은 ID라도 효과가 다른 재고를 합치지 않는다. 관전/기록에는 실제 회복량·포만감·지속 효과·남은 수량을 보존한다.
- 제작 편집은 소수 수량/빈 재료/잘못된 비용을 임의 반올림하거나 삭제해 저장하지 않는다. 새 기기 아이템에는 실제 조합식이 필요하다. 소모품 기기 편집에서는 무관한 관리자 잠금·DB 식별자·장착 능력치를 숨겼다. 새 편집 화면의 시각 확인은 빌드 후 별도로 수행한다.

## 수정 전 실제 실패

제작 수정 엔진 `f711832bab1d755d648273c4f7ae5c16178f119bd3dc70d990029ac05ddd92c3`과 수정 전 서버 모델에서 `client/scripts/check-custom-consumables.mjs`를 실행했다. 실제 스키마·가방·효과·자동/강제 사용 함수를 호출하며 DB/계정에는 쓰지 않는다. 사망/잘못된 HP/보유 수량을 서로 독립된 검사로 나눈 결과 **2/21 통과, 19개 검사 실패**, 종료 1이다. 이 검사는 미구현 요구를 실행 가능한 형태로 고정한 것이며 아직 배포용 전체 검사에 포함하지 않았다.

- 명시한 `consumeEffect`가 아이템 스키마와 가방 획득에서 유실된다.
- 한글 `소모품`과 일반 이름의 회복약이 자동 회복 대상으로 인식되지 않는다.
- 명시한 0 또는 미지원 효과라도 이름이 음식이면 기존 음식 효과가 대신 적용된다.
- 강제 사용 경로에서 사망자 회복, 잘못된 보유 수량 소비, 행동 불가 상태의 사용을 재현했다. 자동 사용의 사망자 회복을 관측한 것으로 확대하지 않는다.
- 최대 체력/포만감에서도 회복 전용 아이템이 소비되고, 같은 페이즈 사용 제한 검사는 명시적 회복약을 사용하지 못하는 선행 문제에서 실패한다.
- 커스텀 보호막·재생·일시 능력치의 명시적 적용이 없다.
- 소수점 가방 인덱스 거부와 효과 계약이 없는 기존 사과의 회복 16·포만감 24는 통과했다.

## 단일 효과 계약 구현

원본은 `server/utils/consumeEffectContract.js`의 부작용 없는 공통 규칙이다. 클라이언트 ES 모듈은 `client/scripts/generate-consume-effect-contract.mjs`로 이 원본에서 기계적으로 생성하고 `--check`로 오래된 생성물을 거부한다. 두 실행 환경에서 규칙을 따로 작성하지 않는다. 제작 버전 전체 회귀가 종료 0으로 끝날 때까지 클라이언트 원본을 고정해 두었고, 클라이언트 생성물은 아직 생성/연결하지 않았다. 다음 실행에서 생성·실제 사용·편집기 연결을 진행한다.

| 필드 | 계약 |
| --- | --- |
| `version` | 1. 생략한 명시적 기존 회복량은 v1으로 정규화 |
| `heal`, `satiety` | 즉시 회복량·포만감 증가. 0 이상의 정수, 포만감은 최대 100 |

| `durationSec` | 보호막·재생·일시 능력치의 지속 시간. 실제 지속 효과가 있으면 필수, 0초 초과·86,400초 이하, 소수점 보존 |
| `stats` | 공격력·방어력·스킬 증폭·공격 속도·치명타 확률·이동 속도·기본 공격 사거리·시야의 비음수 일시 증가량. 실제 런타임 표준 키 사용 |

효과 생략/null은 기존 판정을 유지하는 명시적 미설정이다. 빈 효과 객체, 미지원 버전/필드/능력치, 잘못된 수치는 실패로 반환하고 음식 이름 기반 효과로 대체하지 않는다. 양의 실제 효과가 하나 이상 있어야 한다. 위 수치는 원작 아이템 수치가 아니라 이 시뮬레이터의 커스텀 입력 계약이다.

`server/tests/consume-effect-contract.test.js`는 정규화·원본 불변·깊은 복사·JSON 복원·잘못된 값/버전/필드·지속 시간·기존 미설정을 **7/7 통과**했다. 실제 음식/회복 수치를 이 계약으로 자동 변환하지 않는다.

## 서버 모델·쓰기 경계 연결 — 미배포 작업

- `server/models/Item.js`에 전체 효과 객체의 정규화/검증을 연결했다. 유효한 수치를 보존하며, 잘못된 버전·필드·수치가 조용히 없어지는 대신 검증 실패가 된다. null로 기존 명시 효과를 지우는 것과 필드를 생략해 기존 값을 유지하는 것을 구별한다.
