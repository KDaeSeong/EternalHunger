## 구현

- 경기 시작 시 실제 참가자 24명 이하의 능력치·가방·장비·팀·루트·적용된 특전, 초기 월드와 카운터, 지도, 아이템/키오스크/드론 카탈로그, 설정, 적용된 규칙, 시드를 JSON 소유 데이터로 복사한다. 원본 경기부터 이 복사본으로 계산한다.
- 브라우저의 규칙 변경값, 지도 상자 금지 목록, 변이 야생동물 출현 지역은 시작 시 한 번 해석한다. 경기 중 늦게 도착한 초기 자료나 계정 특전 갱신은 참가자 상태를 바꾸지 않는다.
- 지도와 경기 설정은 시작 후 고정한다. 동일 재경기에서는 편성 변경/개발자 도구를 잠근다. 수동 조작이 표시된 원본은 동일 재경기 보관 대상에서 제외한다.
- 화면용 사건 5,000개 제한과 별개로 전체 사건을 동기적으로 누적한다. 마지막 페이즈와 `match_end`까지 종료 처리에서 읽는다. 전투 로그 내보내기도 전체 사건을 사용한다.
- IndexedDB `eh_simulation_replays_v1`에 최근 10경기를 보관한다. 시작 입력, 전체 사건, 최종 프레임, 최종 난수 상태가 포함된다. 새 기록 저장과 오래된 재경기 기록 정리는 한 트랜잭션이다. 기존 `eh_sim_run_history_v1` 요약 저장 형식과 20개 제한은 변경하지 않는다.
- 결과창에서 바로 다시 실행하거나, 경기 보관함에서 기록을 읽어 새로운 경기 세션을 만든다. 새 세션은 계정/카탈로그 재로딩과 초기 로스터 재추첨을 건너뛴다.
- 동일 재경기는 명예의 전당·승수·LP·계정 서버 결과·생성 장비 저장을 추가 실행하지 않는다. 종료 시 사건 순서와 내용, 최종 전체 프레임, 난수 상태를 원본과 비교한다. 진단용 실제 시각 `ts`는 비교에서 제외한다.
- 계산/공유 코드의 SHA-256 버전을 빌드 시 생성한다. 버전이 다른 기록은 동일 재경기 버튼을 비활성화하고 이유를 표시한다. 기존 시드/참가자 요약만 가진 기록은 완전한 입력으로 승격하지 않는다.
- 보관 실패를 성공으로 표시하지 않는다. 현재 탭의 완주 자료가 남아 있으면 그 경기의 즉시 재실행은 가능하다. `QuotaExceededError`·다른 탭 차단·브라우저 미지원은 별도로 분류해 원인별 안내를 표시하며, 결과창에서 같은 완주 기록의 보관을 다시 시도할 수 있다.
- 보관함의 각 기록은 `기록 삭제`→`삭제 확인`의 명시적 두 단계로 삭제한다. 삭제 transaction의 `complete` 뒤에만 목록에서 제거하고, 실패/abort 때는 기존 목록과 자료를 유지한다. 엔진이 달라 동일 재경기를 할 수 없는 기록도 삭제할 수 있으며 연결된 5분 평가 기록은 별도 보존한다.
