# 편성·전략 변경 경기와 결과 비교

기준일: 2026-09-12. G5.2의 제품 조작 경로와 비교 판정 계약을 기록한다.

## 목적

완료한 경기를 그대로 재현하는 G5.1과 달리, G5.2는 보관된 시작 조건을 복사한 뒤 참가자 편성·전술·무기·스킬·능력치·지도·규칙·시드를 바꾸어 **새 경기**를 만드는 흐름이다. 두 경기의 입력과 실제 결과를 함께 제시하되 한 경기의 상관관계를 인과관계로 과장하지 않는다. 게스트 로컬 경기는 로그인 없이 이 기능을 사용한다.

## 제품 흐름

1. 경기 결과 화면 또는 경기 보관함에서 `편성·전략 바꿔 새 경기` / `조건 복사·변경`을 선택한다.
2. 보관된 참가자·초기 월드·지도·규칙·시드를 별도 초안으로 복제한다. 원본 저장 기록은 수정하지 않는다.
3. 동일 재경기 잠금을 적용하지 않으므로 시작 전 편성·전술과 허용된 경기 조건을 편집할 수 있다.
4. 시작하면 재경기가 아닌 새로운 경기 입력을 확정하고, 완주 시 별도 기록으로 저장한다. 기존 기록의 승리·보상 중복 차단 규칙을 새 경기에는 잘못 적용하지 않는다.
5. 경기 보관함에서 서로 다른 두 기록을 `비교 기준`과 `비교 대상`으로 골라 조건 및 결과 차이를 읽는다. 진행 중 경기에는 기록 교체와 비교 선택을 막는다.

## 비교 계약

시작 조건은 다음을 구분한다.

- 난수 시드, 지도 ID와 세부 지역 규칙, 경기 설정
- 팀 수의 요약과 참가자 추가·제외·팀 이동
- 참가자별 이름, 전술 스킬, 무기, 역할, 특성, 목표 장비, Q/W/E/R 구성과 레벨, 기본 능력치, 목표 장비 구성
- 팀 편성 요약은 참가자별 변화와 같은 사실을 두 번 센 것으로 취급하지 않는다.
- 객체형 설정과 구성은 `기준 세부값 → 변경 세부값`, `기준 구성 → 변경 구성`으로 양쪽을 구별한다. 같은 이름의 지도에서 세부 규칙만 바뀐 경우도 숨기지 않는다.

결과는 저장된 최종 프레임과 의미 사건에서 다음을 읽는다.

- 우승 팀, 경기 시간, 최종 생존자와 탈락자, 총 킬
- 제작·사냥 결산, 팀 교전·팀원 공격·팀 공격 피해, 열세 후퇴
- 공유 자원 획득·고갈 재계획, 차원의 틈 승리

판정 문구는 다음 경계를 지킨다.

- 시드가 다르면 결과 차이를 편성·전략만의 영향으로 단정하지 않는다.
- 시드와 기록된 시작 조건이 모두 같은데 결과가 다르면 전략 효과가 아니라 재현 불일치로 다룬다.
- 같은 시드에서 한 조건만 바뀐 경우에도 한 경기로 인과를 확정하지 않는다.
- 여러 조건이 함께 바뀌면 어느 변경이 결과를 만들었는지 분리할 수 없다고 표시한다.

## 소스 범위

- 세션 분기와 새 경기 초안: `client/src/app/simulation/page.js`, `_lib/useSimulationPageController.js`, `_lib/useSimulationInitialData.js`
- 보관함·결과 화면 조작: `_components/SimulationReplayHistory.js`, `_components/SimulationResultModal.js`
- 비교 계산: `_lib/simulationRunComparisonRuntime.js`
- 화면 스타일: `client/src/styles/ERSimulation.css`

비교 계산은 화면 상태를 변경하지 않으며, 보관된 전체 기록을 IndexedDB에서 읽는다. 시작 조건이 없는 예전 요약 기록이나 불완전한 기록으로 비교 결과를 만들어 내지 않는다.

## 자동 검사 증거

2026-09-12 최신 검사에서 직접 비교 **15/15**와 seed **8/8**이 종료 코드 0으로 통과했다. 같은 최신 소스의 런타임 sweep과 프로덕션 빌드도 종료 코드 0이다.

2026-09-11 당시 `npm run check:run-comparison`의 직접 비교 검사 11개가 종료 코드 0으로 통과했다. 이 명령은 이어서 쿨다운 13개, 고유 자원 12개, 사용자 스킬 이동 12개도 실행하며 모두 통과했다. 이 수치는 당시 기록으로 보존한다.

1. 같은 기록은 전략 효과가 아니라 재현 근거로 분류
2. 팀·전술·무기·능력치·참가자 변화의 실험체 귀속과 편성 이중 집계 방지
3. 지도·객체형 설정·시드 차이의 명시와 거짓 통제 비교 차단
4. 최종 프레임·의미 사건 기반 결과 지표 및 큰 변화 요약
5. 같은 시드의 한 조건 변경과 여러 조건 변경 구분
6. 전술만 편집할 때 편집기가 만든 비활성 스킬·빈 레벨·비활성 자원 기본값을 거짓 변경으로 세지 않음
7. 시작/최종 근거가 없는 기록의 비교 거부
8. 이전 엔진과 사건·난수·종료 판정이 빠진 손상 기록의 비교 거부
9. 최종 명단이 같아도 서로 다른 명시적 종료 판정을 비교 화면에 표시
10. 종료 시각·일차·승자·틈 정산 메타데이터만 다를 때 동일한 종료 판정을 거짓 변경으로 강조하지 않음
11. 소수 경기 시간과 일반 단위 표시

같은 최신 소스에서 런타임 sweep과 60개 경로 프로덕션 빌드도 종료 코드 0으로 통과했다. 자동 검사는 비교 계산의 기능·거부 계약 증거이며, 가독성·재경기 의향은 별도 판정이다.

## 2026-09-12 최신 실제 브라우저 증거

로그인 없이 사용자 지도·규칙을 저장하고 새로고침한 뒤 두 경기의 시작 snapshot과 보관 기록을 비교했다.

- 시드 `1789163312032`: 7팀 우승, 초롱 1명 생존.
- 시드 `1789163583099`: 6팀 우승, 새벽 3명 생존.
- 비교 화면의 warning은 조건 차이를 표시했고, metrics에는 우승 팀·생존자·경기 결과가 분리되어 나타났다. 동일 재경기는 저장된 snapshot과 exact하게 일치했으며 원본 기록은 변경되지 않았다.
- 사용자 지도 geometry/topology와 규칙 patch는 새로고침 뒤에도 유지됐다. 이 제품 표본은 인과·재미·균형의 최종 증거가 아니다.
- 좁은 화면을 포함한 반응형 비교 브라우저 게이트도 완료했다. 이는 배치·가독성 확인의 증거이며, 더 넓은 조합의 인과 해석이나 G5.3 재미 평가를 대신하지 않는다.

## 2026-09-11 역사적 실제 브라우저 증거

엔진 `221ff911b0bc9dec86cae417530a8c231d0823a6857e54f74a3c605209d713b8`의 프로덕션 빌드에서 로그인 없이 다음 제품 경로를 실행했다.

- 시드 `1788542576577`의 붉은 폭풍 기준 경기: 3팀 우승, 20:52.25, 3명 생존.
- 기준 기록을 `편성·전략 바꿔 새 경기`로 복사한 뒤 하늘의 전술만 블링크로 변경: 6팀 우승, 21:16.75, 1명 생존. 경기 기록에는 하늘의 실제 블링크 이탈 사건이 남았다.
- 보관함 비교는 `바뀐 시작 조건 (1)`과 `하늘 · 전술 스킬 붉은 폭풍 → 블링크`만 표시했다. 비활성 캐릭터 스킬 껍데기와 빈 레벨 맵은 더 이상 변경으로 나타나지 않았다.
- 두 경기의 종료 표시는 모두 `마지막 팀 생존 · 교전`이었고, 큰 변화 목록에는 종료 판정 변경 문구가 나타나지 않았다. 승리 팀·경기 시간·생존자·킬·제작·사냥·피해·후퇴·자원 차이는 별도 지표로 표시됐다.
- 원본과 변경 기록은 별도 항목으로 남았고 이전 엔진 기록은 실행 불가 이유와 함께 비활성화됐다. 콘솔 경고·오류는 0건이었다.
- 시험 뒤 하늘의 기기 전술 설정은 붉은 폭풍으로 복원했다.

이 한 쌍은 시작 조건 귀속과 화면 정직성의 제품 증거다. 블링크가 승패 차이를 만들었다는 인과나 재미·균형을 증명하지 않는다.

## 남은 완료 증거

- 더 넓은 편성·시드 조합의 비교 문구·수치·종료 판정을 실제 제품에서 확인
- 반응형 비교 브라우저 게이트는 완료했다. 긴 이름·구성의 더 넓은 조합 가독성은 위 항목에서 별도로 확인한다
- 물리 IndexedDB quota 한계와 전체 x1/x8/x32 브라우저 성능을 확인
- G5.3 경험자의 실제 이해·재경기 의향·재미 평가

이 검증이 끝나기 전까지 G5.2와 전체 목표는 완료로 판정하지 않는다.
