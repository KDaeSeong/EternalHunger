# 진행 중 관전 상태 동기화 검증

기준일: 2026-09-05. G4.1의 위치·체력·장비·사망·부활·시계 표시 작업.

## 원인과 수정

- 이전에는 시계가 행동 처리보다 먼저 갱신되고, 사망자는 별도로 추가되며, 생존자·장비·월드 상태는 페이즈 종료 때 전달됐다. 부활 로그가 나와도 생존/사망 합계가 참가자 수와 맞지 않는 구간이 생겼다.
- `simulationFrameRuntime.js`에서 시계, 날짜, 생존자, 사망자, 장비/가방, 킬/어시스트, 월드, 금지구역을 독립 복사한 한 묶음으로 만든다. React는 하나의 reducer action으로 그 묶음을 반영한다.
- 경기 실행기는 입력 참가자의 복사본으로 계산한다. 초 단위 시간 경과와 해당 시점의 행동 처리가 끝난 뒤 화면을 갱신하고, 그 다음 배속에 맞춰 기다린다. 행동 불가·이동 중·부활 대기 중에도 시간이 흘렀다면 상태를 전달한다.
- 부활자는 같은 묶음에서 사망자 목록에서 제외된다. 이전 시신보다 새 사망 정보가 우선하지만, 사망 기록의 원래 순서는 보존한다. 이 순서를 바꾸면 난수를 사용하는 부활 처리 결과가 달라질 수 있다.
- 마지막 팀이 결정된 바로 그 시각의 상태를 먼저 전달하고 결과를 기록한다. 표시를 위해 추가 시간을 흘려보내지 않는다.
- 진행 중에도 미니맵·캐릭터·로그 같은 읽기 전용 관전창을 열 수 있다. 기존 경기 변경 제한은 유지한다.
- 브라우저에서 발견한 가방의 고정 `3`칸 표기를 실제 규칙의 용량으로 수정했다. 기본 규칙은 10칸이며 같은 아이템 묶음은 한 칸으로 표시한다. 용량이나 획득 규칙 자체를 바꾸지는 않았다.

- 마지막 가방 검사는 공유 규칙 함수의 기본/변경 용량과 UI 연결을 검사하는 소스 기반 검사다. 실제 렌더링 증거와 구분한다.
- 종료 통제 검사 `node scripts/check-endgame.mjs`: 13/13 통과.

`check-action-timeline.mjs`는 각 경기의 매 상태 전달마다 다음을 검사한다.

- 생존자와 사망자의 합집합이 최초 24명과 일치하고, 서로 중복되지 않는다.
- 사망자는 HP 0이며, 사망/부활 이벤트 이후의 인원 상태가 해당 이벤트와 일치한다.
- 시계가 역행하지 않고 미래 이벤트를 표시하지 않으며, 표시 대기 횟수는 실제 경기 경과 초와 일치한다.
- 전달했던 참가자·시신·월드 객체를 동결한 채 다음 페이즈를 실행한다. 이전 화면 상태를 실행기가 바꾸면 실패한다.
- 기존 재료 보존, 이동 경로/시간, 중복 행동/제작/타격, 사망 후 재행동, 비로그인 API 의존 검사를 유지한다.

- 새 경기의 첫 페이즈 종료 02:20에도 24명/0명, 가방 6/10·4/10·3/10 등 실제 렌더링을 스크린샷으로 확인했다. 최종 빌드 브라우저 경고/오류 없음. 검증용으로 시작한 로컬 서버는 종료했다.
