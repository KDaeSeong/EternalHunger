# 스무고개 방 응답의 정규화 재사용

변경된 방 조회와 접속 확인 응답은 버전 비교 전에 한 번 정규화한 뒤, 같은 응답을 화면에 반영하면서 다시 정규화했다. `applyRoomResponse`의 내부 세 번째 인수로 이미 검사한 방 객체를 전달해 두 번째 처리를 없앴다. 객체 형태로 정규화 여부를 추정하거나 전역 캐시를 만들지 않는다.

## 보존하는 동작

- 변경된 조회·접속 확인은 정규화 1회, 같은 버전 또는 다른 방 응답은 1회 후 반영하지 않는다.
- 폐기·언마운트·다른 방·계정·세션·새 요청으로 대체된 응답은 기존 보호 검사에서 막고 정규화하지 않는다.
- 직접 불러오기와 질문·답변·정답 도전·힌트·종료는 원시 응답을 각각 한 번 정규화하는 기존 경로를 유지한다.
- 요청 유효성 검사 위치와 횟수, 버전 비교, 참조와 상태 반영, 원격 알림, 입력창·캐시·오류·요청 정리의 순서를 유지한다.
- 질문·정답 도전·힌트 배열은 원래 응답의 참조를 유지한다. 참가자 식별자·이름은 실제 정규화 함수로 처리하며, 조회가 검사한 객체를 그대로 반영한다.

실제 화면은 내부 API가 Axios의 JSON 파싱과 서버의 JSON 응답으로 전달한 데이터를 사용한다. 이 변경은 그 경계에서 같은 응답의 중복 처리를 줄인다. 임의 getter나 Proxy를 가진 객체의 반복 접근 횟수까지 기존과 같다고 주장하지 않는다.

## 검증

기존 비동기 경쟁 검사 14그룹을 유지하고 6그룹을 추가했다. 실제 제품 선언과 효과를 추출해 실제 정규화 함수의 실행 횟수·정확한 반환 객체·반영 후 알림 순서를 관찰한다. 동결한 `room`·`data`·직접 객체 응답, 옛 응답 거부, 원시 응답 여섯 경로, 비공개 필드의 단독 변경과 실제 원격 알림 우선순위를 검사한다. 제어한 훅과 지연 API를 사용하는 검사이며 실제 React 마운트나 브라우저 검증은 아니다.

현재 소스의 20그룹이 통과했고, 사설 입력 읽기를 차단한 실행의 읽기 시도는 0이다. 별도의 명시적 원본 소스 실행에서는 정규화가 2회인 두 그룹이 실패하고 나머지 18그룹은 통과했다. 일반 검사는 사설 원본이나 과거 결과를 읽지 않는다.

전체 스무고개 묶음·인증·격리된 서버 경합·공통 피드백·공통 화면·변경 소스 린트와 최종 빌드 `jNplUZZ6EJ1kON-25axRY`가 종료 0이다. 선언 소스 1,305개는 검사·빌드 전후 같다. 빌드의 격리된 Node VM 작업자 첫 구간도 통과했고 이터널 헝거 엔진 버전은 `3102c32c…`로 유지된다. 공개 전달은 실제 방 페이지와 연결된 전체 컴파일 파일의 해시·반영 구조를 별도로 대조한다.

독립적으로 로그인한 두 참여자의 실제 화면, 사람 평가와 자연 로그인 만료 관문은 남아 있다. 물리적 Esc로 중단된 화면 조작을 재개하지 않았으며 원래 G1~G5와 다른 게임의 전체 목표를 완료로 승계하지 않는다.
