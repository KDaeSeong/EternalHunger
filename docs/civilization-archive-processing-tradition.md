# 제작·건설 전승의 공동체 투자 선택

## 목적과 범위

초대 캐릭터의 실제 업적에서 이어진 제작·건설 가르침 또는 가호를 공동 건설과 가공 생산 중 어디에 투자할지 선택한다. 기존 생존·후계·신앙·프로젝트와 가공 생산을 재사용하며, 별도 재화나 영구 보너스를 추가하지 않는다.

## 동작 계약

- 기존 의례로 확보한 당일 제작·건설 사용권에서 예약 시 정확히 1회를 소비한다. 개인 제작도 같은 잔여 횟수를 사용한다. 프로젝트와 가공 예약은 하루 한 건, 동일한 예약 칸과 일차 한도를 공유한다.
- 가공 예약 대상은 이미 적용된 공정과 목표 재고다. 입력 중인 생산 계획 초안을 자동 적용하지 않는다. 예약은 AP·ST·시간을 소비하지 않지만 현재 활동 가능한 생존 대원과 남은 AP 1 이상이 필요하다.
- 효과는 바로 다음 아침의 실제 가공에 완전한 묶음 최대 1회 추가다. 실제 가공 일손과 기본 생산 최소 1묶음이 있어야 하며, 기본 생산 뒤에도 목표 재고 여유와 추가 묶음의 전체 재료가 남아 있어야 한다.
- 기존 밤 생존, 공동체 생산·건설·연구와 배식 순서는 유지한다. 가공과 추가 가공은 그 뒤 남은 실제 재료로 수행한다. 기존 건설 정산은 가공 예약을 먼저 만료시키지 않는다.
- 공정·목표 변경, 잠금, 일손·재료 부족, 기본 생산 없음, 목표 도달 또는 예정일 경과는 실제 아침 정산의 사유와 추가 생산 0을 남긴다. 런이 종료되어 아침 정산 자체가 실행되지 않으면 예약도 실행하지 않으며, 없는 정산 영수증을 만들지 않는다. 사용권을 재소비하거나 다른 대상으로 옮기고 환급·이월하지 않는다.
- 가공 영수증은 실제 일손, 기본 생산과 전승 추가분, 실제 재료·산출을 구분한다. 창건자별 전승 기여에는 실제 추가 생산만 집계하며 개인의 과거 행동 공로를 늘리지 않는다. 시조 3명×공정 5종으로 장부를 제한한다.
- 기존 프로젝트 예약·정산·기여·완성일과 구형 가공 영수증을 보존한다. 새 가공 기여는 실제 적용한 뒤에만 기록하고, 옛 저장에 공로를 소급 생성하지 않는다. 기존의 유효한 소수 재고도 유지한다.
- 손상된 새 기록은 정규화 전에 거절한다. 읽기·불러오기가 손상 원문이나 기존 정상 저장을 덮어쓰지 않으며 현재/직전 런과 소유자 분리를 유지한다.

## 검증 기준

공유 예약 한도·정확히 한 번 소비, 기본/추가 생산의 전액 재료 소비, 무효 예약의 무소비, 실제 아침의 적용·만료·중복 호출, 변경된 대상·자원·일손, 소수·비정상·안전 한도 수량, 과거 기록 불변과 실제 추가 기여만의 누적을 검증한다. 체크포인트에는 구형 저장과 새 예약·적용·만료의 왕복, 현재/직전 런, 손상 원문 보존을 포함한다. 화면에는 기존 저장·불러오기·소유자·상점·종료 보호와 오래된 콜백 차단을 적용한다.

## 확인 결과와 남은 인수 항목

새 엔진 13그룹·체크포인트 13그룹·화면 연결 12그룹과 기존 문명 아카이브 전체 검사 체인, 변경된 제품·검사기 10파일의 린트를 통과했다. 통합 검사와 린트 전후 소스 1,224개의 해시와 이터널 헝거 엔진 지문도 같았다. 가공→건설→가공의 여러 날 예약·완성·매 단계 복원, 가능한 분산 기여, 소수 재고, 원문 보존과 실제 정산의 출처를 확인했다. 가공 예약 안내는 기본 닫힌 펼침 영역에 두고 공유 예약 현황을 제목에 표시한다.

제품 빌드 `LcZnjP8DPmn8NuOrM1Q_U`와 제품 워커의 새 첫 단계 실행 검사도 통과했다. 빌드 전후 소스 1,224개와 이터널 헝거 엔진 지문은 같았다. 워커 검사는 독립 Node VM에서 실행하며 실제 브라우저나 관전 성능을 입증하지 않는다. 공개 정적 전달은 해당 커밋의 배포 뒤 별도로 확인한다.

실제 브라우저의 좁은 화면·키보드·저장 생애주기와 사람의 수용 검증은 위 자동 검사로 입증되지 않는다. 본 기능이 추가되어도 원래 G1~G5, 엄격 전경 관전 성능, 자연 로그인 만료 복귀와 후속 사람 평가는 완료되지 않는다.
