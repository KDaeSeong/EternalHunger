# 상태 보호·지속 시간 저항의 실제 전투 연결

기준일: 2026-09-05. G2.3의 면역/저항 단계이며 전체 목표 완료가 아니다. 사용자 제공 상태 분류를 기준으로 하되, 자료에 없는 합성·시간 경계 규칙은 아래에 프로젝트 규칙으로 명시한다. 원작 최신판의 구현이나 모든 실험체 스킬을 확인했다는 뜻이 아니다.

후속 단계: 공포·매혹·도발의 행동 연결과 최신 검증은 `forced-control-verification.md` 참조. 아래 수치는 면역 단계의 역사적 증거이며 이후 엔진의 최종 통과로 재사용하지 않는다.

## 적용 규칙

| 구분 | 실제 처리 |
| --- | --- |
| 이동 방해 면역 | 제공된 목록인 공포·기절·넉백·도발·둔화·매혹·속박·에어본·제압·춤의 새 적용 차단. 침묵·실명·일반 디버프까지 무조건 차단하지 않는다. |
| 모든 방해 면역 | CC의 새 적용 차단. 중독·치유 감소·후속 피해 표식 같은 비-CC 해로운 효과 및 직접 피해는 별개다. |
| 해로운 효과 면역 | CC와 `negative`/`debuff`로 명시한 해로운 효과의 새 적용 차단. 직접 피해에 대한 무적은 아니다. |
| 저지 불가 | 새 CC를 삭제하지 않고 보관하되 행동 제한·능력치·이동 판정에서 일시적으로 무시한다. 보호 종료 때 CC 시간이 남았으면 그 잔여 시간만 작동하고, 먼저 만료했다면 되살리지 않는다. |
| 해로운 효과 제거 | 즉시 해로운 효과를 제거하는 동작. 무시 중인 CC와 비-CC 표식도 제거하며, 보호막·재생·보호 상태는 보존한다. 제거 동작 자체를 지속 버프로 저장하거나 미래 면역을 주지 않는다. |
| 방해 효과 저항 | `ccDurationReduction`, 0.1 = 10%. 새 CC의 지속 시간을 감소시킨다. 넉백·붙잡힘·에어본·제압은 제외한다. 기존 `statusResists`의 확률 판정과 다른 능력치다. |
| 둔화 지속 시간 감소 | `slowDurationReduction`, 0.1 = 10%. 이동 속도 감소의 시간만 줄이고 둔화 강도를 줄이지 않는다. |

프로젝트 시간 규칙:

- 보호를 얻기 전에 이미 붙은 효과는 보호 중 무시하지만 시간은 계속 흐른다. 보호가 끝날 때 남아 있으면 재개한다. 영구 삭제는 제거 동작의 역할이다. 보호 버프를 받는 것이 곧 정화라고 간주하지 않는다.
- 두 감소치가 함께 적용되는 둔화는 `원래 시간 × (1 - 방해 효과 저항) × (1 - 둔화 지속 시간 감소)`를 사용한다. 두 감소치의 원작 중첩 공식을 확인한 것은 아니다. 각 합산 능력치는 0~1로 제한한다.
- 입력 능력치·패시브·활성 능력치 효과와 실제 장착품을 반영한다. 명시적으로 장착하지 않은 예비 장비는 포함하지 않는다. 패시브 편집에 두 입력란을 추가했으며 게스트 프로필 저장/복원 후 실제 상태 적용에 반영된다.
- 지속 시간 감소는 새 적용 시 한 번만 계산한다. 갱신은 이전 남은 시간과 새 감소 시간의 최대값을 사용하고, 이전 시간을 다시 줄이지 않는다. 감소 결과가 0이면 적용하지 않는다. 지속 시간이 없는 효과에는 임의의 만료 시각을 만들지 않는다.
- 무시된 효과도 원본 상태 목록에는 남는다. 추가 효과 적용·보호막 피해·저장/복원·경과 처리에서 유실되지 않는다. 현재 행동 가능 여부를 읽는 함수만 유효 효과를 사용한다.
- 모든 유한 상태의 만료 시점을 전투 일정에 넣어, 보호가 소수점 시각에 끝날 때 시전 취소가 다음 정수 초까지 지연되지 않는다. 이동 적분도 보호 종료/CC 종료 경계를 나눠 처리한다.
- 실제 적용 시간, 감소 전후 시간, 차단한 면역 종류, 저지 불가에 의한 무시, 제거한 상태를 사건 및 설명에 남긴다. 상태 배지에는 무시 중이라는 문구를 표시한다.

## 실패 재현과 수정

1. `모든 방해 면역` 중 기절 적용 결과가 `true`인 실패를 실제 상태 적용 함수로 재현했다. 이름만 표시하던 면역을 그룹 차단에 연결하여 수정했다.
2. 저지 불가가 100.375초에 끝나는데 이미 시전 중인 기술의 침묵 취소는 101초에 기록되는 실패를 재현했다. 상태 만료 일정 추가 후 정확히 100.375초에 취소된다.
3. 저지 불가 1초·속박 3초 상태에서 4초 이동을 한 번에 처리하면 x=18, 0.25초씩 처리하면 x=11로 달라지는 실패를 재현했다. 무시된 속박까지 보존하고 구간마다 재평가하여 양쪽 모두 x=11이 된다(시작 x=4, 이동 속도 3.5m/s).
4. 상태 묶음의 적용 결과가 감소 전 입력 효과로 덮어써지는 경로와, 사건의 시간이 항상 0이 될 수 있는 필드 선택을 수정했다. 실제 적용 시간과 감소 전후 근거를 보존한다.
5. 실제 생존자 카드의 브라우저 검사에서 시간 제한 없는 `모든 방해 면역`이 `0s`로 표시되는 오류를 확인했다. 표시 함수가 `null`을 숫자 0으로 바꾸던 것이 원인이었으며, 실패하는 회귀 검사를 추가한 뒤 시간 표시를 생략하도록 수정했다. 실제 면역의 지속 시간·행동 규칙을 변경한 것은 아니다.

## 실제 화면 확인

- `scripts/preview-status-protection.mjs`는 별도 로컬 포트에 실제 전투 실행기의 프레임을 실제 `SimulationSurvivorBoard`와 실제 스타일로 표시하는 통제 검사다. 제품 경로를 추가하거나 실행기/컴포넌트를 모형으로 바꾸지 않는다. 일반 24인 경기 완주 증거와 구분한다.
- 브라우저에서 100초의 `기절 4s · 저지 불가로 무시 중`, 102초의 `기절 2s`(무시 문구 제거), 104초의 기절 배지 제거를 확인했다. 영구 면역의 `0s` 오류를 수정하고 새로고침하여 남은 시간이 표시되지 않는 것도 확인했다.
- 현재 빌드의 실제 `/eternalhunger` 편집 화면에서 기존 검사 슬롯의 Q를 유지한 채 이름 `면역 검사 여울`, 패시브 `지속 시간 저항 검사`, 방해 효과 저항 `0.3`·둔화 지속 시간 감소 `0.4`를 저장했다. 새로고침 후 편집 화면에서 같은 값·패시브 활성·기존 Q가 복원됨을 확인했다. 기존 과거 경기 기록은 삭제하지 않았다.
- 이 편집을 포함한 현재 빌드의 24인 브라우저 원본은 시드 `1788577799198`, 20:52.92에 교전으로 종료했고 5팀의 새벽·라온 2명 생존(22명 사망), LP 0으로 기록을 저장했다. 새로고침 뒤 보관함에서 과거 두 기록과 새 원본을 확인했다. 과거 기록은 보존하되 엔진 불일치 재경기를 차단한다.
- 새 원본을 불러와 배속 x32→x16 및 관전 1팀→5팀으로 바꾼 재경기도 20:52.92에 같은 생존자로 끝났다. 화면에서 **사건 6,358개·최종 상태 모두 일치**, LP 0을 확인했다. 다시 연 보관함은 과거 두 기록과 새 원본의 총 3개 그대로여서 재경기 중복 저장이 없었다. 브라우저에서 수집한 경고·오류 목록은 빈 배열이었다. 이는 기능/재현성 증거이며 저항의 밸런스·재미 합격이나 모든 CC가 이 경기에서 발생했다는 뜻이 아니다.

## 남은 범위

- 새 패시브 입력란·저장/복원, 실제 상태 배지와 면역 단계 빌드의 브라우저 원본/재경기를 확인했다. 표시 수정 뒤 전체 회귀도 완료했다. 다음 강제 행동 단계의 구현·검증 상태는 후속 문서로 구분한다.
- 면역 분류에 공포·도발·매혹·수면·변이·제압 등이 포함된 것은 그 상태의 강제 보행·표적 강제·피격 해제·개별 이동기 중단을 모두 구현했다는 뜻이 아니다. 해당 행동, 경직/목걸이 정지, 시야 상태는 계속 남아 있다.
- 사용자 정의 Q/W/E/R에서 임의의 상태 부여·보호·정화를 직접 편집하는 경로는 아직 없다. 두 패시브 저항 입력은 실제 적용되지만, 이름만 바꾼 스킬이 자동으로 면역을 부여하지 않는다.
- 원작 개별 기술의 지연 피해 표식/발동 로직은 별도다. 현재 보호는 명시된 상태 레코드를 판정하며, 존재하지 않는 실험체 스킬 구현을 대신하지 않는다.
- 전술/무기 효과의 레거시 지속 시간 단위·실제 원작 수치, 고유 자원·쿨다운 종류, 나머지 특수 피해·회복 경로는 별도 감사가 필요하다. 전술 검사에서는 현재 생성된 둔화 시간이 대상 저항으로 줄어드는 것을 검증했으며, 생성된 원시간 자체를 원작 수치라고 인증하지 않았다.
- G1~G3 지급 감사·파밍/합류/생존 균형, G5.2 편성·전략 비교, G5.3 실제 사용자의 이해/재미 평가는 미완료다.
