## 재현과 수정

- 이전 보관함은 닫아도 비교 기준/대상의 전체 입력·사건·최종 상태를 React state에 보관했다. 컴포넌트 이벤트 처리기를 실행한 검사에서 닫은 뒤 5,000사건 시험 기록이 남아 `true !== false`로 실패했다. 수정 전 실제 브라우저도 선택→닫기→재열기에서 같은 비교 선택을 유지했다. 이는 불필요한 보유의 증거이며 무제한 누수나 기존 heap 증가의 유일한 원인이라고 주장하지 않는다.
- `node --expose-gc scripts/check-replay-history-lifetime.mjs --baseline`은 수정 전 `944637a7`의 컴포넌트를 읽어 같은 실패를 재현한다. HEAD가 바뀌어도 기준을 바꾸지 않으며 작업 파일을 되돌리거나 덮어쓰지 않는다.
- 닫을 때 비교 기록과 목록을 해제한다. 저장된 경기/평가와 작은 평가 초안은 유지한다. 저장 실패로 아직 기기에 기록되지 않은 평가 수정도 닫기 때문에 사라지지 않도록 했다. 비교 선택이 해제됨을 보관함에 안내한다.
- 목록·재경기·조건 복사·비교·삭제 후 UI 반영에 요청 세대 번호를 사용한다. 닫기/이탈로 무효화된 읽기가 늦게 끝나도 자료를 다시 붙이거나 뒤늦게 새 경기를 열지 않는다. 이전 요청의 finally가 새 요청의 대기 상태를 해제할 수도 없다. 이미 명시적으로 시작한 저장소 삭제를 되돌리는 기능은 아니며 이번 브라우저 검증에서는 삭제하지 않는다.
- 저장 실패한 완주 기록을 평가 목록에 넣을 때에도 전체 사건 대신 메타데이터 사본만 넣는다.

## 회수 진단의 한계

`?perfProbe=1`에서만 세션과 보관함의 대표 객체를 WeakRef로 추적한다. 최대 12개 화면 수명·각 8개 객체로 제한하고 초과 관측은 `evictedOwners`로 명시한다. 전체 사건·텍스트 로그·화면 사건 목록·생존/탈락 배열·현재 원본 및 비교 기록을 대상으로 하며 화면에는 종류·순번·회수 여부만 표시한다. 전송/영구 저장/강제 GC는 하지 않는다. 일반 사용자 화면에는 나오지 않는다.

`collected`는 **그 객체**가 실제 회수됐음을 뜻한다. `reachable_or_not_yet_collected`는 아직 살아 있거나 GC가 처리하지 않은 상태이며 누수 확정이 아니다. 재경기 원본은 다음 세션이 같은 기록을 사용하므로 살아 있는 것이 정상일 수 있다. 전체 heap·모든 closure·DOM·음원 등의 무누수 판정은 아니다. 회수 시점은 구현에 달려 있으므로 게임 동작이나 합격 조건을 GC의 특정 시각에 의존시키지 않는다. [MDN WeakRef 설명](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakRef)을 따른다.
