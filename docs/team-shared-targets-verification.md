# 준비된 팀의 안전한 공동 목표 재시도

2026-11-15. 준비된 동료들이 같은 구역에 모여 있어도 첫 공동 목표만 검사했다.
그 목적지의 경로가 위험하면 뒤의 안전한 후보를 확인하지 않고 팀 계획을
버렸고, 실제 개인 이동은 다시 위험한 첫 목표로 향했다. 같은 실제 목표
선택기의 후보 순서만 바꾸면 안전한 공동 이동이 성립하는 것으로 재현했다.

후보 순서를 유지하면서 실제 원천의 현재 가용성과 모든 구성원의 기존
안전 경로를 확인하고, 처음 사용할 수 있는 공동 목표를 선택한다. 선택한
구역에서 실제 오브젝트를 다시 연결하므로 안전한 구역으로 이동하면서 이전
위험 구역의 원천 ID를 보관하지 않는다. 명시한 원천 ID와 수혜자 제약도
유지하며, 재진입할 수 없는 차원의 틈 등 구성원별 제한을 확인한다.

확인된 구체적 원천은 연구 재료·합류지와 같은 유한 지도 전체에서 찾는다.
일반 주변 탐색은 기존 깊이 제한을 유지한다. 모든 후보가 막히면 기존
`path_blocked` 대기로 연결하여 개인 목표 기억이나 위험한 무작위 이동으로
돌아가지 않는다. 적이 없는 곳의 탐색 깊이 제한을 적의 위협으로 표시하지
않고 기존 `replanned` 사유로 구분한다. 준비도·명단·지도·전장 구분과
기존 탈출·회복·확정 행동의 우선순위, 실제 비용·재고는 유지한다.

## 실제 계획과 행동 검증

`npm run check:team-shared-safe-targets`는 실제 팀 계획→개인 이동 및
예약된 단일 행동을 16그룹으로 검증한다. 위험한 첫 후보 뒤의 안전 대안,
구역별 정확한 원천 ID, 명시 원천 제한, 전원 대기, 구성원별 자격, 먼
구체적 원천과 일반 탐색 제한, 준비·사망·지도·전장·전력·종료 경계를 포함한다.
이전 `f0538057` 모듈은 4/16, 현재 소스는 16/16이며, 별도 원본 모듈
로딩 실행에서도 같은 실패를 확인했다. 제품 파일을 되돌리지는 않았다.

초기 검사에는 다른 적 팀의 정상 이동 계획까지 전체 크기로 세었던 계수
오류가 있었다. 대상 동료들의 계획·실제 대기·비용·재고 단언을 유지하면서
대상 팀만 확인하도록 수정했고, 최초 실패 로그도 보존했다. 이후 별도
검토에서 발견한 무위협 깊이 제한의 잘못된 원인 표시도 RED/GREEN으로 고쳤다.

## 전투 검사 도우미의 날짜·단계 전달

전투 도우미가 요청받은 날짜·단계를 실제 전투 상태와 사건 시각에 일관되게
전달하도록 수정했다. 후퇴 검사는 둘째 날 밤 이동 뒤의 전투에도 그 단계를
명시한다. 기본 첫날 아침, 초 시각·HP·ETA·프레임·난수 동작은 유지한다.

`npm run check:combat-scenario-clock`의 실제 전투 3그룹은 원본 1/3에서
현재 3/3으로 바뀌었다. 100·101초의 실제 공격과 HP, 사건 날짜·단계 및 실제
밤 전투 설정을 검사하므로 사건 라벨만 고치는 구현도 거절한다. 날짜를 뺀
기존 작은 재현의 사건·프레임·최종 인물·난수 지문은 이전과 같았다.

두 새 검사와 전투 도우미는 기존 검사 체인과 검증 소스 지문에 연결했다.
관련 팀·합류·지원·후퇴·공간·시전·회복·조달·관측·지문·린트 25명령이 같은
1,622개 소스에서 통과했다. 같은 입력과 엔진 `493c9be3…`를 유지한
프로덕션 빌드 `oEnDDhee90-jgKDq-vkuN`와 빌드 Worker 첫 단계도 통과했다.
