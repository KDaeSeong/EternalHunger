# 팀 공격 피해와 후처리 HP 변화 분리

2026-11-15. `team_strike.damage`를 공격 시작 전과 모든 후처리가 끝난 뒤의 HP
차이로 계산하면 숙련 성장 회복은 팀 피해에서 빠지고, 다른 지역으로 도주한 뒤
받은 추격 피해는 원래 지역의 팀 피해에 더해질 수 있었다.

현재 엔진의 새 고정 조건 3개를 먼저 선언하고 각각 두 번 실행했다. 72명의
초기 목표가 첫밤 종료 기한 안에 완료됐고, 전원 합류 시도 68건 중 62건이
완료됐으며 6건은 동료 사망으로 끝났다. 일반 제작 1,307건은 실제 카탈로그의
재료·결과 수량·비용과 일치했다. 세 경기 모두 마지막 팀 생존으로 자연 종료했고
각 재경기의 전체 사건·프레임·최종 상태·로그·난수가 일치했다.

양의 팀 공격 225건 중 7건이 피해 사건 합계와 달랐다. 다섯 건은 타격 뒤
HP와 최대 HP의 증가, 두 건은 도주·추격 중의 추가 HP 5 감소가 원인이었다.
예를 들어 일반 타격 70과 무기 추가 타격 4 이후 숙련 성장으로 HP가 4 회복되면
팀 공격이 70으로 기록됐다. 다른 지역에서 추격 피해 5까지 받은 경우 실제
기본 공격 115가 원래 팀 교전의 피해 120으로 기록됐다.

`resolveCombatWinnerOutcome`은 기존 전투 피해 계산 결과를 `damageDealt`로 반환한다.
팀 교전은 이 값을 사용한다. 실제 HP 전후를 진단하는 값은 기존 순변화 기준을
유지한다. 기존 호출자가 피해 메타데이터를 반환하지 않을 때의 HP 차이 계약도
유지한다.

검증:

- 수정 전 실제 교전·숙련 성장 회귀에서 피해 18을 14로 기록하는 실패를 재현했다.
- 성장 회복·다른 지역의 추격·명시적 피해 0·기존 호출자 계약을 포함해 팀 전투 16개가 통과했다.
- 팀 전투 전체 묶음, 편성·전술 비교 묶음, 변경 파일 정적 검사가 통과했다.
- 같은 세 조건을 수정본에서 각각 두 번 실행했다. 수정 전후의 모든 프레임 지문,
  저장된 최종 상태·로그·난수·종료는 같고 사건은 `team_strike.damage`만 달랐다.
  변경된 값은 같은 공격자·대상·시각·교전의 기존 `battle.damage`와 일치했다.
- 새 엔진의 세 조건 재경기도 모두 일치했다. 처음 비교 도구가 살아 있는 객체의
  `undefined` 속성과 JSON 기록을 혼동한 실패는 보존했고, 이미 끝난 수정본 1경기를
  재사용해 나머지 5회만 실행했다.
- 수정된 사건은 A 2건·B 4건·C 3건이며, 위의 실제 귀속 차이 7건 외 두 건은
  HP 뺄셈의 부동소수점 잔차였다. 다른 사건 필드와 모든 경기 결과는 같았다.
- 전체 프로덕션 빌드와 실제 빌드 Worker의 첫 단계 검사가 통과했다.
  빌드 ID는 `M4V2k-BQQlUxX8pHDB18j`이며 검사 전후 소스와 엔진 지문이 같았다.
  공개판의 실제 UI 원본 경기·보관함 동일 재경기는 배포 후 별도 검증한다.
