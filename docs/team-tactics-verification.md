# Eternal Hunger 팀 판단 1단계 검증

검증일: 2026-09-04 · 범위: 로컬 개발본의 스쿼드 판단·이동·회피

## 완료한 변화

초반 개별 파밍은 유지하고, 이후에는 팀이 합류하고 공동 목표를 따라 이동하도록 연결했사와요. 회복·금지구역 탈출·전력 열세 후퇴가 합류보다 우선한답니다.

- 같은 지역의 살아 있는 아군과 적군 전력을 함께 평가. 1 대 3과 3 대 1을 같은 개인 대결처럼 취급하지 않음.
- 안전 지역 선택에서 아군을 위험 인원으로 세지 않으며, 위험도가 같다면 아군이 있는 곳을 우선.
- 목적지뿐 아니라 도중 지역의 위험과 금지구역을 확인. 경로가 없을 때 목적지로 바로 이동하던 대체 처리 제거.
- 모든 팀원이 같은 행동 전 스냅샷으로 합류 지점을 결정. 흩어졌을 때 합류, 모였을 때 대표 팀원의 공통 목표 사용.
- 회피 대상과 지원 스킬의 아군 목록은 현재 살아 있는 참가자 기준으로 조회. 이미 행동한 아군을 지원 대상에서 빠뜨리던 순서 의존성 보완.
- 이동·팀 판단 이벤트에 인원·전력·이유·목표를 기록. 결과 화면에는 실제 이동과 대기를 분리해 표시.
- 공통 경로의 중간 지점에 도착한 것을 오브젝트 도착으로 처리하지 않도록 보호.

이는 의사결정용 위험 지표이며 실제 승률 공식은 아니랍니다. 피해량·HP·장비 수치에 팀 보너스를 추가하거나, 교전 자체를 완전한 3 대 3 전투 엔진으로 교체한 작업은 아니랍니다.

## 검증

`client`에서 최신 `npm run check:team-tactics`: **29/29 통과**.

검사 범위: 수적 열세/아군 우세, 사망·원거리·중복 상태 제외, 아군 엄호 선택, 위험한 중간 경로 차단, 금지구역, 초반 루트/솔로 보존, 합류 기준 일치, 입력 순서 독립성·입력 보존, 공동 이동, 실제 이동·회피 함수 연결, 저체력 우선, 오브젝트 도착 판정, 퇴각 직후 왕복 방지, 종료 로테이션 우선순위, 실제 이동과 대기를 구분하는 결과 집계랍니다. 최신 성능 회귀는 밤 사냥 조건의 비리더에게 유효한 팀 계획이 있으면 버려질 개인 목표·TTL 선택을 실행하지 않고, 계획이 없을 때에는 개인 목표 선택이 유지되는지 난수 소비 차이로 검출한답니다. 기존 개인 목표 메모리 제거와 팀 목표 종류·세부 종류·경쟁 압력의 반환값·이동 사건·목표 도착 상태도 함께 확인했사와요.

기존 `npm run check:eternal-hunger` 전체 검사도 1차 수정본에서 통과했사와요. 이후 추가한 도착 판정·집계 보완은 위 20개 검사와 `npm run check:runtime:full`(런타임 린트 + 프로덕션 빌드)로 다시 확인했사와요. 새 검사는 앞으로 전체 검사 명령에도 포함된답니다.

## 최종 빌드 실제 경기

프로덕션 빌드를 다시 열어 게스트 24명·8팀, 32배속 자동 경기로 확인했사와요. 개발자 도구로 경기 상태를 바꾸지 않았답니다.

| 관측 항목 | 최종 결과 화면 |
| --- | --- |
| 협동 판단이 기록된 팀 | 8팀 |
| 합류 이동 / 대기 | 11회 / 20회 |

횟수는 **참가자별 행동 기준**이므로 팀 전체가 함께 이동하면 여러 건으로 집계된답니다. ‘협동 판단 8팀’은 모든 팀이 합류를 완수했다는 뜻이 아니랍니다. 실제 이동·대기 집계는 별도로 확인했사와요.

[최종 화면 관측 기록](C:/2저장고/EternalHunger/artifacts/team-tactics-verification/final-ui-observation.txt)을 남겼사와요. 이번 브라우저 세션에서는 JSON 다운로드 파일을 확보하지 못했고 페이지 파일 내보내기도 지원되지 않았으므로, 전체 원시 경기 로그를 별도로 재감사한 결과라고 주장하지 않겠사와요.

## 남아 있는 핵심 문제

1. **성장과 교전의 실행 빈도**: 현재 단계 구조는 참가자별 이동·파밍 행동 묶음 이후 남은 시간 동안 PvP 행동을 반복한답니다. 다음 단계는 이 빈도를 측정하고, 파밍·제작·교전이 같은 시간 흐름에서 반복되도록 정리하는 것이랍니다. 근거: `simulationPhaseCycleRuntime.js`, `phasePvpActionLoopRuntime.js`.
2. **특수 재료의 별도 즉시 장비화 경로**: 이번 화면에서도 운석·생명의 나무를 통한 즉시 전설 장비 제작 로그가 관측됐사와요. 일반 레시피와 별개인 `gearImmediateSpecialCraftRuntime.js`가 남아 있으므로, 모든 장비가 정규 레시피만으로 만들어진다고 할 수는 없답니다. 일반 초반/후반 무료 보정 차단과 구분해야 한답니다.
3. **재미·밸런스 판정**: 후퇴 76회가 적절한지, 팀 대기가 지나치게 보수적인지, 서든데스 의존이 높은지는 여러 시드의 비교 검증이 필요하답니다. 이번 두 번의 화면 완주(중간본 1회·최종본 1회)를 장기 밸런스 합격으로 계산하지 않겠사와요.

기존 사이트 기능·계정 연동·원작 최신 패치 재현·전체 3 대 3 전투 재작성은 이번 범위 밖이랍니다.
