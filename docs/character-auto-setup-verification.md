# 캐릭터 자동 설정 · 2026-10-05 로컬 구현

상태: **편집기·자료 읽기·검증 계약 구현, 실제 AI 생성 품질과 공개 배포는 미확인**. 전체 게임 목표의 완료 판정이 아니다.

## 구현 범위

계정 캐릭터 목록의 `자동 설정`에서 ER 실험체 또는 커스텀 캐릭터를 선택한다. 이름만 입력하거나 설정·스킬 설명을 한 번에 붙여넣으면 능력치·무기·Q/W/E/R/패시브·고유 자원의 초안을 요청한다. 미리보기와 추정/미지원 안내를 읽은 뒤 적용하며, 서버 반영은 기존 `지금 저장`을 별도로 눌러야 한다.

기본 적용은 이미 작성한 이름·능력치·무기·스킬·고유 자원을 유지한다. 비활성 상태의 이름/설명/수치가 있는 작성 중 스킬도 보호한다. 기존 작성 항목 교체는 별도 체크가 필요하다. ID·이미지·전적·아이템·장비 목표·경기 상태는 AI 초안에 포함하지 않는다. 적용할 스킬과 유지할 자원이 맞지 않으면 전체 패치를 거부한다. 요청 실패·취소·닫은 뒤 늦은 응답은 기존 캐릭터를 바꾸지 않는다.

ER 이름만 입력한 요청은 공식 홈페이지의 [캐릭터 DB 안내](https://playeternalreturn.com/posts/news/1280?hl=ko-KR)가 연결하는 네이버 게임 DB를 고정된 공개 API로 읽는다. 정확한 한글 이름 하나에만 대응하고 Q/W/E/R/T 설명, 능력치 항목 및 무기를 가져온다. AI가 원작 스킬 이름이나 무기 종류를 새로 지으면 초안을 거부한다. 최신 패치와 일치한다고 보장하지 않는다. 폼 전환·적중 시 발동 패시브 등 현재 엔진이 지원하지 않는 효과를 영구 능력치로 지어내지 않고 비활성/생략 안내 대상으로 둔다. 원작 수치를 이 시뮬레이션에 맞추는 생성 품질은 실제 AI 검증이 필요하다.

자료의 URL을 사용자나 AI가 정하지 못하게 하고 자동 리디렉션도 금지했다. 이름 목록만 15분 동안 메모리에 보관하며 DB·대용량 결과 파일로 수집하지 않는다. Google Search 도구는 호출하지 않는다. 붙여넣은 ER 설명에는 자동으로 공식 검증했다는 표시를 붙이지 않는다.

API는 기존 인증 경로 안의 `POST /api/analyze/character-setup`이다. 기존 AI 분석과 사용자별 `ai:analyze` 제한을 공유한다. 기존 `/api/analyze`와 게스트 경기·게스트 프로필 저장은 그대로 유지한다. 이번 자동 설정 UI는 계정 편집기에 연결했으며 익명 AI 서비스나 게스트용 자동 설정을 구현했다고 주장하지 않는다.

## 저장 중 발견한 결함

`compactCharactersForSave()`가 명시적인 `hpDamagePercentUnit: 'percent'`를 빼는 결함을 수정했다. `0.2%`가 저장/재편집 뒤 `20%`로 재해석될 수 있던 경로다. 명시 단위를 가진 값에만 표시를 보존하며 단위 없는 과거 분수 데이터의 의미는 변경하지 않는다. 요청 형식 `{ characters, deletedIds }`, 서버 소유 전적, LP·권한·사용자 표시명 계약은 유지한다.

## 확인한 증거

- 독립 신규 서버 검사 **22/22**, 클라이언트 패치/실제 전투 검사 **10/10**, 실제 모달 SSR 검사 **3/3**. 과거 경기 결과를 검사 입력으로 참조하지 않는다. 실제 마운트된 새 API도 익명 요청을 AI 호출 전에 401로 거부한다.
- 기존 작성 **22/22**, 기본 정보/전부 사용 **9/9**, 설명 컴파일/런타임 검사 통과. 관련 서버 저장·보안·경기 마운트 회귀는 신규 검사 포함 **36/36**다. 제한 환경의 루프백 접속 거부 뒤 같은 검사를 제한 밖에서 재실행했다.
- 변경 ESLint 및 diff 검사 종료 0. 최종 62페이지 빌드 `4Y1r2iS8fOAw7bQL7fyQL` 종료 0. 첫 제한 환경 빌드는 생성 폴더의 EPERM으로 실패했으며 제한 밖의 최종 빌드와 구분한다.
- 현재 엔진 `bdb438309b4ecad7eb4d2b19edb86d2832911e0faaf9d309763ba265e2de2811`. 생성기 규칙에 따라 편집기 유틸 변경도 버전에 포함된다. 과거 기록의 엔진 버전을 덮어쓰지 않았다.
- 비용 없는 독립 응답과 **실제 React 모달/프로덕션 CSS**를 결합한 루프백 화면에서 생성→미리보기만 유지, 취소, 확인 후 적용, 실패, 작성 중 닫기와 늦은 응답 차단을 실제 클릭으로 확인했다. 작성된 이름은 유지되며 적용 전 HP 100/전부 비활성→적용 후 HP 110/다섯 스킬 활성이다. 서버 저장은 항상 0이다. 초안 완성 시 미리보기로 초점을 이동한다.
- 390px 화면에서 상세 수치를 펼쳤을 때 문서 너비 390px, 모달 client/scroll 너비 모두 351px로 가로 넘침이 없다. 화면 크기 설정을 복원하고 확인 탭/서버를 종료했다.
- 실제 Node 자료 읽기는 헤이즈·재키·에키온 세 명에서 Q/W/E/R/패시브와 능력치 항목을 확인했다. 이는 전체 실험체 또는 생성 정확도 증거가 아니다.
- 적용한 독립 `0.2%` 스킬은 실제 전투 경로에서 HP 5,000의 대상에게 정확히 10 피해를 입혔다. 형식/단위 검사이며 실제 모델 밸런스 합격은 아니다.

로컬 화면 증빙: [초안 미리보기](../artifacts/character-auto-setup-preview-20261005.jpg). 확인용 번들 1,674,966바이트는 RAM에서만 생성했고 경기 JSON/MD를 만들지 않았다.

이번 빌드의 webpack 캐시 12파일·630,112,687바이트(600.92MiB)만 경계/재분석 지점을 확인한 뒤 정리했다. 소스·완성 빌드·타인의 변경·사용자 JSON/MD 등 29개 보호 파일의 전후 SHA256은 일치하며 남은 캐시 파일은 0개다. `npm run build`로 재생성할 수 있고 실제 물리적 여유 공간 증가량은 측정하지 않았다.

## 남은 관문

실제 AI 응답의 ER/커스텀별 수치·효과·밸런스, 실제 계정의 서버 저장/재열기, 여러 실험체/사용자 설정, 실제 전체 경기와 사람의 평가는 미확인이다. 비용이 발생할 수 있는 AI 2건 검증은 사용자에게 별도로 요청했으며 현재 실행하지 않았다. 이번 변경은 푸시·공개 배포하지 않았다. 기존 미실행 공동 구매 진단과 다른 작업자의 서버 변경도 이번 범위에서 제외했다.

재검사: `server`에서 `node --test tests/character-setup.test.js tests/audit-defects.test.js tests/security-contracts.test.js`, `client`에서 `npm run check:skills` 및 `npm run build`. UI 확인은 빌드 후 `node scripts/check-character-auto-setup-ui.mjs --preview`이며 공개 AI/계정 저장을 호출하지 않는 로컬 독립 입력이다.
