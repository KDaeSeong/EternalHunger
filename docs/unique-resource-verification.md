# 실험체 고유 자원 의미 연결

## 2026-11-11 경기 시간 분할과 회복 누적

매 시간 조각마다 회복 결과를 0.001 단위로 반올림하여, 초당 0.1·시작 0·비용 3인 정상 설정도 같은 30초 뒤 정수 경계에서는 3, 공속 3의 0.333333초 예약과 공용 시계 경계에서는 2.97이 되던 결함을 재현했다. 후자는 실제 스킬 사용 가능 여부도 달랐다. 새로운 회복률이나 비용을 추가하지 않고, 표시 아래의 누적 잔여만 현재 정의·현재 표시값에 연결된 직렬 상태로 보존한다.

공개 현재량과 비용·획득의 0.001 정밀도, AI의 같은 현재량 비교, 시작 1회 지불·취소 시 비용 유지·성공 발동 후 획득은 유지한다. 실제 소유자의 잔여만 받아들이며 정의·현재값 불일치와 비유한/범위 밖 잔여는 버린다. 0 아래 숨은 부채와 상한 초과분 저축을 만들지 않는다. 정상화·프레임·JSON·재경기 입력 복원·기존 부활은 잔여를 이어가며, 실제 새 경기와 게스트 정의 재적용은 시작값으로 초기화한다. 잔여가 없는 대부분의 참가자는 추가 정의 정규화를 건너뛰며, 객체 단위 캐시나 외부 WeakMap에 실제 자원 상태를 숨기지 않는다.

집중 검사 22/22는 정상 공속의 실제 공용 시간축, 낮은 회복률의 실제 필드 시간 진행, 지급/소비·상한·무효 입력·정상 부활·새 경기 초기화·프레임과 입력 JSON 복원을 다룬다. 기존 상태 정규화 15조건·336비교와 변경 5파일 린트·변경 형식 검사도 종료 0이다. 실제 실패 `2.97 !== 3`와 후속 성공은 `.local/code-audit/unique-resource-partition-red.log`·`unique-resource-partition-green.log`에 보존한다. 최종 통합 검증은 새 `resource-clock-*` 결과로 분리하며, 아래 9월 기록이나 과거 경기 출력을 입력/기대값으로 읽지 않는다. 광범위 커스텀·원작 개별 자원·실제 전경 성능·사람 평가는 이 집중 검사로 완료하지 않는다.

엔진 `e8e8b934…`의 최종 관련 11명령·린트와 빌드 `OmPzbQdPWy7U23grLFeBC`는 실제 종료 0이며, 각 실행 전후 선언 소스 1,256개가 같다. 상태 처리의 실제 전체 경기 비교, 캐릭터 시전·게스트 저장/새 초기화·상태 스킬 경기/재경기, 부활·프레임·지도·공격 시간 및 장문 기록 재경기를 포함한다. 시전 통제 경기의 사건 15,307개와 장문 기록 입력의 포착 15,101개가 각각 동일 재경기와 일치했다. 후자는 기존 HP 2배 장문 기록용 1101 입력으로서 자연 편성 분포가 아니다. 원시 명령과 로그는 `.local/code-audit/resource-clock-checks-result.json`, `resource-clock-build-result.json` 및 인접 로그다. 배포 묶음의 첫 단계는 Node VM 검사이며 실제 브라우저 관전이나 전경 9회 인수가 아니다. `a1d557c8…`의 앞선 실제 화면 완주는 이 새 엔진의 화면 증거로 승계하지 않는다.

기준일: 2026-09-06. 사용자가 제공한 실험체 자료의 `고유 자원` 항목을 G2.3 전투 인과관계에 연결한 소스 계약이다. 이 문서는 이바의 바이탈 포스나 에키온의 VF 게이지 같은 특정 원작 실험체의 개별 규칙을 재현했다고 주장하지 않는다.

## 구현 규칙

- 고유 자원은 캐릭터별 선택 기능이다. 이름, 최대치, 경기 시작치, 초당 회복량을 명시적으로 작성한다.
- 최대치는 1~10000, 시작치는 0~최대치, 초당 회복은 0~100으로 제한한다. 런타임 값은 소수 셋째 자리까지 보존하고 최대치를 넘지 않는다.
- Q/W/E/R은 고정 `resourceCost`와 `resourceGain`을 가질 수 있다. 패시브에는 시전 사건이 없으므로 소비·획득을 허용하지 않는다.
- AI는 현재 자원으로 비용을 낼 수 없는 스킬을 후보에 넣지 않는다. 자원 획득만 있는 스킬은 실제 순증가가 있을 때 효용으로 보며, 이미 최대치라면 획득만을 이유로 반복 사용하지 않는다.
- 비용은 실제 시전 시작이 확정될 때 한 번 소비한다. 재발동은 별도 시전이므로 다시 소비한다. 시전 중 사망·행동 제한·지역/전장/대상 이탈로 취소되어도 반환하지 않는 것이 이 프로젝트의 명시적 규칙이다.
- 일반 스킬은 성공적으로 발동한 뒤 획득한다. 기본 공격 강화는 강화 준비 시점이 아니라 실제 기본 공격이 적중해 스킬이 해소될 때 획득하며, 실명·회피로 공격이 빗나가면 획득하지 않는다.
- 회복은 성장·상태·쿨다운과 같은 경기 경과 구간을 사용한다. 살아 있는 일반 필드 및 차원의 틈 참가자는 회복하지만, 사망자와 차원의 틈 전투 불능자는 회복하지 않는다. 차원의 틈 입장/복귀 자체는 자원을 초기화하거나 보너스로 채우지 않는다.
- 소비·획득은 `unique_resource` 사건에 이름, 변화량, 전후 값, 최대치와 스킬을 남긴다. 초당 회복은 사건 폭증을 막기 위해 매 틱 기록하지 않고 프레임의 현재 값으로 관측한다.

## 편집·저장·관전 계약

- 로그인 없는 경기 전 편집기와 계정 캐릭터 전술/스킬 편집기에서 자원 정의와 스킬별 소비·획득을 작성한다.
- 고유 자원을 끈 채 소비·획득을 설정하거나 범위를 벗어난 값을 보내면 저장하지 않는다. 서버 직접 요청도 같은 모순을 거절한다.
- 게스트 로컬 프로필은 정의만 저장하며 HP·현재 자원·쿨다운 같은 경기 상태를 섞지 않는다. 새 경기를 만들 때 시작치로 초기화한다.
- 계정 캐릭터는 정의와 스킬 소비·획득을 서버 스키마, 저장 압축, 저장 후 비교, 편집/시뮬레이션 조회에서 왕복한다.
- 생존자 카드에는 `이름 현재/최대`와 초당 회복 설명을 표시한다. 시작 프레임, 진행 프레임, 최종 프레임 및 재경기 입력은 전체 생존자 상태를 JSON 복제하므로 정의와 현재 값이 함께 보존된다.
- 두 경기 비교는 실험체별 고유 자원 정의 변경을 편성/전략 입력 차이로 표시한다. 현재 값 차이는 결과 프레임에 남지만 시작 조건 변경 횟수로 중복 집계하지 않는다.

## 작성한 검사 — 미실행

`client/scripts/check-unique-resource.mjs`에 다음 12개 검사를 작성했다.

1. 정의 범위와 런타임 시작치/현재치 보존
2. 비용 가능 여부, 부족 시 비변경, 1회 소비와 최대치 획득
3. 소수 경기 시간 회복과 최대치 제한
4. 부족 시 AI 후보 제외 및 충족 뒤 후보 복귀
5. 실제 시전 시작 1회 소비와 중복 시작의 이중 소비 방지
6. 취소된 시전의 비용 비환급 및 획득 없음
7. 성공 발동 뒤 획득과 준비된 시전의 이중 비용 방지
8. 일반 경기 시계 회복과 차원의 틈 전투 불능 회복 정지
9. 게스트 정의/스킬 로컬 저장과 자원 비활성 모순 거부
10. 계정 저장 압축·저장 비교의 정의/소비/획득 왕복
11. 경기 비교의 실험체별 고유 자원 변경 귀속
12. 서버 스키마/조회/저장 및 완주 사건 보존 필드 존재

사용자의 `검증 중단` 지시에 따라 위 검사는 실행하지 않았다. 린트·빌드·서버·브라우저·경기도 실행하지 않았으며, 작성한 코드나 과거 검사 결과를 이 수정의 통과 증거로 사용하지 않는다.

## 남은 완료 증거와 잔여 범위

- 두 편집기에서 정의/비용/획득 저장→새로고침→새 경기 시작치 복원 확인
- 비용 부족, 회복 경계, 취소, 재발동, 강화 적중/빗나감의 실제 사건·프레임 확인
- 같은 입력/시드의 재경기에서 자원 사건과 최종 현재 값 일치 확인
- 관전 카드의 긴 한국어/영어 자원명, 소수 값, 좁은 화면 표시 확인
- 특정 원작 실험체의 충전 조건, 변신, 과부하, 전용 UI는 해당 실험체 자료와 별도 설계 없이 이 범용 계약의 완료로 주장하지 않는다.

따라서 범용 고유 자원 정의·비용·획득·회복·저장·관전 경로는 소스에 연결했지만 실행 검증은 미완료다.
