# 개인 금지구역 타이머 수정 및 검증

2026-09-20. 사용자가 직접 확정한 규칙을 구현한다. 원작의 최신 규칙을 별도 조사하여 일치한다고 주장하는 문서는 아니다.

## 확정 규칙

| 상황 | 규칙 |
| --- | --- |
| 평소 | 각 실험체의 금지구역 타이머 최대 30초. 팀 공용 시간이 아니다. |
| 마지막 밤 진입 | 그 시점에 살아 있는 각 실험체의 남은 시간에 15초를 한 번 더한다. 30→45, 8→23. 45초로 일괄 초기화하지 않는다. |
| 마지막 밤 이후 | 회복·처치 보상으로 최대 45초까지 다시 채울 수 있다. 사용자가 별도 질문에 명시적으로 확정했다. |
| 처치 | 기존 +5초 회복은 유지하되 최대 시간을 늘리지는 않는다. 실제 받은 양만 로그에 표시한다. 상한이면 가짜 +5초 메시지를 내지 않는다. |
| 부활·새 경기 | 기존 부활 조건·시작 시간 20초는 변경하지 않는다. 부활은 보너스를 재지급하지 않으며, 새 경기에서는 이전 보너스 상태를 초기화한다. |

현재 시뮬레이터의 마지막 밤 진입은 기존 최종 구역 축소 개시 조건인 **6일차 밤**이다. 기본 시간표에서는 경기 1,180초이다. 2→1→0 안전구역 축소 시간표나 최종 승패 판정은 이번 변경으로 바꾸지 않는다.

## 구현

- `detonationTimerRuntime.js`에 상한·초기화·회복·일회 지급을 모았다. 이전 처치 보상으로 부풀려진 `detonationMaxSec`를 계속 사용하지 않는다.
- 마지막 밤 보너스는 일반 틱이 아니라 phase setup에서 첫 행동 전에 지급한다. 실험체 지급 표시와 경기 지급 기록을 함께 보존하여 같은 진입 반복, 정규화, JSON 복원으로 재지급하지 않는다.
- 지급은 남은 시간만 변경한다. 체력 회복·이동·장비·사망자 부활을 생성하지 않는다. 살아 있는 별도 전장 참가자도 개인 지급 대상이지만 별도 전장 안의 금지구역 차감/회복 제외는 유지한다.
- `detonation_bonus` 사건에 개인·전후 시간·증가량·상한·경기 시각을 저장한다. 전체 로그와 팀 관전 이력은 사건 당시의 값으로 설명하고, 생존자 타이머 설명은 평소/마지막 밤 이후의 상한을 구분한다.
- 기존 경기 보관함은 엔진 버전이 다르면 동일 재경기를 거부한다. 구버전 결과를 새 규칙의 재현·밸런스 증거로 재사용하지 않는다.

## 검증 상태

- 수정 전 실제 처치 처리에서 `35 !== 30` 실패를 확인했다. 수정 후 같은 검사 통과.
- 집중 검사 `check-detonation-rules.mjs` **21/21 통과**: 30/8/0/소수 시간, 개인별 지급, 사망자 제외, 30/45 회복·처치 상한, 0초 보상 설정, 잘못된 이전 상한, JSON 복원/중복, 부활/새 경기, 별도 전장, 관전 문구, 실제 6일차 밤→7일차 낮 phase setup 포함.
- 관련 검사: 종료 **13/13**, 부활 **6건**, 전투 시간 **26/26**, 시뮬레이션 ESLint 통과.
- 합류 수정(HF4)과 타이머를 합친 엔진은 `292b3ac05a82ae97300fc525c7631c0c8a5ab7da558d15038a008ef5c7e790bc`이다. 아래 자동 검증 뒤 실행 코드는 변경하지 않았다.

### 합친 버전 자동 검증

- 전체 `check:eternal-hunger`의 모든 단계는 **분할 실행으로 통과**했다. 첫 시도에서 기존 시전 검사가 불필요한 `_teamRegroup: null` 쓰기를 찾아 수정했고, 현재 엔진의 재실행은 저장 입력 재경기 16/16·종료 13/13·타이머 집중 21/21까지 통과했다. 그 뒤 새 완주 검사 파일의 ESM 등록보다 정적 import가 먼저 실행되는 로더 오류로 중단됐다. 검사 파일만 동적 import로 고친 뒤 타이머부터 남은 전체 단계를 이어 실행해 종료 코드 0을 확인했다. 단일 무중단 전체 명령의 종료 코드 0으로 기록하지 않는다.
- 현재 버전에서 팀 합류 22/22, 팀 전술 29/29, 시전 28/28, 판단 근거 21/21, 관전 17/17, 목표 29/29, 난수 격리 12/12 및 실제 3회 실행, 저장 입력 재경기 16/16을 포함한 전투·상태·지도·피드백·음원·런타임 검사가 통과했다. 프로덕션 빌드는 60/60, 종료 코드 0이다.
- `check:detonation:match` 실제 모델 경기 시드 2202: **6,537 프레임**(마지막 밤 전 6,053 / 이후 484)의 생존자 개인 상한과 잔여 범위를 검사했다. 생존자 7명이 6일차 밤 1,180초에 각자 30→45를 정확히 한 번 받았다. 7,255개 사건, 1,274.333333초에 교전으로 5팀 최후 생존 종료. 이 경기에서는 지급 당시 모두 30초였으므로 8→23은 위 집중 검사 증거와 구분한다.
- 사건 digest `020dfccaabdddafb5aea009f68c8453de7c378ea38cc83d7674036fc8858a16f`, 프레임 digest `815f1b62ca8f71fc8031b399e8a6104a7ff3f93cb2f1e05c894930a31e55cce8`. 입력은 통제 fixture이며 사용자가 평가한 편성·경기의 재현이 아니다.

### 실제 제품 확인

- 같은 빌드의 로그인 없는 로컬 평가 화면에서 기준 시드 1789192220412 경기를 진행했다. 6일차 밤 로그에 당시 생존자 5명의 개별 `30초 +15초 → 45초 (최대 45초)` 지급, 생존자 보드 `45/45s`와 `마지막 밤 이후 상한 45초`, 전투 상세에 `[다온] 처치 보상: 금지구역 타이머 +5초 (35/45초)`를 확인했다.
- 원본 경기는 x32로 시작해 마지막 밤 전후 x16으로 관전했으며 21:22.83, 3팀·다온 1/3명 생존·마지막 탈락 교전으로 정상 종료하고 보관 성공을 표시했다. 실제 `동일 조건으로 재경기`를 눌러 x16으로 진행한 결과 **사건 7,510개·최종 상태·종료 판정 전부 일치**를 표시했다.
- 페이지 새로고침 후 경기 보관함에 원본 21:22.83·24명·기준 시드 기록이 한 건 유지되고 동일 재경기 버튼이 활성화됐다. 이전 엔진의 보관 기록은 보존되지만 규칙 업데이트 안내와 함께 동일 재경기가 비활성화됐다. 관측 콘솔 경고/오류 0건. 공개 반영 확인은 아직 진행 중이다.
- 사람의 평가 점수는 입력하지 않았다. 이 확인은 타이머 규칙·표시·제품 동선의 증거이지 재미, 균형, 장시간 성능이나 최신 UI 가독성 합격을 뜻하지 않는다.

HF4의 합류/성장 고립 분석과 HF1–HF7 나머지 목표는 그대로 유지한다. 이전 합류 전용 전체 검사는 새 타이머 요구 수신 시 의도적으로 중단한 것으로, 통과나 결함 실패로 집계하지 않는다.
