# 확대 지도 맞춤·클릭 수정 검증

2026-09-24. HF1의 확대 지도 잘림과 실제 생존자 클릭 실패를 다룬다. 기본 관전 화면 배치, 원작 통행 구조 및 사람의 가독성 평가는 별도 잔여다.

## 원인과 변경

- 앞선 x1 전체 관전 뒤 정지한 매화 표식도 클릭으로 열리지 않았다. 중심 좌표의 DOM hit test는 같은 지역의 `도담 / 사망 / 고급 주택가` 원을 반환했다. 키보드 Enter로는 명단이 열렸으므로 이동 중 표식의 타이밍 문제로만 취급하지 않았다.
- 사망 표식을 같은 지역 생존자보다 먼저 그리며 `pointer-events="none"`으로 입력 대상에서 제외했다. 생존자·HP·사망 기록·위치는 바꾸지 않았다.
- 확대 창은 화면 높이에 맞춘 전체 지도로 시작한다. 별도 `전체 지도`/`2배 확대` 버튼과 중앙 기준 확대를 제공하며, 지도만 스크롤한다. 닫기·배율 버튼과 참가자 목록은 지도 이동에 휩쓸리지 않는다.
- 창을 닫았다 다시 열면 전체 보기로 시작한다. 기본 지도와 사용자 지도는 같은 표시 컴포넌트를 사용한다. 계산 엔진은 `a64d82ae9c869757f75e9a46a3f2638d07e6eb11a19b2656e8ade9fa265bdbdf`로 유지한다.
- 실제 클릭 뒤 브라우저 기본 outline이 SVG 배율만큼 커져 HP를 가리는 현상도 확인했다. 마우스 초점의 기본 outline을 없애고 기존 키보드 `:focus-visible` 강조를 유지했다.

## 자동 확인

- `check:lumia-minimap`: 기존 좌표·표식 배치 검사와 실제 컴포넌트 SSR 검사 7/7 통과. 사망 표식의 비상호작용·그리기 순서, 생존자 접근성·HP, 기본 맞춤/배율 버튼, 일반 지도 분리, 사용자 지도·빈 지도·원본 입력 보존을 확인한다.
- 변경 컴포넌트/검사 파일 ESLint 및 production build 61/61, 종료 코드 0.
- SSR은 실제 브라우저 클릭·스크롤·가독성 증거가 아니다. 위 테스트 이름과 단계를 전체 프로젝트 회귀 재실행으로 확대하지 않는다.

## 실제 화면 확인

로컬 production 3108의 최신 빌드, IAB 새 탭에서 확인했다. 앞선 탭은 정리되어 사라졌으나 같은 브라우저의 보관함 4건·평가 미시작·20:44:09 최신 원본 재경기 가능 상태가 보존되어 있었다.

- 1280×720: 전체 지도가 주유소부터 바지선까지 한 화면에 표시된다. 2배 확대는 빈 좌상단이 아니라 섬 중앙으로 시작한다.
- 확대 지도에서 호텔 팀 표식을 클릭해 7명의 팀/이름/HP 명단을 열었다. 아래쪽 바지선까지 스크롤해도 명단과 닫기/배율 버튼은 화면에 남는다.
- 1280×480: 전체 섬과 닫기/배율 버튼이 잘리지 않는다. 높이가 낮아 글씨가 작으므로 전체 맞춤이 모든 환경의 가독성 합격을 뜻하지 않는다.
- 390×844: 전체 보기, 2배 확대, 호텔 명단 실제 클릭을 확인했다. 명단은 화면 폭 안에 들어간다. 마지막에 임시 화면 크기를 기본값으로 복원했다.
- 지도 재열기에서 `전체 지도` pressed=true, `2배 확대` pressed=false를 확인했다.

## 동일 원본 완주와 사망 표식 중첩

- 같은 보관함의 20:44:09 원본, 시드 1789192220412·24명/8팀/21구역·스킬 켬을 x32로 재경기했다. **20:52·4팀 매화 1/3명 생존, 사건 7,297개·최종 상태·종료 판정 일치**를 제품 결과에서 확인했다.
- 종료 후 고급 주택가의 정지한 매화 표식을 확대 지도에서 실제 클릭했다. `고급 주택가 · 1명 / 4팀 / 매화 / HP 114/146` 명단이 열렸다. 같은 중심의 DOM hit test도 사망자가 아닌 해당 생존자 내부 `image`를 반환했다.
- 보관함은 원본 4건·평가 전부 미시작·이전 엔진 기록 재경기 차단을 보존했다. 콘솔 warning/error 0건이다.
- 측정 창 121,472.1ms(종료 후 체류 포함), Long Task 43건/최대 **153ms**, LoAF 46건/최대 **156ms**, RAF interval median 10/p95 10.1/max 150ms, 클릭→다음 RAF 2표본 최대 6.6ms다. 측정 중 지도 확대/명단 조작의 성능을 잰 것은 아니며 실제 painted FPS/INP가 아니다.
- heap 26,987,311→42,658,462B. 이 단일 x32 표본은 연속 경기의 자료 회수·누수 부재를 증명하지 않는다. 전체 단계 자료를 포함한 이전 x1 근거는 `observer-replay-optimized-x1-browser-20260924.json`에 별도로 남긴다.

원자료 `artifacts/minimap-interaction-browser-20260924.json`은 제품 패널 집계와 실제 hit test 발췌다. DOM 전사/디스크의 정렬 직렬화 **1,796자·FNV-1a 3,820,033,300**이 일치한다. 암호학적 검증 또는 전체 trace가 아니다. 이 측정은 마지막 마우스 outline CSS 수정 전이며 엔진은 동일하다.

## 최종 CSS 후속 확인

- 지도 집중 검사·실제 컴포넌트 7/7, 변경 ESLint, 61/61 빌드를 다시 통과했다.
- 새 빌드에서 호텔 표식의 마우스 클릭 뒤 과도한 흰 외곽선 없이 7명 명단이 표시됐다. 절의 청람 표식에 Enter를 입력해 `HP 106/106` 명단과 키보드 초점 강조를 실제 확인했다.
- 기존에 저장된 8구역 단방향/하이퍼루프 0 사용자 지도를 선택했다. 전체 맞춤/확대와 주유소의 혼잡 21명 명단 클릭·내부 스크롤 표시를 확인했다. 이후 내장 지도 선택과 새로고침 후 루미아 지도 복원을 확인했다. 사용자 지도 데이터를 삭제하거나 덮어쓰지 않았다.
- 일부 자동 조작에서 selector/CDP 응답 제한을 넘겼다. 동작 성공으로 간주하지 않고 현재 DOM과 새로고침 후 저장 상태로 다시 확인했다. 이 사실만으로 게임 결함 또는 브라우저 도구 결함의 원인을 확정하지 않는다.
- 최종 outline 수정까지 포함한 빌드에서 같은 20:44:09 원본을 x32로 다시 완주했다. **7,297사건·최종 상태·종료 판정 일치**, 종료 후 확대 지도 매화의 실제 클릭/명단 HP 114/146, 보관함 4건·평가 미시작·콘솔 warning/error 0을 다시 확인했다. 이 두 번째 경기는 성능 계측을 실행하지 않았으므로 앞선 측정 수치를 그대로 복제하지 않는다.

배포 결과는 후속 절에 기록한다. 기본 관전 화면의 지도 배치, 원작 통행 구조, 자연 희귀 목표, 다양한 합류/빈 슬롯, 실제 계정 저장, 메모리 회수 및 사람의 재평가는 미완료다. 현재 이 문서의 화면 근거만으로 HF1 전체 또는 전체 목표를 완료로 판정하지 않는다.
