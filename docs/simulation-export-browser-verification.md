## 실제 파일에서 발견한 검사 연결 누락

최초 출력 호출에서 headless 반환값의 `evidence` 위치를 잘못 읽어 예외가 발생했다.
호출을 바로잡은 뒤에도 전체 사건 비교는 **실패**했다: 브라우저 16,120개,
headless 16,096개, 첫 차이는 index 5,426의 1일 밤 190.666666초 무기 효과였다.
최종 상태·난수·종료 판정만 같다는 이유로 사건 재현을 합격 처리하지 않았다.

제품 `useSimulationEventActions`는 무기 스킬에 `emitEffectRunEvents`를 연결한다.
`run-random-isolation-match.mjs`는 bare runtime을 전달하여 그 연결이 없었다.
headless 공용 도구의 전투 연결만 제품과 맞췄다. 게임 규칙·피해·난수·엔진 버전은 변경하지 않았다.

`check-simulation-combat-actions.mjs`는 실제 제품 hook의 함수들을 작은 hook harness로 실행하고,
공격자 무기 버프·상대 CC·숙련 부족의 기록/상태/반환값을 검사 도구와 비교한다.
옛 연결의 음성 대조는 효과 누락으로 실패했고 수정 연결은 **3/3**이다.
이 harness는 실제 React 렌더러/브라우저 성능 증거가 아니다.
기존 내보내기 **6/6**과 변경한 두 검사 파일의 ESLint, diff 검사를 통과했다.
새 검사는 기존 내보내기 검사에 포함하며 과거 결과 파일을 읽지 않는다.

수정 후 방금 받은 실제 평가 JSON을 제품 실행기에 입력한 한 경기에서는:

- 사건 **16,120/16,120**, 첫 차이 없음, 무기 효과 24개 포함.
- 최종 상태·난수·종료 판정 일치, 1,220.583333초·1팀 종료.
- headless 프레임 6,344개. 프레임 digest는 수정 전후 headless에서 동일하다.

## 성능 판정과 잔여

동일 재경기 복원·자동 진행·지도 확대·경기 현황 전환까지 제품에서 확인했다.
하지만 IAB는 실제 브라우저가 숨겨진 상태에서도 DOM `visibilityState=visible`을 보고했고,
표시 요청 이후에도 숨겨진 상태로 돌아갔다. 측정 창 217.0036초의 RAF는 약 1.064회/초,
interval 최대 1,039.9ms, Long Task 최대 144ms였다. **중간 표본이며 정상 전체 관전의 성능 합격이 아니다.**
측정과 재경기를 중지하고 페이지를 떠났으며 재경기 완주를 성공으로 세지 않는다.
최신 정상 가시성 x1/반복 메모리·실계정 DB·사람의 가독성/재미·공개 배포는 남는다.

캐릭터 저장 `{ characters, deletedIds }`/전적 제외, `game.js`의 경기 정산,
서버 LP 50+100, 공개 `displayName` 계약도 소스를 다시 확인했다.
`server/index.js`와 `.env.example`의 별도 MyAnime 변경은 수정·커밋하지 않았다.

이번 검증이 만든 다운로드 JSON 두 파일은 위 해시·실제 경로를 확인한 뒤 정리하여
29,135,503B(27.8MiB)를 회수했다. 사용자가 첨부한 원본은 삭제 대상이 아니며,
브라우저 보관함의 원본과 빈 평가 초안은 유지해 다시 내보낼 수 있다.
전체 trace/JSON을 저장소에 중복 보관하지 않고 집계·해시·작은 화면 증거만 남겼다.
작업 전용 탭을 닫고 3042번 서버의 listener가 사라진 것도 확인했다.
실행 빌드/엔진 파일과 별도 서버 변경 두 파일의 SHA-256은 정리 전후 같았다.
